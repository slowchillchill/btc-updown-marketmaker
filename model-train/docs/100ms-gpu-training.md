# 100ms GPU 常驻训练：时间与状态合同

本文落实 [#181](https://github.com/slowchillchill/btc-updown-marketmaker/issues/181)
已批准方案中的时间、状态和设备边界，供生产实现与审查使用。公共语义参考为
`d255397c102d860cd21b49439b3d13a7b07339db`，包括 `account_economics_v2`、
`native_inputs_v7` 和 `native_actions_v2`。公共事实、平台规则、执行、NOE 与账户经济继续由
原模块负责，本文不重新定义这些合同。

本文成稿不表示生产调度器、GPU 公共后端或正式训练已经实现。正式窗口字段、数值表示和
训练参数仍有下文列明的剩余设计，#181 任务 1 尚不能据此整体完成。

## 1. 节拍与合法观察

100ms 是模型的观察和递推周期，不是行情降采样周期，也不是 GPU 计算耗时。调度网格按
UTC 毫秒对齐，观察时点为 `t_k = 100 × k`；在预登记根历史范围内使用该网格，不以进程
启动、读取分片或模型计算完成的时刻重新设定相位。市场的资格与 T-30 边界仍取自公共
市场身份。切换市场、自然日、行情块或训练批次不重启此网格。

每个节拍由公共宿主取得该时点实际合法可见的前缀及观察截止 `C_k`，冻结本次观察。
`C_k` 包含公共组、反馈和观察时间的真实关联，不能只用一个 UTC 时间戳代替。具体规则是：

- 公共源事实逐条经原规范化、因果组和公共归约链处理；一个已经签发的因果组整体应用，
  不在组内插入模型观察，不把相同毫秒的不同组重新合并。
- 严格更早的公共输入与必需逻辑推进先由原公共接口处理。观察所在毫秒仍保持开放；
  时间戳相同不表示该毫秒全部事件已经可见，也不表示同毫秒反馈应提前领取。
- 输入只包含取得 `C_k` 时实际可见的内容。来源时间较早但后来才合法应用的事实进入后续
  观察，不回改旧输入；原 `event_time`、`received_time`、来源身份及组序均保留。
- 相邻观察间的窗口材料由两个冻结前缀之差确定，每个完整因果组及合法应用事实只计一次。
  时间戳用于各自规定的年龄、持续时间和统计，不以来源时间重排已经发生的可见顺序。
- 没有新行情时仍产生合法的静默观察并推进时间、反馈读取及模型状态。没有原公共材料时，
  沿公共接口的无观察行结果处理，不伪造盘口、市场身份或来源更新。

首个窗口只使用根历史范围内已经合法取得的材料，不从范围外补历史。跨文件或传输块保留
尚未消费的窗口累积和冻结前缀；文件结束不是业务窗口结束。

CPU 参考入口为
[`FinitePublicConsumptionV1`](../../sim-system/src/run_v2.rs) 的 `next_group_at`、
`advance_before`、`observe_at`、`frames_at_observation`，以及
[`SharedExecution::freeze_action_before`](../../shared-run/src/group.rs)。调用冻结接口前，
宿主必须已沿公共链应用对应事实；它本身不替调用方推进 SIM 或账本。
当前冻结接口接收观察截止及 `frames`，账户经济使用同一批公共观察，不能沿旧签名遗漏
`native_inputs_v7` 所需的估值证据。

## 2. 冻结输入与有序积压

每个已接纳节拍保留当时的窗口、末状态、账户与执行快照、动作规则和身份。后续来源更新、
成交、预留和反馈可以继续推进活动环境，但不能改变这个输入。实现可共享不可变存储或
复用缓存；共享不允许修改旧观察所引用的值。

同一根的模型按观察序号执行。每个市场的 GRU 使用该市场上一条合法观察完成后的隐藏状态，
不能用零状态、其他市场状态或未来状态代替。前一模型计算未完成时，后续 100ms 观察仍按
原节拍冻结并排队。排队只推迟计算开始和完成，不跳过、覆盖、合并旧节拍，也不自动生成
`NoTrade`。同一根至多一个交易决定活跃市场，热身状态行不另行调用 Actor。

对有模型状态行的观察，设 `b_k` 为本次计算开始，`c_k` 为本次全部状态递推及必要决定的
计算完成，`s_k` 为 Execute 的实际发送时点。在同一调度时间域中，有：

```text
t_k <= b_k <= c_k
b_k >= c_previous              # 前一条有模型状态行的同根观察已计算完成
q_k = b_k - t_k                # 排队等待
s_k >= c_k                    # Execute 才有发送；不保证二者必然相等
arrival_k = s_k + outbound_k   # 沿原平台出站延迟合同
```

这些量与实际计算墙钟分别记录。离线经济模拟中的计算完成时间服从冻结的延迟合同，不能
用训练 GPU 本次运行快慢替换或叠加该延迟，也不能拿既有有限均值设定固定 50ms 偏移。
PAPER 的实际耗时使用所属同一单调时钟域；UTC 时间继续承担因果与审计职责。未来正式
经济比较所用延迟分布沿 #5 技术 §6.2、§12.3 成稿，不由本例设定。

例如，假定某段同根模型计算每次耗时均为 160ms，发送无额外等待：

| 观察时点 | 计算开始 | 计算完成 | Execute 发送 | 原观察截止 |
| --- | --- | --- | --- | --- |
| 0ms | 0ms | 160ms | 160ms | `C_0` |
| 100ms | 160ms | 320ms | 320ms | `C_1` |
| 200ms | 320ms | 480ms | 480ms | `C_2` |

100ms 时已经冻结第二个输入；160ms 的第一笔提交不能倒填进它。200ms 的输入则可以包含
截至该观察已经合法可见的本地提交、预留及反馈。公共事实在模型计算期间继续归约。
本例说明积压语义，不宣称实际模型耗时为 160ms，也不设定容量通过或拒绝阈值。

队列长度、等待、观察年龄及排空过程按真实结果报告。该语义不保证无限积压可以在有限
内存中运行；若实际实现遇到不能满足合同的资源或调度困难，按 #181 的用户指令保留现场、
停止受影响工作并报告，由用户裁决，不能自行用队列上限引入丢弃、拒绝或动作替换。

## 3. 动作完成、发送与经济反馈

Actor 在冻结输入和完整合法支持集上自主选择动作。模型计算完成后，Execute 沿
`send_decision_at(C_k, s_k)` 取得发送能力，保留原观察截止，并复用原整动作预留、Registry、
Intent Bridge、SIM 及回执链。发送前更晚的合法事实继续影响当前公共执行能力；不能据此
重新选动作、改价或缩量，也不能把发送回插到已经关闭的过去。

本地提交和预留沿原公共链及时可见。冻结观察后可用资金发生变化时，保留既有公共预留的
实际结果及原意图，不用 GPU 后端另加一套现金判断或将失败改成模型选择的 `NoTrade`。
`NoTrade` 在运行时确认最终选择时完成，没有发送、Bridge 请求或模拟到达记录。

CPU 参考已用独立观察与发送时点验证冻结输入、静默递推、忙时事实推进和迟到发送，见
[#180 时间能力](../validation/issue-180/time-capability.md)及
[短验证报告](../validation/issue-180/time-report.md)。这些材料是公共接口证据；其中有限
观察窗口、50/250ms 声明延迟和测试权重不是正式 100ms 调度器或训练配置。

## 4. 市场记忆与连续账户

隐藏状态身份沿 `(trajectory_id, account_id, condition_id)`。市场在 `[T-30s, T)` 热身，
只生成 `ContextOnly` 状态递推；开市承接该市场的缓存和隐藏状态，不重新初始化。
当前市场最后 30 秒交易与下一市场热身可以重叠，两者消费各自市场的窗口和倒计时，
同一观察共享动作前账户快照。下一市场热身不取得交易决定资格。

每个市场在一次观察中递推一次 GRU，状态行顺序沿原 `ContextOnly` 在前、
`DecisionRequired` 在后的约定。无行情的节拍也更新该市场的剩余时间
`market.end_at_utc_ms - observation_time_utc_ms`，来源值和来源时间保持真实；该时间进入
Actor 与训练 Critic 所消费的状态，不另造人工紧迫度分数。新布局的字段位置和变换在
正式输入设计中明确，不直接把旧 `fast[440]` 当作新版本固定索引。

初始化、市场资格、退役和旧订单读取继续沿
[`NativeInputRoot`](../native-inputs/src/root.rs) 的生命周期语义。模型队列中已接纳的旧
市场观察仍按序消费，其隐藏状态的释放也按该消费顺序执行；活动环境推进到下一市场
不能使尚未处理的旧观察失去自己的状态。市场记忆退役不删除旧市场的账户、未终态订单、
预留、结算或返佣事实。

账户属于连续根，跨市场、日、行情块和 rollout 承接同一经济状态，不因模型批次结束或
优化器更新而重新注资。市场结束、根历史范围截断和账户经济终止保持原区别。根间可并行，
经济状态和随机流保持各自身份，不以并行批次拼接账户。

恢复沿 [#5 技术 §14.1](https://github.com/slowchillchill/btc-updown-marketmaker/issues/5#issuecomment-5565141870)：
原根计划的自然合法边界上，完整 PPO 优化轮结束、对应 rollout 已消费且无活动训练根
需要恢复时，才形成完整恢复检查点。GPU 常驻不新增活动 SIM、NOE、Ledger、GRU 或半次
更新恢复；没有可用合法检查点时按原计划重算。不能为方便关机而提前截断或重置账户。

## 5. GPU 热循环与 CPU 边界

| 内容 | 运行位置与责任 |
| --- | --- |
| 文件读取、已批准的数据准备、分块传输、进程编排、日志及产物 I/O | CPU；历史可分块进入 GPU，不要求全部历史一次驻留显存 |
| 活动行情、窗口累积、盘口、模拟订单及延迟队列 | GPU；`data-pipeline`、`sim-system` 沿原职责交付对应后端 |
| NOE、账户、费用、返佣、预留和经济状态推进 | GPU；执行规范化、`ledger`、`shared-run` 维持唯一事实链 |
| 正式窗口输入、GRU、Actor、完整支持集与精确动作解码 | GPU；模型职责归 `model-train`，公共规则及执行职责仍归原模块 |
| Critic、训练奖励所需经济读取、轨迹、优势估计和 PPO 更新 | GPU；未交付部分由 #181 沿训练合同实现 |
| 离线 CPU 参考对照、训练后报告序列化、合法检查点和模型导出 I/O | CPU 可承担；不能作为每一步训练推进所必需的回调 |

跨行情块保持活动状态、积压观察、窗口和账户连续性。GPU 后端必须能独立推进本步公共
状态、支持集与动作；不能只把神经网络移到 CUDA，而仍逐条件调用 CPU Rust 解码或读取
`int(tensor)`、`.cpu().tolist()` 的结果后才能继续训练。控制面进度和输出可按既有可控频率
回传，不要求完全消除 CPU 编排。

精确经济和模型浮点计算分别设计。当前公共经济及支持集使用 `Decimal`、`BigInt`／
`BigUint` 和精确有理数；[`support.rs`](../native-inputs/src/support.rs) 的数量编码域超过 64 位，
[`buy_cost.rs`](../../sim-system/src/buy_cost.rs) 已有费用中间乘积超过 `u128` 的单元反例。GPU 表示不能默认
统一缩成 `int64` 或 `int128`，也不能因网络使用混合精度而近似资金、费用或合法支持集。
训练输入、奖励或动作所需的精确归约属于热路径，纯输出格式化可留 CPU；完整数值表示
及其覆盖仍须根据实际调用链设计、对照和测量，本文不预先宣称已经解决。

## 6. 输入复用与剩余设计

`native_inputs_v7` 提供已交付的精确经济、账户与执行状态、市场身份、来源缺失表达、
盘口编码和动作前读取参考。其经济含义及 `native_actions_v2` 的完整合法域继续适用。
现有 `NativeInputRoot::observe_sources` 可独立更新来源历史，`encode` 消费同截止冻结
材料；这些职责分离可复用，不能因此继续逐公共事件构造完整模型输入和运行 GRU。

正式 100ms 输入必须另行明确窗口统计、末状态及必要路径信息，不能把最后一个公共组
当作整窗汇总，也不能把原逐帧 596／433 维布局或来源 history16 自动宣布为最终新布局。
新模式须绑定准确版本；旧权重、旧轨迹和旧检查点不重标为 100ms 成果。

后续在对应实现前补齐：

- 窗口字段、单位、数值变换、来源年龄、缺失与静默表达；首窗及跨块累积如何进入张量，
  原来源历史与新增窗口历史各自的用途。
- GPU 精确数值表示、全部合法中间值及与公共参考的对照；实现所需工作集与存储安排。
- 正式模拟延迟配置、100ms 奖励归属、Critic 目标、折扣、优势参数、序列、TBPTT、
  跨更新隐藏数值衔接，以及原根计划与合法恢复边界的对齐。
- 本方案的候选、种子、投入和正式数据验收；继续按 #181 管理，不默认复制 #5 的
  27 配置竞赛或全部逐帧辅助损失。

时间实现的定向验证覆盖完整组窗口归属、未来信息隔离、静默倒计时、160ms 有序积压、
冻结后本地承诺可见性、T-30 重叠与市场退役、跨块账户连续性。设备验证另外核对实际
传输和同步；时间语义成立、GPU 常驻成立、真实容量和模型学习分别形成证据。
