## 1. 节拍与合法观察

100ms 是模型的观察和递推周期，不是行情降采样周期，也不是 GPU 计算耗时。调度网格按
UTC 毫秒对齐，观察时点为 `t_k = 100 × k`；在预登记根历史范围内使用该网格，不以进程
启动、读取分片或模型计算完成的时刻重新设定相位。市场的资格与 T-30 边界仍取自公共
市场身份。切换市场、自然日、行情块或训练批次不重启此网格。

每个节拍由公共宿主取得该时点实际合法可见的前缀及观察截止 `C_k`，冻结本次观察。
`C_k` 包含公共组、反馈和观察时间的真实关联，不能只用一个 UTC 时间戳代替。具体规则是：

- 公共源事实逐条经原规范化、因果组和公共归约链处理；一个已经签发的因果组整体应用，
  不在组内插入模型观察，不把相同毫秒的不同组重新合并。
- 严格更早的公共输入与必需逻辑推进先由原公共接口处理。观察所在毫秒仍保持开放；
  时间戳相同不表示该毫秒全部事件已经可见，也不表示同毫秒反馈应提前领取。
- 输入只包含取得 `C_k` 时实际可见的内容。来源时间较早但后来才合法应用的事实进入后续
  观察，不回改旧输入；原 `event_time`、`received_time`、来源身份及组序均保留。
- 相邻观察间的窗口材料由两个冻结前缀之差确定，每个完整因果组及合法应用事实只计一次。
  时间戳用于各自规定的年龄、持续时间和统计，不以来源时间重排已经发生的可见顺序。
- 没有新行情时仍产生合法的静默观察并推进时间、反馈读取及模型状态。没有原公共材料时，
  沿公共接口的无观察行结果处理，不伪造盘口、市场身份或来源更新。

首个窗口只使用根历史范围内已经合法取得的材料，不从范围外补历史。跨文件或传输块保留
尚未消费的窗口累积和冻结前缀；文件结束不是业务窗口结束。

已有公共语义的源码入口为
[`FinitePublicConsumptionV1`](../../sim-system/src/run_v2.rs) 的 `next_group_at`、
`advance_before`、`observe_at`、`frames_at_observation`，以及
[`SharedExecution::freeze_action_before`](../../shared-run/src/group.rs)。调用冻结接口前，
宿主必须已沿公共链应用对应事实；它本身不替调用方推进 SIM 或账本。
当前冻结接口接收观察截止及 `frames`，账户经济使用同一批公共观察，不能沿旧签名遗漏
`native_inputs_v7` 所需的估值证据。

## 2. 冻结输入与有序积压

每个已接纳节拍保留当时的窗口、末状态、账户与执行快照、动作规则和身份。后续来源更新、
成交、预留和反馈可以继续推进活动环境，但不能改变这个输入。实现可共享不可变存储或
复用缓存；共享不允许修改旧观察所引用的值。

同一根的模型按观察序号执行。每个市场的 GRU 使用该市场上一条合法观察完成后的隐藏状态，
不能用零状态、其他市场状态或未来状态代替。前一模型计算未完成时，后续 100ms 观察仍按
原节拍冻结并排队。排队只推迟计算开始和完成，不跳过、覆盖、合并旧节拍，也不自动生成
`NoTrade`。同一根至多一个交易决定活跃市场，热身状态行不另行调用 Actor。

对有模型状态行的观察，设 `b_k` 为本次计算开始，`c_k` 为本次全部状态递推及必要决定的
计算完成，`s_k` 为 Execute 的实际发送时点。在同一调度时间域中，有：

```text
t_k <= b_k <= c_k
b_k >= c_previous              # 前一条有模型状态行的同根观察已计算完成
q_k = b_k - t_k                # 排队等待
s_k >= c_k                    # Execute 才有发送；不保证二者必然相等
arrival_k = s_k + outbound_k   # 沿原平台出站延迟合同
```

这些量与实际计算墙钟分别记录。离线经济模拟中的计算完成时间服从冻结的延迟合同，不能
用训练 GPU 本次运行快慢替换或叠加该延迟，也不能拿既有有限均值设定固定 50ms 偏移。
PAPER 的实际耗时使用所属同一单调时钟域；UTC 时间继续承担因果与审计职责。未来正式
经济比较所用延迟分布沿 #5 技术 §6.2、§12.3 成稿，不由本例设定。

例如，假定某段同根模型计算每次耗时均为 160ms，发送无额外等待：

| 观察时点 | 计算开始 | 计算完成 | Execute 发送 | 原观察截止 |
| --- | --- | --- | --- | --- |
| 0ms | 0ms | 160ms | 160ms | `C_0` |
| 100ms | 160ms | 320ms | 320ms | `C_1` |
| 200ms | 320ms | 480ms | 480ms | `C_2` |

100ms 时已经冻结第二个输入；160ms 的第一笔提交不能倒填进它。200ms 的输入则可以包含
截至该观察已经合法可见的本地提交、预留及反馈。公共事实在模型计算期间继续归约。
本例说明积压语义，不宣称实际模型耗时为 160ms，也不设定容量通过或拒绝阈值。

队列长度、等待、观察年龄及排空过程按真实结果报告。该语义不保证无限积压可以在有限
内存中运行；若实际实现遇到不能满足合同的资源或调度困难，按 #181 的用户指令保留现场、
停止受影响工作并报告，由用户裁决，不能自行用队列上限引入丢弃、拒绝或动作替换。

## 3. 动作完成、发送与经济反馈

Actor 在冻结输入和完整合法支持集上自主选择动作。模型计算完成后，Execute 沿
`send_decision_at(C_k, s_k)` 取得发送能力，保留原观察截止，并复用原整动作预留、Registry、
Intent Bridge、SIM 及回执链。发送前更晚的合法事实继续影响当前公共执行能力；不能据此
重新选动作、改价或缩量，也不能把发送回插到已经关闭的过去。

本地提交和预留沿原公共链及时可见。冻结观察后可用资金发生变化时，保留既有公共预留的
实际结果及原意图，不用 GPU 后端另加一套现金判断或将失败改成模型选择的 `NoTrade`。
`NoTrade` 在运行时确认最终选择时完成，没有发送、Bridge 请求或模拟到达记录。

已有 CPU 实现曾用独立观察与发送时点验证冻结输入、静默递推、忙时事实推进和迟到发送，见
[#180 时间能力](../validation/issue-180/time-capability.md)及
[短验证报告](../validation/issue-180/time-report.md)。这些材料是公共接口证据；其中有限
观察窗口、50/250ms 声明延迟和测试权重不是正式 100ms 调度器或训练配置。

## 4. 市场记忆与连续账户

隐藏状态身份沿 `(trajectory_id, account_id, condition_id)`。市场在 `[T-30s, T)` 热身，
只生成 `ContextOnly` 状态递推；开市承接该市场的缓存和隐藏状态，不重新初始化。
当前市场最后 30 秒交易与下一市场热身可以重叠，两者消费各自市场的窗口和倒计时，
同一观察共享动作前账户快照。下一市场热身不取得交易决定资格。

每个市场在一次观察中递推一次 GRU，状态行顺序沿原 `ContextOnly` 在前、
`DecisionRequired` 在后的约定。无行情的节拍也更新该市场的剩余时间
`market.end_at_utc_ms - observation_time_utc_ms`，来源值和来源时间保持真实；该时间进入
Actor 与训练 Critic 所消费的状态，不另造人工紧迫度分数。新布局的字段位置和变换在
输入设计第8节通过逐项映射明确新倒计时为fast440，不据旧索引自行假定新布局。

初始化、市场资格、退役和旧订单读取继续沿
[`NativeInputRoot`](../native-inputs/src/root.rs) 的生命周期语义。模型队列中已接纳的旧
市场观察仍按序消费，其隐藏状态的释放也按该消费顺序执行；活动环境推进到下一市场
不能使尚未处理的旧观察失去自己的状态。市场记忆退役不删除旧市场的账户、未终态订单、
预留、结算或返佣事实。

账户属于连续根，跨市场、日、行情块和 rollout 承接同一经济状态，不因模型批次结束或
优化器更新而重新注资。市场结束、根历史范围截断和账户经济终止保持原区别。根间可并行，
经济状态和随机流保持各自身份，不以并行批次拼接账户。

#181 的活动根恢复按第9节新增协调检查点；#5 §14.1 的无活动根限制仍仅适用于原逐帧方案。
不能把权重保存加载当作恢复活动账户。新能力交付前，停机或换卡仍可能需要从原合法边界重算。

## 5. 紧凑块接口与CPU/GPU准备

### 5.1 材料归属和格式

跨模块类型和精确数值归 `contracts`；紧凑构建器、块读取器及DPT归约归
`data-pipeline/training`，公共观察GPU归 `data-pipeline/core`。100ms窗口、来源history16、路径和端点归 `model-train/native-inputs`
GPU输入后端，复用DPT公共事实；模型记忆不搬入DPT。
设计格式为 `compact_exogenous_v1`：不可变、分列、变长载荷用偏移引用，不按事件落盘全盘口。
数据成员使用二进制小端列，头部JSON只描述模式/成员/初始化引用/版本；不保存第二份任务状态。
块以完整公共组边界切分。单个超大组允许独立块，不能截组以适配默认容量。

| 列/表 | 物理类型与shape | 精确语义 |
| --- | --- | --- |
| 身份表 | `uint8[bytes]`、`uint64[n+1]`偏移 | 源文件/manifest摘要、source、condition、token、稳定逻辑身份原字节；索引仅作为句柄 |
| 来源坐标 | source/epoch字典句柄、原admission坐标各整数列及presence | 逐字段保存 `CollectorAdmissionCoordinateV1`，不由时间戳重造身份 |
| 公共组 | 原组身份句柄、`uint64[G+1]`事实偏移、原前缀/截止字段列 | `PublicFactPositionV1`及组内原ordinal；组不按相同毫秒合并 |
| 公共事实 | `uint16[F]`类型、原位置/市场/资产句柄、`uint64[F+1]`载荷偏移 | 保留原事件变体、质量、direct_sources和dependency关系，未知值与已知空区别 |
| 真实时间 | `int64[F]` event/received、各自`bool[F]`存在位 | 保留缺失与原符号；差值在128位或更宽整数域计算 |
| 精确值 | 原token字节表；符号`uint8[V]`、scale`uint8[V]`、coefficient `uint32[V,3]` | 已由原Decimal接纳的96位系数与0—28 scale；原字符串不经浮点；有理值另用多字表 |
| 盘口载荷 | `uint64[F+1]`档位偏移；价格/数量值句柄、侧、原顺序、直接锚点句柄 | full-book为真实替换，absolute-change含零删除；不误当增量相加；缺失/质量边界保留 |
| 可见关联 | 原可见前缀、公共位置与源坐标的关联列 | 读取器按公共合同签发合法前缀，不按event_time预测可见性 |
| hidden侧表 | 独立成员及索引、公共依赖位置、真实source time、bucket边界 | 沿 `HiddenDerivedStepRefV1`/`ClosedHiddenStepBucketV1`；无真实源时刻不伪造索引 |

actor观察投影不接收hidden侧表句柄。只有SIM后端能读该成员并按原hidden推进规则应用。
收益读取已实际公开给账户的经济事实，不让Critic或标签借此读取未来。public归约和hidden
事件时间索引是两条不同的顺序，不能用一次全局时间排序替代。

头部绑定实际源文件/成员摘要、范围、初始化位置、DPT因果/观察/归约语义版本、规则快照、
压缩和紧凑格式版本。沿既有DPT实际来源和成员合同记录，不要求复制旧Gate-A全部报告，
也不以旧prepare目录布局作为紧凑构建前置。现有合格录制或规范化材料可直接编译；新原始
材料沿同一公共解码/归约语义构建。生产入口需保留TWAP实际支持范围，不能由新格式宣称
旧Gate-A已支持其尚未支持的来源。

块头引用相同数据范围的合法初始化及前块，连续读取从上块GPU状态承接。断点只读恢复加载合法
初始快照和截至位置的必需增量，或加载本设计活动状态；不能把任意块首当作市场初始状态。
共享只读块没有账户事实。同版本的多个获准根复用同一物理载荷；账户状态各自独立。

### 5.2 一条协作准备路径

优先复用锁定CUDA12.8工具链、已有Rust/Parquet/serde与CUDA内置CUB；本设计不引入cuDF、
另一套通用准备插件。TorchRL仅用于第7节训练组件，不用于材料准备。自定义CUDA列内核与PyTorch设备扩展只用于实际公共路径。
CUB的排序/scan用途须在目标环境编译确认，不由文档宣称已可用。

| 步骤 | 设备与方法 | 保留CPU的具体原因/顺序责任 |
| --- | --- | --- |
| 列出实际manifest成员、读压缩Parquet页/嵌套JSON、结构变体及source关联 | CPU多核分文件解码、批次保留数字原token；复用现有结构/身份校验 | 现有锁中无支持全部嵌套变体的GPU文件解码器；数据盘I/O及现有错误行为在此完成，不为换设备复制SDK |
| 数字token批量转换、列packing、offset/存在位生成 | GPU按原十进制词法做整数逐位/分段转换，CUB scan生成偏移；已是Decimal的合格材料直接传系数 | 不先parse为浮点；原解析不支持GPU批量的罕见变体走同一Rust解析后传精确系数，属于准备批次兼容处理 |
| 公共归约所需排序 | GPU对原来源/epoch/admission及已有总序比较键做稳定排序；字典rank由原比较器形成 | 不以event_time排序公开流；相同键保留原ordinal；排序后的业务接纳仍由所属DPT决定 |
| hidden索引、独立列统计/质量计数、批内可独立盘口侧工作 | GPU独立稳定排序、分段scan/reduce；保留精确计数和多字金额 | hidden按实际source-time与原稳定tie顺序，缺时间沿原规则；不把独立统计说成全部业务归约并行 |
| 初始化、跨组有依赖DPT状态 | 复用公共归约；CPU有序处理元数据/不兼容结构，GPU公共后端处理兼容盘口和数值列 | source epoch、初始快照、缺口及跨组依赖不能任意并行；CPU输出的是共享外生准备结果，不是训练每条件回调 |
| 写块/成员并发布，CPU预读和GPU上传 | CPU流水线写压缩列、同步发布，page-locked双缓冲；H2D stream与compute stream用事件关联 | 文件I/O留CPU；同一卡准备与训练按实际容量分阶段，避免排序scratch挤占优化器 |

GPU数值词法转换必须复用原接纳域和错误分类；尚未兼容的输入可在准备批次用原CPU解析器，
但不得改变事实或掩盖错误。已合格材料无需二次全链prepare。工作量、CPU结构解析成本、
GPU转换/排序/归约、传输及写盘分别计时，选择保留CPU步骤以端到端结果修订。

当新材料超出GPU排序工作集时，将排序run落数据盘，复用一条CPU外排合并路径；这时才使用
main吸收的 #249/#251。`SortConfig.merge_workers`必须显式配置，启动值取
`min(可用CPU工作核, 独立合并组数, floor(合并可用内存/单组缓冲), floor(共享可用FD/单组FD))`，
非空工作至少1。当前25核配额先留2核给I/O/控制，其余23作为可调上限；共享FD与单组成本
运行前实测，不照搬1，也不把23直接当已测吞吐最优值。合格旧材料不为改worker重做。

## 6. 公共GPU状态与精确数值

### 6.1 状态责任和设备边界

各模块提供自身CUDA后端及同合同的设备状态视图，公共ABI归 `contracts`。
Rust负责初始化、文件与控制面；CUDA算子读取设备句柄，PyTorch通过设备张量/stream接线。
运行装配归 `shared-run`/`backtest`，PPO及模型归 `model-train`。不在Python复制公共经济归约。

实际公共反例定位必要修复，保留原错误，不恢复旧exact-003全窗CPU诊断。

### 6.2 数值ABI与范围

采用32位字（limb，存一个整数的32个二进制位）的设备多字表示。`ExactDecimal`只对原
Decimal已接纳值使用96位系数、符号、0—28 scale；`EconomicRational`本身没有固定分子
上限，不能把所有状态都压进96/128/512位。

| 值种类 | 设备表示和运算 |
| --- | --- |
| 原Decimal/时间 | `uint32[3]`系数+符号/scale；时间原int64，差先用带符号128位；保留原token |
| 任意精确整数 | `DeviceIntRef=(arena_offset:u64, limb_len:u64, sign:u8)`，小端`uint32[]`；零规范为空长度 |
| 普通精确比率/窗口均值 | 分子/正分母两句柄；约分gcd、精确加减乘除、比较/div-rem均在CUDA；持久状态用规范值，临时空间复用 |
| 真实现金/份额/预留/费用 | 沿公共字段原量纲与原平台舍入；micro-share、micro-pUSD或1e-5费用整数不互换；返回Decimal的边界沿原可表示性/溢出结果 |
| D-0295派生成本/贡献 | 单位分别为pUSD/shares，量子10^-12；结果用十进制系数与实际scale的多字表示，细源scale不截断；一部分最近偶数，另一部分原总额扣除；配对形成后固定；原非有限十进制比率走通用精确表示，不强制转有限系数 |
| 模型比率及末端 | 普通`round_f32`用精确商/余数判最近偶数；原值先求差。log/sqrt用归一化指数+尾数转FP64，标准CUDA运算后转FP32；不先使分子/分母各溢出，不开全局fast-math |

通用多字核采用按值长度分组的warp协作加减/比较、全宽乘积、长除法和gcd。每次输出长度
由输入长度推导：加法最多max+1，乘法最多长度之和，移位增加ceil(bits/32)，临时除法
保存余数。arena先按实际块/状态分配，长度不能以容量静默截断。需要增长时在算子提交
状态前给出所需空间，控制面扩页后续调同一未提交算子；业务数据留GPU，不用CPU计算替代。
分配失败保留原状态并报告工程资源缺口，不新增金额拒绝、量域裁剪或自动NoTrade。

GPU先用上述完整实现保证合法域，再针对已证明的字段范围做固定多字快路径；256/512位
诊断只能复用经核实的carry、div-rem、舍入原理，不能作为生产全域容量证书。本设计不重新
开发取消的递归成本分母动态大整数；多字用于真实事实、单次有理中间值和有限分摊余量。

费用保留 `buy_cost.rs`/`matching.rs` 的严格半个1e-5单位比较和原向上半舍入。大exponent先
用已有 `q*r/4^e` 上界及位长比较：严格小于才归零，等号继续精确算。其余幂用平方求幂并
全宽乘积、原约分，不能把 `u32::MAX` exponent直接物化为固定宽分母，也不限定费率。
SIM金额买入保留最小正Decimal价格10^-28导出的份额上界，而非默认u128足够。
数量保留 `((1<<96)-1)/10000` 完整原编码上界、16路分段、原FOK/GTC最低本金及配对
联合资金支持；现有跨u128反例必须在真实GPU函数检验。原MOS仍是平台执行条件而非新增
模型数量屏蔽。普通GTC显式post_only=false，价格坐标保持两档tick全域。

## 7. 连续采集、PPO及隐藏状态衔接

### 7.1 每学习器的同步批次

一个学习器拥有自己的Actor/Critic/优化器、策略版本v和获准根。独立候选不是同一策略的
额外环境；共享只读输入不共享经济状态、hidden、轨迹或随机流。没有批准的根不创建。
同根正式训练覆盖完整15天、开发完整3天；块/日/PPO批次只截学习图，不截账户历史。

采集一个rollout期间锁定行为参数 `theta_v`。每条真实状态行推进一次全部层GRU，ContextOnly
只作记忆递推，DecisionRequired才采样。轨迹保存冻结输入引用、h输入/输出、动作路径/
支持上下文、old_log_prob、价值、奖励、观察/完成/发送时刻、根/市场/策略版本和随机流位置。
熵辅助样本与业务动作的随机发生器分开，唯一合法项不耗随机。

设备阶段循环按族→数量16路循环→每腿类型→每腿价格或撤单对象推进；完成行退出活动mask。
数量坐标用完整精确区间，不能转int64；每次分段有合法续项才进支持。全对象两遍评分保留
稳定顺序和完整人口；训练全局归一化，不能逐块采样。两腿确定前不推进环境、不提交任何腿。
原微型样板与Python `consume_actor`只保留历史用途，新生产链不用它的逐条件CPU回调。

### 7.2 更新屏障与开放转移

冻结观察只固定业务材料，不立即绑定行为策略。该观察首次开始正式模型计算时，才绑定
本学习器当前版本v；此后不可改标。采集达到本批已开始的决定数/声明时长后，停止启动
新的模型任务，但继续按原调度推进所有已经绑定v的模型完成事件。跨过的每个100ms
观察仍冻结并排队，尚未开始的队列项保持未绑定，不能因更新门漏网格或自动NoTrade。

最后已开始任务的声明完成事件应用后，学习器停在这个准确公共frontier。待发送时刻比
该frontier更晚的动作保留，不为排空而推进到任意未来；已到时的发送/反馈沿原顺序处理。
下一学习片段从最早未开始的合法冻结观察起，不使用该frontier最新可变账户替换旧快照。
这个起点作为本批最后转移的bootstrap材料；仅用保存h的副本作v的值预测，不提交下一
GRU、Actor或随机消费，临时h不写回活动记忆。更新后该起点首次正式递推仍恰好一次。

下例仅说明算法，声明每次完成需160ms且发送立即，不设置正式延迟profile：

| 动作 | 公共/模型结果 |
| --- | --- |
| t=0冻结C0并开始模型，绑定v；本批目标为一决定 | b0=0、c0=160，关闭新的模型启动，业务时钟继续 |
| t=100到达原网格 | 冻结C100，尚未启动模型，因此未绑定策略；没有第一笔提交的未来事实 |
| t=160完成C0并发送原动作 | h0提交一次，原本地预留/发送合法可见；停公共frontier=160，C100保持原值 |
| 闭合旧批并PPO更新 | 奖励区间0—100来自当时实际经济前缀；用C100+h0副本作值预测，不提交该副本h |
| 更新后继续C100 | 首次开始并绑定v+1，b100=160、c100=320；真正递推一次，携带h0 |
| 继续推进到t=200、300及c100=320 | 每个网格仍冻结；旧动作反馈按实际时间出现，不倒填C100；下一批按原序启动排队项 |

这允许队列快照早于其首次计算，符合第2节忙时语义。优化墙钟不增加模拟执行延迟；
更新前后逻辑时钟、观察网格和队列不重置。若同批有多个已绑定v任务，按顺序完成它们，
所有已绑定v观察消费完再更新；其他尚未开始项在下一批首次计算绑定新版本。
根范围结束无下一合法起点时沿原截断/终止合同取末端价值，不读取范围外材料。

开放转移保存已采样动作、起始价值、奖励累计器、起始/末端时间、done/truncation和待取
bootstrap的位置。进入更新前用已保存的相邻合法观察经济前缀闭合区间，以v的Critic
自举；rollout截断不等于经济终止，bootstrap不能填零。仍在出站/平台/反馈队列中的旧
动作保留原发送时间、引用与v，属于下一状态内的真实在途业务，不重新选取或重复提交。
其后经济后果沿所属后续奖励时间区间记录，不回填旧观察或重复计奖。

本学习器全部参与根的本批转移闭合后才更新，全部PPO轮完成后标消费一次。更新期间
不以旧策略继续启动采集，不混入滞后策略轨迹。其他学习器有独立屏障，其未消费轨迹/
开放转移/已绑定观察及版本可一起保存，不能跨参数版本重复学习。这里只暂停历史墙钟
供料，不赋予PAPER暂停业务时间的能力。

### 7.3 重算与hidden数值

选择**携带hidden数值**的方法。跨更新保留采集结束的全部层h作为下一策略的初始记忆值，
同时保存产生它的策略版本与位置；不清零，不用新权重重放整个过去，不声称h已经由新
权重生成。下一条模型状态用 `theta_(v+1)` 和该保存h推进，生产状态图采用相同携带规则。

学习序列用TBPTT切片：每片的起始h取采集保存值并detach；可配置前缀burn-in从这个保存h
在当前训练参数下以 `torch.no_grad()` 重算，到学习段起点将全部层h detach；
学习段的ContextOnly与DecisionRequired都保留递推梯度，仅真实决定计算损失。
这一过程只重建学习计算图，不写回活动采集h。每个minibatch/PPO参数变化
后重新计算该前缀，不能缓存上轮z/h冒充当前重算。评分部分在当前参数下递推，按保存的
同截止精确上下文和原路径计算new_log_prob，old_log_prob来自theta_v当时实际采样。
起始h是条件状态的一部分，不要求学习重算把整个根历史恢复成当前参数的hidden。

保存h使不同TBPTT切片无需从根首回放，也使跨版本数值衔接完全明确。这是截断梯度的
方法，不证明模型已学会跨日记忆；长期记忆仍以真实时长和业务行为验收。首个合法市场h
初始化/热身/退役按第4节，burn-in不得读取根前史或未来标签。

### 7.4 训练量及参数边界

奖励由同一公共经济读取和已批准Reward合同产生，最终奖励是无量纲训练分数。WCM、
原始做市收益及真实账户金额继续用pUSD；WCM不等于实际账户净利润，含惩罚的训练分数
不是实际收益率。训练器保留原始账户净收益和方向中性做市收益两套报告；不把单市场
1000pUSD验收变成动作限额，也不新增临近结束惩罚。共同评价沿[#5技术§11.5](https://github.com/slowchillchill/btc-updown-marketmaker/issues/5#issuecomment-5565139746)：
最差5%账户根条件平均做市回报保留报告，不设该项数值下限或独立性能否决；报告完整性
及计算正确性仍须满足。未配对持仓资本时间占比不设独立验收上限或性能否决，保留报告
和原适用排名；准确口径、完整性及计算正确性仍须落实。自主决策后的真实成交配平学习、
正孤腿时间惩罚及其他全部要求保持。
按[本次用户决定](https://github.com/slowchillchill/btc-updown-marketmaker/issues/181#issuecomment-6073369497)，
100ms首轮采用与Actor共享编码器/GRU的传播预测辅助任务：以一个预测时距预测Up、Down
两腿各自的中间价变化。适用边界沿[#5技术§8.3.1](https://github.com/slowchillchill/btc-updown-marketmaker/issues/5#issuecomment-5565139746)，
适配100ms真实决定位置及因果可见前缀。未来标签不进入当时输入、交易奖励或动作支持；
辅助头不作为Actor输入，生产导出移除辅助头。采用该任务已确定；首轮孤腿时间成本
系数已按[用户选择A](https://github.com/slowchillchill/btc-updown-marketmaker/issues/181#issuecomment-6074806152)确定，见下文。
预测时距、辅助权重、其余学习参数及正式训练投入仍待逐项明确；不自动继承#5其他损失
或参数，不自动增加搜索或对照训练。公共后端和无学习的工程接线不等待这些参数选择。

GAE用实际相邻奖励区间时长 `dt`，以声明的时间基准定义
`gamma(dt)=exp(-dt/tau_gamma)`、`lambda(dt)=exp(-dt/tau_lambda)`；若选离散参数，
必须显式记录基准100ms及 `gamma_100^(dt/100ms)` 等等价形式。真正经济终止置零自举，
市场关闭和rollout截断不置零；未判定经济读取保留原未知状态，不将其填零后训练。
rollout步数/秒数、序列长度/burn-in/TBPTT、PPO轮数/minibatch、学习率/clip、时间常数
与奖励系数是训练profile字段，必须运行前完整记录；正式取值与投入仍按 #181 批准。
工程短验证使用显式的短profile并标明仅验证接线，不借它新增正式根、种子或预算。

复用现有GRU、BookEncoder、条件Actor和概率重算数学，新增共享z后的独立Critic头。
训练采集使用 `torch.no_grad()` 保存数值与不可变上下文，学习时重新计算图；ContextOnly
推进记忆但不产生策略/价值/熵损失，不把它包装为NoTrade转移。Critic/辅助输出不再喂Actor。

沿共同成熟组件合同，复用TorchRL `ClipPPOLoss`、GAE与TensorDict；循环序列、精确动作
分布和协调屏障由本项目编排，不使用实验高级训练器。TensorDict保存本节轨迹字段及
实际决定mask；Actor分布适配器在原冻结上下文/路径上返回完整动作联合log_prob，
ClipPPOLoss只对联合比率裁剪一次，关闭其默认熵分支。既有独立完整动作样本的熵替代
梯度单独接入，不逐头裁剪，也不使用条件熵和冒充联合熵。
GAE使用TorchRL `generalized_advantage_estimate` 基础函数，输入各根有序决定的
`value/next_value/reward/done/terminated: [R,T,1]`，gamma/lambda按dt形成同形设备张量。
其候选版本[实际源码](https://github.com/pytorch/rl/blob/v0.13.3/torchrl/objectives/value/functional.py)
以逐位置折扣乘法和反向递推消费这些张量，不经scalar/item路径；目标机再核对锁版本行为。
时间轴仅含真实决定，ContextOnly仍在循环重算序列中；没有状态行的时间计入dt，不填造转移。
截断令done切断后续GAE但terminated为假保留bootstrap，真正经济终止terminated才为真。
优势按完整更新有效决定一次总体标准化，minibatch不重新标准化；补齐不参加均值。
`model_train/dt_advantages.py` 提供本节的生产数学函数，显式消费真实奖励区间
`dt_seconds` 与必传 `tau_gamma_seconds/tau_lambda_seconds`，没有正式取值默认。
`present` 只区分真实决定与补齐；`reward_known` 和所需 `bootstrap_known` 不缩小
真实决定人口。任何真实区间未知、原来源故障或时间倒退都令整次更新设备 `ready`
为假；未知/补齐可用计算占位，但不能取得学习资格。合法零间隔折扣为1。真正终止
不要求未使用的bootstrap已知；非经济终止的截断仍需bootstrap。优势与价值目标不带
采集图，标准化使用整批真实决定的总体方差，minibatch仅索引这份结果。
本组件消费奖励区间的known，但尚未提供完整轨迹绑定或optimizer门。后继更新入口必须
在协调边界阻止not-ready批次的 `optimizer.step()`；零loss不是该门，优化器仍可能

再安装新 `E`；迟到来源不回填。区间闭合补齐静默尾段，并精确计算
`10000/2000 * (ΔWCM - a_pusd * area_pusd_ms / 6000000)`，只在末端投影成张量。

## 8. 完整工作集预算与当前单卡安排

设R为获准活动根数，M为仍被引用的市场状态数，E为块事实数，J为总盘口档数，K为真实
撤单人口，T为rollout决定数，Q为积压冻结观察数，L/H为层数/宽度，P为参数数。
以下均按实际字节/人口计算，不由小样本最大值推全域上限：

```text
输入块 B = 固定列字节 + 身份/载荷/值/锚点表字节 + hidden侧表字节
活动环境 S = 完整盘口页 + SIM订单/队列/时延 + NOE待前驱/引用
             + Ledger账户/成本池/贡献 + Registry/预留 + 多字arena实际容量
窗口 W = 各根精确整窗统计 + 各市场history16/路径/冻结端点
冻结 F = Q条输入固定张量 + 唯一仍引用盘口/精确页 + 规则/身份/待发动作
模型 O = 4P权重 + 4P梯度 + 8P Adam一/二阶矩 + Critic及其他实际参数状态
hidden Hs = 4 * L * H * M（含队列中未退役市场）
轨迹 Tr = T条(fast626+slow433+路径/旧概率/价值/奖励/时间/版本)
          + 唯一精确/盘口页 + 保存全层h + 开放转移 + GAE/PPO工作张量
学习 A = 当前minibatch/TBPTT的全部盘口编码/两遍撤单/GRU/Actor/Critic激活及autograd
峰值GPU = 驻留输入块 + 下一块预取 + S + W + F + O + Hs + Tr + A
          + 最大并存CUDA scratch + allocator/上下文开销
峰值CPU = 解压/结构解码批次 + 缓存只读块 + page-locked双缓冲
          + checkpoint序列化快照 + 产物写队列 + 编译/运行控制开销
```

固定市场张量每行 `(626+433)*4=4236` 字节；未压缩补齐盘口为
`B*6*N*(9*4+1)` 字节，实际存储优先变长页，补齐仅学习调用。
L=30/H=1024的每市场全部层hidden为122880字节；这些只是可核算示例，不签发该候选。
对象激活、整段保存h、共享页存活时间和临时有理分母须纳入实测，不能只算参数。

当前已核配额为25 vCPU/90GiB主存、单RTX5090的32607MiB显存。设计起始分配如下，
是可调内存计划，不是业务上限或容量通过证据；同一共享页只计一次：

| GPU用途 | 起始预算GiB |
| --- | --- |
| 当前/下一输入块 | 2+2 |
| 完整盘口及公共行情页 | 2 |
| SIM订单/队列/延迟 | 2 |
| NOE/Ledger/Registry/预留与精确池 | 1 |
| 窗口/全部hidden/冻结观察及待发动作 | 4 |
| 模型/梯度/优化器 | 2 |
| 轨迹及其独占引用页/开放转移 | 5 |

不预分配无用载荷凑使用率；编译阶段与训练可排队避免峰值叠加。工作核启动按最多23核

字节键与返回 permutation 跨 CPU/GPU，原载荷按同一 permutation 搬运。
CPU 继续执行原跨 run 多核归并、来源头选择、公共事实归约和原子持久写入。
这部分保留 CPU 的原因是现有嵌套 Parquet/强类型来源证据和因果归约尚未迁入公共
GPU 后端。此入口是一次冷材料准备的实际接线，不表示 GPU 连续环境已完成。

该入口直接使用 `push_facts` 和紧凑 writer，不要求先写旧 public recording。
当前 writer 发布紧凑材料 v4；它沿用 v3 对每个 packet 的强类型 JSON 独立执行 Zstd level3
压缩。复用锁内 `zstd=0.13.3`，无需新平台依赖；CPU保留成熟流式编解码，原因是
当前嵌套强类型JSON codec在CPU，避免为一次冷持久阶段复制专用GPU codec。
reader 兼容原 v2/v3 身份，并对压缩字节和解压字节分别检查调用者的资源容量；容量不足可
提高资源参数重试，不截断、不丢弃业务。偏移列描述实际压缩字节，自身完成凭据
和SHA覆盖该编码。`--repack <旧材料> <新目标> <packet容量>` 严格读取已完成
材料后重编码，无需原源重扫或业务重归约。

这些版本均只保存源盘口快照/增量；PM 事实和初始步骤引用源输入，Binance
盘口状态引用完整合法公共前缀。完整盘口可按原归约配方重建。reader 检查自身
完成凭据、连续位置、固定列、PM/普通 Produced 实际引用及末端覆盖。它不签发
正式数据验收，也不代替独立 hidden 顺序的准备。

### 请求式清偿的成功经济接线

`SettlementRegistrations` 的显式有限场景可在 `Registered` 后调度
`TerminalSuccess`。成功步骤读取同一根实际资产余额，按原 token 的长度及字串序
输出两个成员，零变化成员不进入人口。BTC 二元来源合格 payout 为赢家 1、输家 0；
销份额与到账保持原微单位，正输家余额即使现金变化为零仍产生原经济转移。
成功守卫阻止重复销份额；这不授权首次发送零应收请求。

NOE `schema21` 将完整判定／政策身份、八列余额及原多资产成员写成一条经济事实。
共享传输和 Ledger 按成员人口消费，不拆平台经济序号。Ledger 先等待公开 Resolution
关联和平台直接前驱，再同事务销实际 token 成本、记录已兑付配对与孤腿量。
未兑付配对到账归 Maker，其余到账归 Directional；费用不因清偿撤回。
市场已实现盈亏持续接原返佣应计，再在清偿经济成功时加到账减被销成本，
不把仅本次清偿增量当作完整累计盈亏。
Request 证据仍独立占一个账本条目，本身不改变余额或应收。

当前自然短例沿原 TypedRaw、GTC、Maker、Terminal、MINED／CONFIRMED 与首次
请求后追加成功步骤。`Registered` 偏移 1、成功偏移 20001、公开领取截点
60000／80000 均为有限工程输入，不是正式训练场景。该例只有一腿正余额；
原 Query／Retry、费用及完整宿主仍需后续实际来源接线与验证。
当前不据两成员物理容量签发完整根或长期容量结论。

双正腿对照复用原共享执行的配对五份、赢家孤腿一份及输家失败补偿屏障场景，
使用 V4 唯一 Memory 消费者取得实际提交材料。原后台写入器在封存前后两个
真实前缀恢复账本，保留原 Request、Economic 正文、position 和首次 visibility。
设备仅冷安装一次清偿前已提交状态；清偿金额由同一 SIM 账户真实余额和原 payout
生成，后态只作对照。生产 NOE 映射保持 token3/-5、token20/-6 两成员原序、
同一 private 及一个平台经济序号，公开 Ledger 将到账 6 归为 Maker 5、Directional 1，
移除两腿成本且保留费用。此处一次经济消费、旧冻结及重复位置对照已运行；
原完整双腿场景的 GPU 接单、失败补偿与结算费用连续推进尚未验收。

### 普通订单 Query 的公开账本消费者

普通 `Control::OrderQuery` 与上述结算请求的 `QueryFinalSuccess` 是不同事实。
设备 `schema25` 保留原 `DirectResponse Request` 逻辑身份、Found/NotFound/OutOfRetention、
完整订单身份和状态、Unknown 原字符串、精确数量及保留水位。原 V1 没有数量时明确保存
数量缺失；`schema26` 同样保留原 V1 Submission 正文，不构造 V2 数量基准。
完整 u64 private 序、source ordinal、context/run/batch/record position 保持原来源坐标。

Ledger 的 `QueryAssociations` 只保存实际发送方显式登记的 Query 请求与原预留关联。
登记使用原本地事件幂等域，增加本地前缀和 Ledger 条目，不改变资金、平台经济前缀或
公开可用前沿。唯一登记入口分配下一个 Ledger 序并按首次空槽追加，增长只尾补空槽，
快照保原序；读取选最后匹配的占用槽，不重排目录。资源不足保留原状态，冷增长后重试
同一操作；普通 NOE 候选、冻结快照和
目录增长沿原公共 Ledger 存储处理。已关联 Found(Open/Matched) 复用原预留确定结果和
订单累计本金 once-only 归约。NotFound、OutOfRetention、无关联及终态 Found 均不确认或
释放未知预留；已消费无关联 Query 不在迟到关联后重新应用。Query 先确认再接经济事实，
以及经济先到再接 Submission/Query，均保留累计接纳本金，不用当前净占款代替。
Submission 的已收到 Accepted 也须有原 SubmissionItem 关联才应用 Ledger 订单生命周期；
未关联 Accepted 不能重开已 Matched 的订单。Query 不属于原订单资金归属来源，不新增或
改写 `OrderFunds`，也不因无关资金目录容量已满而等待；原 Submission 资金观察保持独立。

订单接纳不依赖二元成功份额派生。仅订单/Query 消费者可显式安装实际累计本金目录并
省略成功池；依赖成功池的成交或贡献进入该配置时停止候选提交，保留原记录与全部状态。
完整成功池路径继续承担原成交、贡献和结算归约，这种局部配置不代表完整连续账户。

有限验证沿 `ledger/tests/stage3_economic_lifecycle.rs` 两个原实际 V1 NOE 构造和 CPU Ledger
检查点，导出原记录及本地事件；GPU 冷装一次实际来源后逐步消费，独立核金额、预留状态、
三种前缀、累计本金、开放订单与公开可用前沿，并核同图候选、容量重试和旧冻结。
原合法入口另构造未登记请求的 Accepted(Open) 指向已 Found(Matched) 的订单，CPU/GPU
均保持关闭；真实经济建立的单槽资金目录满后，另一实际预留的 Query 确认仍不改变资金目录。
进度按实际步骤数输出，可由 `B_GPU_QUERY_PROGRESS_EVERY` 调节，0 关闭。
后置验证入口是 `model-train/scripts/run_order_query_validation.sh`，完整成功池路径复用
原 `trade-records` 定向回归。`cf03345` 两个原 Ledger 场景均在 AutoDL 通过，
`c510f64` 完整成功池非空 trade 回归适用；原导出和验证读面失败保留于 #181 实施记录。
Registry 的 V2 Found 消费者见下一节；本批单笔 Base SIM Query 和显式发送登记见后续小节。Found 快照
不能替代原 Submission 数量测量。此处不增加自动查询或重试政策，也不声称完整 Query 宿主、
连续训练、PPO 或活动账户恢复已经交付。

### Native 来源身份的运行内磁盘存储

`SourceIdentityRegistry` 将完整来源键到整数 ID 的索引放入标准库 SQLite，取消 Python
常驻的事件级键字典。键仍是原有的完整有序 `DirectObservationAnchor` 向量，包含路径、
位置、组、消息 ID 和两种时间。SQLite 按完整文本键精确比较，不用摘要代替身份。
同键跨块仍取得同一 ID，不同键不合并；索引不删除键，不因换块、市场或 UTC 日重新编号。
市场身份字典继续按原市场人口维护。

每个当前块沿原冷构造批量绑定，在一个事务中生成原 BBA/参考 ID 张量；逐组 GPU history、
路径、事件/成交窗口和冻结热路径没有 SQL 或新的 CPU 回读。当前块的键向量和 ID 张量是
真实输入，不另保存全部来源键列表。六路每路16槽的历史记忆、未消费窗口和旧冻结保持。

一个运行对象创建并共享一个 registry；当前/下一市场与原根映射继续共享它。临时目录默认
使用训练环境的数据盘 `TMPDIR`，调用方也可明确指定数据盘目录。全部实际消费者释放引用
后关闭连接并删除运行临时目录；验证调用方在整条验证完成后显式关闭，先复制数据库作为
证据。证据副本不是跨运行缓存或活动恢复协议。SQLite 页缓存的当前起始建议为2 MiB，
语句缓存为4项；这是物理配置，不是业务容量或总内存上限，完整准备仍需按实际工作集调整。

有限 Core 代表从空索引开始消费47组/24块，随后才加入原整页独立参考。生产阶段有26键，
数据库28,672字节；当前块冷构造累计0.171秒，包含张量与精确数准备，不是单独 SQL 成本。
真实2成员来源向量保持顺序等价，反序和截短不同；关闭并重开同一 registry 的数据库连接
后，较旧键仍为 ID 3。关闭连接释放该连接的页/语句缓存，但保留同一运行数据库；此代表
不是靠大输入制造缓存压力，也不证明跨运行恢复。完整 Core 入口12.47秒通过。
实际 PM 接纳计数为22，固定历史仅保留最近16槽；另有1个 spot，较旧 TWAP 是独立参考
选择对照。不能把来源计数、历史槽数或 spot/TWAP 混用。

Core 冷阶段 `tracemalloc` 活跃/峰值为1,337,466/9,910,910字节，包含语义对照和24块
尚未冻结窗口的真实引用；不包含 SQLite C 缓存、Torch、驱动或 OS 页缓存，也不是索引
自身的总内存。双市场原连续入口62.00秒通过，其中连续验证56.02秒；10块共享11键，
数据库12,288字节，真实挂单/撤单、非零 history、旧冻结、开市所有层继承和容量续接保持。
两个数据库是不同有限代表，不能合并成正式容量结论。源码快照、命令、原始报告和数据库

本批只改变身份索引物理存储。完整根仍由验证器的材料字段、限定时刻和1–2市场装配，

### 已完成模型任务释放
