# 100ms 窗口输入：语义与物理接口

本文定义 [#181](https://github.com/slowchillchill/btc-updown-marketmaker/issues/181) 的窗口输入，
与[时间与状态合同](100ms-gpu-training.md)共同使用。参考为 `native_inputs_v7`、
`account_economics_v2` 和 `native_actions_v2`。本文只补充模型观察的归约与编码，
不改变公共事实、撮合、账户、动作支持集、收益、训练参数或恢复边界。

本文给出任务1的字段语义和物理接口设计。生产累积器、100ms schema及 GPU 实现尚未交付。
文中的 `reference37` 等名称引用当前 [feature_schema.json](../native-inputs/feature_schema.json)
的配方，不表示新输入必须沿用旧索引或旧总宽度。旧 schema 仍描述已实现的 v7，不能直接
改名为 100ms 版本。

当前增量实现了公共 PM 盘口、直接字段、生命周期、有限窗口及参考的设备接口，完整输入和
环境仍待交付。`public_compact_facts_v4_reference_selection_zstd` 在原准备器执行后记录
`PreparedReferenceSelectionV1`、所属市场和源记录引用。它保存原首条选择，后续设备前缀查询
不能改用最新 TWAP。v2/v3 保持原身份并可读取；重编码不能补出它们缺少的选择能力。
设备列的 `reference_preparation_complete=false` 明确要求沿原合法输入重新准备，不能当作已知无参考。
PM 侧 E9 继续按原 Native 的侧字段路径筛选；`l2`／`l2.absence` 的整簿直接锚点可由公共材料
保留，但不自动计入侧 E9。合法空侧仍区分已知空簿和未观察到盘口。

## 1. 窗口、顺序和共享范围

令 `C_k` 为当前节拍冻结的合法观察截止，`t_k` 为其中的观察 UTC 毫秒。窗口 `W_k`
包含相邻冻结前缀之间新接纳的完整因果组及适用事实。顺序沿公共组序和组内原事实顺序。
它不等于按来源时间筛选的 `[t_k-100,t_k)`；迟到事实只进入实际应用后所属的窗口。

首窗只消费预登记根历史范围内已取得的材料。跨文件、传输块和自然日保留累积状态，
不提前冻结或清空。无公共观察行时沿原无行结果处理。市场首次具有状态行时仍读取该根的
当前窗口，不另起时钟；来源历史和路径样本另沿第 6 节的原市场资格接纳，不向前补样本。

| 材料 | 共享与计数范围 |
| --- | --- |
| 完整组事件及其直接时间证据 | 每个根的每个窗口累计一次；当前市场与下一市场的观察投影共享结果 |
| PM 成交统计 | 从同一窗口事实中按实际市场及 A/B 资产分别选择；其他市场成交不进入这两项，但仍参与完整组事件统计 |
| Binance 成交统计 | 从同一窗口事实中选择 Binance 成交；不同市场行可读取同一统计，不重复增加计数 |
| 市场末状态、来源历史、路径、端点变化 | 按原市场身份分别维护；当前市场与下一市场不能混用 |
| 账户与执行状态 | 同一根在 `C_k` 冻结一次，状态行共享原账户读取；角色位仍区分 `ContextOnly` 与 `DecisionRequired` |

[`MarketBusinessObservationV1.group_events`](../../contracts/src/public_observation.rs)
本来就包含关闭组的全部事实，包括跨市场事件。这里消除的是同组在多个市场投影中的副本。
不同 `PublicFactPositionV1` 的事实不因值相同或引用同一源消息而合并，也不另建来源消息
过滤规则。已有公共组和前缀负责顺序与接纳；输入累积器不再次决定事实是否合法。

第 4、5 节只累计公共行情的 `PublicBusinessFactV1`。本账户的提交、成交反馈、费用、
结算和返佣仍沿公共执行与账本链进入冻结账户材料，不混入公开成交次数。原市场、资产、
根身份和截止前缀继续作为关联元数据，不能用浮点价格或数组位置替代这些身份。

## 2. 数值、单位和缺失

数量、金额、价格和、均值、比率与平方差先按原整数／有理数语义归约，再投影到模型 `f32`。
[exact.rs](../native-inputs/src/exact.rs) 保留为旧高精度有限参考。按独立[裁决 D-0297](https://github.com/slowchillchill/btc-updown-marketmaker/issues/62#issuecomment-5994293485)，
末端 `log1p`／`sqrt` 不再以全域数学正确舍入或跨设备逐位一致作为实现前置；先验证标准CUDA
的FP64计算后转FP32，再独立比较FP32。最终精度结合数值误差、固定模型连续状态／动作／
概率重算、开发集收益风险和完整步骤耗时选择，不预设整个表达式最多1 ULP。

原值求差、必要统计归约、符号、单位和缺失表达保持；不能先把原价格变成FP32再相减，
也不能把巨大分子、分母分别转成溢出的FP64后相除。使用稳定的 `log1p`，不隐含开启全局快速数学优化。
普通比率的 `round_f32` 不随本决定放宽。模型 `f32` 不能反向决定经济金额、数量、费用或合法动作。
GPU 数值表示的实际覆盖仍须实现和对照。必要独立对照服务于真实 100ms GPU 输入及
训练链，在训练服务器按独立计算批次并行；不为旧参考另建低配置执行路线，不把整窗
逐帧 CPU 重放、逐组全量状态输出或先跑完全部参考检查作为 GPU 实现的前置。
旧参考不得成为 GPU 逐步训练回调；本机不执行数值测试、回放或基准。

账户派生归属按[D-0295](https://github.com/slowchillchill/btc-updown-marketmaker/issues/62#issuecomment-5993533059)
及[有限分摊候选](../../contracts/docs/finite-attribution.md)逐步交付；新公共归属结果成为输入的精确原值，
不在消费者内重建旧无限精确成本。上述投影调整来自 D-0297 的单独批准，必要验证随
真实 GPU 链完成；生产输入版本尚未切换，新旧模型及历史证据按实际适用版本区分。

| 记号 | 含义与单位 |
| --- | --- |
| `L(x)` | 非负值的 `log1p(x/u)`；计数以 1 次为单位，其他量取所在字段的 1 个原单位 |
| `S(x)` | `sign(x) * log1p(abs(x)/u)`；用于有符号差值、年龄及原有有符号投影 |
| `phi(p)` | PM 价格或支付比率的 `2*p-1`；价格先以 `1 pUSD/份` 归一化 |
| 比率 | 精确分子／分母后最近偶数舍入到 `f32`；分母为零时数值填零，是否有材料由该组计数或原 presence 表达 |
| 时间 | UTC 毫秒先以 `i128` 相减，除以 1000 得秒，再用 `S`；保留负值，不裁成零 |
| RMS | 精确相邻差平方和除以实际差的数量，再按本节标准浮点候选计算 `sqrt` 与 `log1p`；原区间结果作有限参考 |

PM 数量单位为份，金额为 pUSD，公开成交的 `fee_rate_bps` 单位为 bps；规则中的
`fee_rate` 仍为原无量纲比率，两者不混用。Binance 价格为 USDT/BTC，数量为 BTC，
金额为 USDT。Chainlink 价格为 USD/BTC。不同币种不互换，不用新增换汇假设拼接统计。

市场末状态沿原 `Q6`：Fresh、Stale、Missing、UnknownNotObserved、ConfirmedGap、Invalid。
Fresh／Stale 的可见值继续保留。缺失数值填零，原 value-present、known、适用位和质量位
保留；真实零与缺失不混同。来源时间不从依赖前沿或 lineage 补造。

账户和执行字段沿 `Known`／`Unavailable`／`NotApplicable`：原三槽分别为
`[投影值,1,1]`、`[0,0,1]`、`[0,0,0]`。原单独布尔位、角色位和时间块沿其既有编码。
缺失反馈不等于失败，未知估值不等于零估值，静默行情不等于账户没有变化。

## 3. 窗口末状态与动作材料

以下材料都取自同一 `C_k`。它们表达窗口末状态，不在窗口内求平均。原字段组的完整
内容和 presence 继续继承；本表列出来源和本次观察方式，避免复制一套公共业务定义。

| 字段组／原配方 | 来源和精确计算／投影 | presence 与静默语义 |
| --- | --- | --- |
| 参考价 `reference37` | 原有效参考规则、临时 TWAP、官方锚点、spot／TWAP30／TWAP60；价格用 `S`，已选价格减有效锚点先精确相减再 `S`；窗口秒数用 `L` | 保留原选择、临时存在和值 presence；静默时沿用真实来源值，并用 `t_k` 更新年龄 |
| 三本盘口摘要 `book38` | PM A、PM B、Binance；侧正数量档数及全侧数量用 `L`，侧直接时间用 E9；变化字段按第 7 节 | 保留原 Q6、侧 known；已知空侧的档数和总量为真实零，未知侧不能当空侧 |
| 六侧全部盘口档位 | 同截止公共观察中的全部可见正数量档；PM 价格用 `phi`，Binance 价格用 `L`，数量用 `L`；离同侧最佳价的距离先精确相减再 `L` | 每档保留原 9 项和批次 mask；不设 top-N、不重采样；静默时值不变，实际直接时间年龄推进 |
| PM A/B 直接 BBA `bba28` | 原直接最佳买／卖价和直接 spread；价格用 `phi`、spread 用 `S`，单项时间用 T5 | 保留 Q6、whole-present 和各值 presence；不以归约盘口推导的 BBA 冒充直接 BBA |
| PM A/B 最新成交 `pm_trade18` | 公共末状态中的最新成交；价格 `phi`、数量 `L`、方向类别、费率 `S` 和 T5 | 最新成交与本窗成交统计分开；无新成交不清空旧成交，年龄按 `t_k` 更新 |
| Binance 最新成交 `binance_trade15` | 原最新 aggregate trade；价格 `S`、数量 `L`、buyer-is-maker 及 T5 | 保留 Q6 与 presence；静默时仍是原成交，不增加本窗成交次数 |
| 生命周期 `lifecycle103` | 原 market.window、生命周期、交易状态、active／closed／accepting-orders、terminal；类别、布尔、支付比率及各自直接时间沿原配方 | 每个市场独立计算 `t_k-start_at` 和 `end_at-t_k`，均用 `S(秒)`；静默仍更新，进入 Actor／Critic 共享状态，不增加人工紧迫度分数 |
| 规则 `rule30` | 原资产 tick 为 pUSD/份、LIMIT 最小数量为份、market BUY 最小金额为 pUSD、延迟为秒、费率与指数无量纲，数值用 `L`；tick 带 T5，原布尔及 presence 不变 | 同一冻结规则与实际资产 tick；缺失和不适用保持原义，不以静默窗或来源质量新增交易门槛 |
| 账户／执行 `account433` 参考 | 原 `ActionBeforeReadV2`、账本、预留、NOE 与 `account_economics_v2`；金额、数量、计数及有符号经济量先精确归约再原投影 | 保留全部原字段与三态；同截止公共报价用于 v7 孤腿估值；行情静默时仍读取已合法应用的反馈和经济变化 |
| 撤单对象 `cancel184` 参考 | 原完整对象人口、原请求结果及其时间；字段沿 [cancel.rs](../native-inputs/src/cancel.rs) | 沿原适用位和候选资格，不缩成 top-N，不由本窗成交数过滤 |
| Actor prefix／价格费用材料 | 原 `PrefixState`、完整精确支持集及冻结规则；数量、价格坐标和估费沿 `native_actions_v2` | 随同一决定的原选择步骤生成；不做窗口平均，不因 GPU 实现改变动作域或将失败替换为 NoTrade |

盘口价格顺序沿公共观察：买侧降序、卖侧升序。批次补齐只服务张量合批，全部原档位均参加
原编码；补齐项由 mask 排除。Binance 当前只有整本直接锚点，逐档 T5 和侧 E9 仍为空，
整本时间继续出现在事件时间摘要中。不能把整本锚点复制给每档或伪造中点来源历史。

账户原字段的完整定义继续由 [account.rs](../native-inputs/src/account.rs)、
[values.rs](../native-inputs/src/values.rs)及适用公共合同负责。100ms 不把账户差分替代账户
状态，也不新增收益或奖励字段。执行时间块继续使用同条原反馈的时间，不能借行情时间填空。

## 4. 整窗成交统计

复用 [market.rs](../native-inputs/src/market.rs) 中 `trades` 的精确配方，但输入改为
`W_k` 的全部适用成交事实。当前 `events` 只处理一个 `group_events`，并未实现此累积。
首末成交按合法应用顺序选择，不按来源时间重排。数量、方向或费用缺失时仍保留该成交。

| PM A/B 各自字段组 | 精确累积与投影 | presence／空窗 |
| --- | --- | --- |
| 次数、首／末／最小／最大／算术均价 | `n` 用 `L`；价格和除以 `n` 得均价，五项价格用 `phi` | `n=0` 时整组为零；`n>0` 表示五项价格存在，不能把均价改成 VWAP |
| 已知数量、数量已知比例、已知成交金额 | 对数量存在的事实求 `sum(q)`、`known_q/n`、`sum(p*q)`；数量和金额用 `L`，比例直接投影 | 缺失数量不当成真实零；比例保留已知程度 |
| Buy／Sell／Unknown／方向缺失次数 | 四类各自精确计数后用 `L` | 四类互不代替；无该类时次数为真实零 |
| Buy／Sell 已知数量及已知比例 | 各方向已知数量和用 `L`；该方向数量已知的成交数除以该方向全部成交数，比例直接投影 | 方向分母为零时比例零；Unknown／缺失方向不分摊给 Buy／Sell |
| 已知费用均值、费用已知比例 | 已知 bps 之和除以已知费用数，均值用 `S`；已知数除以 `n` | 无已知费用时均值和比例为零；不能称为真实零费率 |
| E9 | 每笔成交的原 `direct_time`，按第 5 节汇总 | 空窗全零；未知时间保留已知比例 |

| Binance 字段组 | 精确累积与投影 | presence／空窗 |
| --- | --- | --- |
| 次数、首／末／最小／最大／算术均价 | `n` 用 `L`，五项 USDT/BTC 价格用 `S` | `n=0` 整组为零；`n>0` 表示价格存在 |
| BTC 数量、USDT 金额 | 全部成交的 `sum(q)` 与 `sum(p*q)`，分别用 `L` | 原事实数量必有；零次成交不沿用上一窗口的和 |
| 主动 Buy／Sell 次数与数量 | `buyer_is_maker=true` 归主动 Sell，否则 Buy；各计数／数量用 `L` | 原方向含义不反转；无该方向时为真实零 |
| E9 | 每笔成交的原 `direct_time`，按第 5 节汇总 | 与 PM 相同 |

不保存每组已经投影的均值再二次平均，也不对对数数量求和。累积状态只需实际归约所需的
精确计数、和、首末极值和时间界限；公开成交原事实仍由公共模块持有。

## 5. 整窗事件计数与直接时间

沿原 `events104` 的 23 类事件计数，范围改为 `W_k`。每个原事实贡献一次对应类别，
`L(count)` 作为模型值。类别保持：PM full-book、absolute-changes、BBA、tick、trade、
new-market；fixed-identity、initial-tick、lifecycle、trading-state、terminal、quality-boundary；
Chainlink spot、TWAP30、TWAP60、official-anchor、reference-rule；Binance depth、aggregate-trade；
RTDS InvalidType、InvalidTopic、InvalidSymbol、InvalidTimestamp。

计数单位是原事实，不是档位数、市场行数或时间戳数。一次 absolute-changes 消息内有多个
档位也只按一个原事实计数。静默窗口所有事件计数为零；零只说明本窗没有这类已接纳事实，
不能据此证明来源完整、连接存活或设置交易禁令。

事件时间保持 9 类：PM messages、market facts、spot、TWAP30、TWAP60、anchor/reference、
Binance depth、Binance trade、RTDS anomalies。每类从原事实的 `direct_sources` 取时间，
一项直接来源证据贡献一次。成交统计 E9 的分母是成交数；事件 E9 的分母是该类直接来源
证据数。两者不能混用，也不能用事件数替代直接来源证据数。

| 时间字段组 | 精确计算 | 缺失与静默 |
| --- | --- | --- |
| T5 | 单项唯一直接锚点的 `t_k-source`、`t_k-received`、`received-source`，各用 `S(秒)`；再带 source-present、received-present | 没有唯一直接锚点时不择最大时间；来源时间缺失只清空依赖它的项，已有接收时间仍保留 |
| E9 前 6 项 | 对来源年龄、接收年龄、传输时间分别取最小／最大值，各用 `S(秒)` | 该类时间没有已知值时数值零；一个已知值的最小／最大相同 |
| E9 后 3 项 | 来源已知数／总数、接收已知数／总数、成对已知数／总数，精确比例后投影 | 总数零时三项零；数值零和时间真实为零通过已知比例区分 |

累积时保留原绝对时间的必要界限、传输时间界限和已知计数。冻结时统一用 `t_k` 算年龄；
例如已知来源时间的年龄范围为 `t_k-max(source)` 到 `t_k-min(source)`。也可使用数学
等价的精确更新。不能合并先前各组已经用各自观察时间投影的 E9，否则同一
窗口内不同组的年龄基准会不同。末状态的 T5／E9 同样以 `t_k` 编码，但只取其所选字段
的真实直接锚点，不与整窗事件时间合并。

## 6. 来源历史与新增窗口路径摘要

保留原六路来源历史的接纳和生命周期，参考 `MarketHistory::observe_sources` 与
`NativeInputRoot::observe_sources`。PM A/B 使用直接 BBA 的买卖中点；另外三路为
Chainlink spot、TWAP30、TWAP60。每次完整组应用后，只有原可见值和非空直接身份满足原
接纳规则且身份相对上个已接纳样本改变时，才增加样本。值相同但来源身份更新仍是新样本。
缺失、无关组及静默观察不补样本；现有 Binance 中点一路因缺少所需来源证据继续为空。

来源历史仍保留最近 16 个已接纳样本。四项原输出为样本数／16、最后相邻差的 `S`、
相邻差 RMS 的 `L`、首末样本原接纳时刻差的 `S(秒)`。接纳时刻沿各原组
`decision_cutoff` 的逻辑观察时间，不改记为下一次 100ms 观察或 GPU 实际计算时刻。
样本不足两个时后三项为零。
这个 16 是继承的来源缓存语义，不是新训练序列、TBPTT 或 16 个固定窗口的选择。

新增路径摘要只覆盖上述五路当前有真实来源证据的标量。对每路，按原接纳顺序累计本窗
全部样本 `x_1...x_n`；在来源 history16 截断之前将新样本计入窗口，不能只在冻结时遍历
最后 16 项。其最小字段如下：

| 字段 | 精确定义与投影 | presence／静默 |
| --- | --- | --- |
| 样本数 | `L(n)` | `n=0` 表示本窗没有新接纳样本；不等于末状态缺失 |
| 首／末／最小／最大值 | PM 中点先精确求 `(bid+ask)/2`，四项用 `phi`；Chainlink 四项用 `S(USD/BTC)` | `n>0` 才有值，否则四项零；`n=1` 时四项相同 |
| 相邻变化 RMS | `L(sqrt(sum((x_i-x_(i-1))^2)/(n-1)))`，只含本窗内部相邻样本；差、平方和及均值精确计算 | `n<2` 时零；是否有一对样本由本组样本数表达，不把缺一对解释为已观测零波动 |

选择这六项的用途是区分静默、单次更新和窗内往返变化。例如首末同为 `0.50` 的
`0.50→0.55→0.50`，其极值及 RMS 与未变化路径不同。它不是价格回报率、按时间归一化
波动率或完整路径编码；不同路径仍可能得到相同摘要。它不为模型新增跨源合成价格或人工
信号。全盘口、三组成交统计、全部事件类别和原来源历史继续保留，未因只为五路新增摘要
而删减其他来源。

这里的样本是完整组应用后、原来源历史实际接纳的状态。它不声称保留同一原子组内部
每次原字段变化；组内原成交和事件已由第 4、5 节完整统计，不在组内运行观察或 GRU。
相邻已接纳样本之间若出现缺失，沿原历史规则不补值；RMS 表示已接纳样本间的差，不能
据此声称这段来源连续。原质量和事件证据继续可见。

来源历史按市场隐藏身份和原 T-30 资格更新，开市承接，不从 T-30 以前补采样。首个市场
状态行的窗口事件可以非空，而该市场合资格路径样本仍为空，两者范围不同。路径累积每窗
交接一次，历史继续跨窗；冻结后的历史特征和路径结果不能因下一窗口的更新而变化。
市场退役和积压旧观察的释放顺序沿时间合同。历史、窗口和端点状态纳入 #181 活动根协调检查点，具体清单见训练设计第9节。

## 7. 相邻窗口端点变化

原 `book38.side16` 的数量变化和最佳价变化，在新输入中明确比较同一市场、同一侧的
相邻冻结观察端点 `C_(k-1)` 与 `C_k`。比较对象是末状态的精确值，不能取最后两个源组，
也不能取模型计算真正开始时的可变值。每侧保留以下两对字段：

| 字段 | 精确计算／投影 | presence |
| --- | --- | --- |
| 全侧数量变化 | `S(total_k-total_(k-1))`；PM 单位份，Binance 单位 BTC | 两端均为已知侧时存在；已知空侧总量为零 |
| 同侧最佳价变化 | `S(best_k-best_(k-1))`；PM 单位 pUSD/份，Binance 单位 USDT/BTC | 两端均实际存在最佳价时存在；空侧没有最佳价 |

首个有资格的市场状态行没有此前冻结端点，两项数值和 presence 均为零，不从根范围外
或更早源组补一个端点。任一端未知时数值和 presence 也为零；不能跳过未知端点改用更早
已知值。静默窗若两端均已知，则数量／价格变化为真实零且 presence 为真。窗口内部发生
变化后又回到原值，端点差仍为零；它不代替事件或路径统计。

端点基线在窗口冻结顺序上推进，不受 GRU 积压、优化器更新或数据分块影响。市场切换后
沿各自市场身份保存基线，不能把上一市场末值接给下一市场。

订单身份和合法前缀。模型张量仅用于感知和评分，Actor选择后在设备上由公共精确解码

Rust逐条件回调。训练重算使用保存的同截止上下文、原全局路径及原支持；不会用更新后
的账户重算旧动作合法性。设备/训练状态与精确表示见[训练设计](100ms-gpu-training.md)。

## 9. 实现与验证衔接

现有 v7 `NativeInputRoot::observe_sources`、来源采样、投影配方和BookEncoder是复用依据。
新增GPU窗口累积器在完整组应用后更新精确次数、和、极值、身份及时间界限，每100ms
冻结上述输出；不会把最后一组假作完整窗口，也不每事件运行完整编码器/GRU。

必要验证直接运行实际GPU链：同窗多组/跨市场共享计数、迟到事实与hidden隔离、静默
反馈及倒计时、首窗缺失端点/窗内往返、超过16个来源样本、跨块累积及完整盘口恢复。
预期来自可区分错误的固定原事实或适用公共CPU函数，并在训练服务器批量核对；不以
GPU自产的两份相同输出证明正确，不另跑旧全窗逐帧诊断。此处不新增交易拒绝条件。

生产100ms schema、累积器和模型仍待实现。奖励与时间折扣、PPO衔接和完整恢复按
训练设计；正式延迟profile、奖励系数、种子及投入按 #181 对应工程/正式训练前落实。

当前 Native 实现 `gpu/input_history.py` 批量接纳每个完整公共组，显式消费公共交付协调器提供的
逻辑 cutoff，不推定正式根的额外交付延迟为零。完整直接锚点向量的冷身份表可跨块复用；
根记忆包含原市场身份、根起点、最后接纳位置/时刻、精确 history16 及本窗精确路径统计。
冻结只返回清路径的候选状态，不自行提交账户或 GRU。来源同值但新身份、超过16条的窗内路径、
跨批次接纳和静默冻结由原合法 BBA 短链验证；跨块坐标迁移及完整活动根持久恢复仍待装配。
