# 旧末端投影诊断：停用与历史证据

本页对应的独立参考诊断路线已停止。当前开发计划以
[#181](https://github.com/slowchillchill/btc-updown-marketmaker/issues/181) 及
[100ms GPU 时间与状态合同](../docs/100ms-gpu-training.md)为准。不得按本页或历史命令
恢复旧诊断，也不能把诊断代码仍然存在解释为运行授权。B 路线已按 #181 的当前恢复授权推进新架构；
该授权不恢复本页的旧长诊断。仅授权代码审查时不运行计算。

## 被替代的执行方式

旧路线先在 CPU 捕获全部精确末端输入，再由 GPU 批量计算 `log1p`／`sqrt` 替换表，
最后回到 CPU，按各投影政策从根重放比较。真实数据诊断在每个公共组后调用模型，
没有实现正式 100ms 窗口；GPU 只承担末端投影，不是 GPU 常驻训练链。

当前计划取消这条独立路线，包括本机 CPU 比较、低配置参考任务、固定单线程设置、
每种政策完整窗口重放，以及逐组完整特征和隐藏状态落盘的要求。不能把原命令搬到服务器
后继续作为正式 GPU 开发前置，也不新增另一个小参考工程承接同一等待关系。

原命令、配置生成方式及旧比较器合同保留在
[`344fd08` 版本的本文](https://github.com/slowchillchill/btc-updown-marketmaker/blob/344fd08/model-train/scripts/gpu-projection-sensitivity.md)。
该版本仅供解释旧结果和定位失败，不是当前操作手册。

## 历史结果如何解释

- 公共短 BUY 夹具使用固定未训练的 `MAIN-1x256` 组件、共同外生账户前史和有限前缀。
  它记录连续隐藏状态、共同 Actor 路径及各政策自身概率和梯度重算，只支持对应组件结论。
- 真实诊断使用已批准训练内部的 2026-09-15 04:15—04:20 UTC 窗口，Native 根从
  04:14:30 开始；公共来源从更早的合法前序恢复。账户为 2000 pUSD、零仓位、零挂单，
  模型意图不提交。该路线不是 PPO 训练，也不能证明长期盈利或 GPU 常驻容量。
- `exact_cpu`、`fp64_then_fp32`、`fp32_control` 是旧报告中的投影政策标识。
  `discovery_only` 表示替换表缺失实际输入，不能参与完成比较；`status=complete`
  只表示旧测量流程结束，不单独证明精确不变量、梯度重算或业务结果通过。
- 原运行的提交、环境、数据与规则身份、命令、失败记录及已生成报告按原版本保留。
  已中止或失败的诊断仍记录为中止或失败，不能改写为新 100ms GPU 方案的成功证据。
  旧文件保留的逐组数据有历史定位用途，不意味着后续继续生成同规模输出。

## 当前必要检查的归属

末端浮点精度、精确资金、合法动作、连续状态、因果边界及采样／概率重算仍需有能识别
真实错误的证据。这些检查随实际 100ms GPU 输入、环境、模型和 PPO 链完成，复用
仍适用的公共合同与历史证据；必要独立数值对照在训练服务器运行，不把 GPU 自产结果
之间的一致当作独立正确性证明。模型投影政策仍按 D-0297，在标准 CUDA FP64 转 FP32
候选与 FP32 候选之间结合实际数值、模型和业务结果选择，不降低精确经济或合法动作要求。

当前按 #181 选择单张 RTX 5090（32GB 显存），充分使用服务器实际 CPU、内存、GPU 及显存，
按真实资源瓶颈和已批准方向升级单张 RTX PRO 6000 Blackwell（96GB），实例切换由用户操作。
按独立测试、计算批次和已批准账户根并行。同一账户保持因果顺序，
不为增加硬件占用扩大数据、候选、种子或预算。
保留足以解释失败的输入、差异及上下文，输出频率和细节服务于诊断，不再默认逐组
复制所有特征与状态。具体设计和验收归属见[窗口输入设计](../docs/100ms-window-inputs.md)。
