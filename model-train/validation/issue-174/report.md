# #174 完整输入跨帧复用与增量更新

本轮基线为 `43765885dedd2593abdbdde868da3d64ed6fb646`。保留的实现减少神经编码前重复解析、精确投影与打包；原生两个连续窗口、两轮反序均有净收益，但普通窗口包含首次建缓存的均值仍约 6.03 ms，首次调用达到 100—227 ms。16 次独立完整服务共 1,024 组结果一致；大模型高更新窗口首轮退化、反序轮改善，**不宣称整链稳定提速**。全部服务调用仍高于 4 ms 和 1 ms。

## 依赖边界与实现

| 输入或状态 | 完整依赖与本轮处理 |
| --- | --- |
| `book_levels[B,6,N,9]` | 按每市场六侧保留当前十进制原文、精确价量与不可变九维投影。每次扫描当前完整侧；原文相同复用精确解析，数量变化只重做对应数量投影。结构变化建立临时迁移索引，删除过期条目。最佳精确价格改变时，重新做该侧所有精确距离投影。 |

| Binance 逐档 T5 | 继续为零；没有从侧级事件时间虚构逐档时间。 |

新缓存只属于现有 `NativeInputRoot` 的每市场 `MarketHistory`。原 `SidePrevious.logs` 投影树由当前侧缓存替代，独立的前帧业务统计保留。未知观测清空对应侧派生状态；市场退役释放缓存。缓存没有重新归约公共经济事实，也没有把前沿、组号或 f32 价格当成来源身份。结构扫描、索引迁移、锚点扫描及删除都在构造计时内，复杂度仍含 O(档位数＋锚点数)，不声称一般 O(变更档位数)。

旧 `NativeInputGroup` 与 `NativeActor` 通过不可变 `Arc` 持有当时的投影。后续帧产生新版本，不能改写旧组。Rust 同步 ORT 的补齐存储属于消费者，沿当前帧序位复用，并用锁定 `ort` 的 `TensorRef::from_array_view` 在同步调用期间借用。打包存储记录的是仍存活的不可变投影引用，不是公共输入对象地址。

Python 默认 `features()` 仍返回原嵌套数组。实际消费者通过 `shared_books=True` 接收只读侧句柄；未变侧避免重复浮点装箱。已发布 PyTorch 张量从不原地更新：变化帧仍复制必要的整块 book 张量，形状与根映射变化重新分配。`no_grad` 和 `detach` 不作为允许覆盖存储的依据。fast、slow、实际 hidden、必要传输和复制均保留并计入对应成本。

## 测量设计

原生短筛选使用普通 `201582—201645` 和高更新 `418584—418647` 两个连续 64 组窗口，8 个原生线程。四个独立原生根分别连续处理两轮基线和候选，轮内顺序为基线→候选、候选→基线。每组比较全部 f32 位、序列化坐标、隐藏操作、共同历史与业务状态、账户投影和实际补齐值/掩码。另一个独立根逐组只清新增派生缓存，验证可重建性；它保留原历史与前帧统计。

独立基线源码来自本轮固定 main，保留 #172 已合并的时间及规则优化，不重复计入本轮收益。候选不会每组从基线重建。旧检查点只用于恢复已验证的无交易业务前史和真实 hidden；新增缓存不在检查点中，入口首次 `consume` 冷建且计时，后续 63 组正常复用。基线恢复了其原有 `logs` 投影缓存，因此入口对照是“旧实现连续前史恢复”对“新增缓存首次构建”，不能把基线也称作完全冷态。逐组清新增缓存的额外 128 次对照只验证正确性，不混入正式计时统计。

拟保留版本的完整服务采用 MAIN-1×256（ORT 4 线程）及 MAIN-30×1024（ORT 16 线程），原生均为 8 线程。两窗口、两版本、两轮反序共 16 个独立串行运行。每个运行有自己的执行器、账户与 hidden，从录制起点顺序应用公共无交易前史；进入片段后自己生成并执行动作，不在交易中恢复或回滚账户。服务时钟从实际 `consume` 前到实际执行回执，证据序列化和公共前史准备单列。状态图、动作图、权重、数学和模型线程方案均未修改。

## 正确性、所有权与回归

定向原生输入由有效原始解析/归约入口建立，包含同事实时间推进、21→31→31 的总量差值、数量零删除、最佳价插入/删除及投影到同一 f32 的精确价格、已知空/未知恢复。同值的新直接身份沿原历史逻辑推进；全组事件继续包含跨市场事实。独立 `4376588` 编码器比较完整输入和共同状态，新缓存清空后重新构造也必须相同，未把旧缓存树的内部布局当作合同。

## 内存边界

两个原生窗口观测到的各字段最大值为：6,236 个解析档位、8,704 个解析容器容量、2,158,592 字节解析结构容量、159,280 字节文本容量、46,642 字节有理数值位宽、6,236 个投影容量和 224,496 字节当前九维数组容量；当前侧强引用数最高为 3。它们是各自最大值，不能相加为同时堆峰值；有理数内部实际分配容量、分配器元数据和临时扫描结构不在这些载荷字段内。

旧版本持有会额外保留存储。Rust 定向夹具保留 18 个组、12 个 Actor，共 52 个不同投影版本、23,904 字节九维数组容量，释放持有者后弱引用全部消失。该容量由显式输出补采，未重跑性能矩阵。Python 定向夹具在两种梯度模式下都实际持有 8 版 book 张量（共 561,168 字节底层存储）和 8 版 mask（15,588 字节），仍不包含图、反向图和其他输入。候选没有以覆盖已发布张量来消除这部分必要成本。
