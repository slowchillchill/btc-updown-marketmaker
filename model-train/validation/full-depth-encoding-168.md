  `inputs.f32` SHA-256：`9b40c87a5a667724c4c5b8d626ce38e4330dcc1bf4650407ea9304840a6144d0`。

  全部有效档位 3,080,952 个，统一补齐后 9,876,582 个位置。实际行情决定档位数，未截成固定七档。

  每组另选16个均匀位置与单线程 PyTorch 数值参照比较，所有正式输出检查有限性。
- 各配置／线程的基线与候选相邻运行，AB／BA 在每种线程中各12对，在每种配置中各2对。
  全部串行，无竞争 CPU 的测试或构建。正式时间由关闭分析器的 `session.run` 纳秒计时产生，含 Python 调用边界。
  读取、padding、零 hidden 准备在计时外；候选这些准备工作的合并 P50/P99 为0.079／0.121 ms，仅用于标明边界。

  原生特征已有因果历史，零 hidden 只指图的递推输入。**这是抽测，不是五分钟完整连续回放，也不是动作图或端到端计时。**
  分位数用 NumPy `linear`，样本最大值不构成最坏情况保证，不同实验的分位数不能相加。

机器为 AMD RYZEN AI MAX+ 395，16物理核／32逻辑线程。Python 3.13.15、Torch 2.11.0+cpu、

ORT 使用 CPUExecutionProvider、图优化 ALL、SEQUENTIAL、inter-op=1、memory pattern关闭、spinning关闭。

## 热点、实现与空间取舍

1. 五输入图内部按 mask 收集有效行，PM四侧／Binance两侧各用原共享权重编码，散回原坐标后做原归约。
   删去的是 padding 的网络计算，全部有效档位保留；压紧和恢复成本也在正式计时中。
2. 逐档仿射的乘积逻辑布局从输出块／输入轴改为输入／输出轴，保留每个输出的 float32 乘法和相邻配对树。
   紧凑但未换布局的代表64帧筛选 P50 为10.664 ms，加入布局后为3.797 ms；这些是候选筛选，不替代正式矩阵。
   最终26个状态图逐图核对标准节点、五输入／两输出、同权重；归档实际含动作图的6组逐文件保持字节一致。
3. 原生锚点建立当前侧路径索引，重复锚点仍表示时间不唯一；T5直接时间只在当前侧、当前帧按完整时间输入复用。
   精确对数仅复用不可变 `ln(2)` 初始有理区间，需要精度加倍时仍走原区间算法。
4. 每根／市场／侧保存上一帧实际用过的精确对数输入与 f32 结果。价格、数量及距离先形成准确表达式再查表；
   不缓存整行时间。每帧重建当前集合，缺侧／空侧清除，退役随原历史删除，无固定容量、截断或跨账户可变共享状态。
   Rayon持久池每块64行，仅写不重叠纯输出；历史、侧级统计、GRU及同根前后帧保持顺序。
5. 大配置剩余成本主要为原 GRU／特征编码。保留现有实现和 ORT 算子内并行，没有普通 GEMM、近似 log、混合精度、
   自定义运行时算子或层间乱序；线程矩阵验证实际收益，没有为完成步骤强加新内核。

独立 profile 每组4调用（含冷调用和分析器开销）。下表为算子累计毫秒，排除 Loop 容器，子事件仍计入；

首个真实帧在 profile 中最大的单节点输入激活为基线12,247,040字节、候选10,747,904字节，**不是全图峰值内存**。
新仿射一次处理32个输出，旧实现分16个输出块；六侧均深且全部有效时，该乘积临时张量可为旧单块的两倍。
真实稀疏深度的收益不能推广为所有形状都省内存。计时进程 RSS 还包含 PyTorch参照、会话及分配器，不当作纯图内存。

独立真实连续诊断从同批精确观测重建查键序列：63,802,098／63,855,346次前帧命中，约99.9166%；
峰值6,641键，键值载荷估算557,796字节。不包含树节点、分配器容量和前后双表重叠，不是堆峰值。
该完整回放宿主 VmHWM 为82,844 KiB；正式20行各线程宿主为90,376—104,068 KiB，不能归因为缓存单独占用。
诊断会影响机器状态，未混入正式性能轮。

## 行为与数值验证

- Python全部32测试通过；其中原编码同权重输出零容差一致，随机按深度归一化损失下输入／参数梯度按
  `atol=1e-5, rtol=1e-4` 对照，padding输入梯度为零。包含内部空洞、混深度合批、全空／PM空／BN空、
  N=1/257/4096、固定树抵消、有效负max和并列首项梯度。
- 独立原生 continuous-validation 普通回归38通过，默认16个外部产物／长场景测试忽略；独立精确舍入3通过。
  使用平台解析入口的数量、最佳价、插删、锚点缺失／重复、时间推进、深档与价格投影碰撞反例通过。
  后续显式运行实际Actor、深盘口退役和撤单场景，未把其余忽略项记为通过。
- 四代表 `BASELINE-1×256/2×256、MAIN-1×256/30×1024` × 1／16线程，PyTorch／Python ORT／Rust ORT
  每组27案例、2,102次输出比较通过，含N=1/257/4096及动态合批；状态容限保持原 `1e-5 + 1e-4*abs(PyTorch)`，
  任一端非有限失败，最终动作严格比较。四代表实际 BUY／撤单 Actor 检查通过。
- 四代表各执行深盘口完整生命周期7帧：1 ContextOnly、6实际决定、1 Retire，最终各端hidden清空。
  原图选择配对撤单并继续验证冻结撤单竞态的独立检查通过。
- 有界真实连续段为2026-09-16 **00:04:30.011—00:05:00.044 UTC**，完整包含7,752 ContextOnly和32 DecisionRequired。
  MAIN-1×256、BASELINE-2×256各31,136次输出比较通过，最大绝对误差分别2.861e-6／4.321e-7。
  三端各自维护全部层hidden；7,785个原生组在缓存前后全部字段按f32位一致。
  实际出现ResetRootHidden和InitializeZero；该真实段未到市场末端，Retire由上列独立生命周期夹具覆盖。
  此段采用无交易模拟账户，Rust窄验证入口另执行固定Family前缀评分，不冒称自主交易或完整五分钟回放。
  连续准备沿原夹具运行身份；实际候选二进制和源码另按哈希归档，不将夹具身份重标为实测代码身份。

  ```bash

  ```

  `four_source_production_path_sustains_two_to_five_thousand_native_messages_per_second` **跳过**（UTC时钟夹具）。
  Rust ORT独立测试／严格clippy通过，独立工程格式检查通过。
  native严格clippy仍有基线已有的`cancel.rs` needless_borrow及原`side()`九参数lint；未扩大生产修改。
