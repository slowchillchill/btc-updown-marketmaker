# 原生输入与状态图优化验证（#170）

执行合同：[Issue #170](https://github.com/slowchillchill/btc-updown-marketmaker/issues/170)。基线为 `040c7cb00b98b4897f077f8f9dc4ad6156bcc4b6`。测量日期为 2026-09-27 UTC（跨至 2026-09-28 JST）。

## 实现与保留条件

原生侧分别保留缓存单项、投影单项、两者组合及增加 S1 历史复用后的对照。缓存单项只计算一次精确价格距离，并将拥有的精确键批量建成下一帧的有界缓存；相同键仍对应相同精确投影。投影单项复用时间区间上下界相同时的结果，将六侧互不依赖的准备分给同一 Rayon 池，按原侧序写回；六条历史队列仍由原有顺序循环推进。S1 只保存每条原历史队列派生的四个 f32，队列追加或淘汰后重算；同值新事实仍更新，未改变事实身份规则。

BookLinear 保持各输出的相邻配对加法树，直接计算首层相邻输入对的乘积之和，随后继续原归约。生产模型、权重、输入 ABI、有效行压紧及动作图职责保持。输出通道每 8 个一块的早期候选在两个代表模型、两轮筛选中退化，已撤回；其结果另列，不能与最终候选混算。

## 真实输入、选样及计时边界

真实市场为 `btc-updown-5m-1789517100`，来自已选训练日期 2026-09-16，窗口为 00:05—00:10 UTC。全部因果可见、正数量的真实档位均参与编码；档数来自观测，无固定七档输入或深档截断。

原生正式样本按每分钟起点后的首 64 个合格目标帧选取，共五段 320 帧；按实际 `consume` 组去重，保留目标帧到组的映射。旧 20 帧对应 00:04:30.011—00:04:30.035 UTC，原录制组位置为 193830—193849，第一组为投影缓存冷态、其余 19 组为热态，另列统计；此时线程池和公共前史已经准备，不是进程冷启动计时。S2 的两个 64 帧片段按价量增删／变化数量和精确投影输入差集最大事件选择，先冻结身份再计时，不按耗时挑样。

原生准备完整顺序消费原公共前史，保留真实历史队列和上一帧精确输入缓存。每个选中组先保存调用前原生状态、Ledger 派生状态、规则登记、消费游标及 pending，再执行基线首调用；每次候选恢复相同前态。无交易夹具仍有市场接纳 NOE，恢复后的领取、Ledger 应用和市场登记均在完整 `consume` 计时中重新执行，并与首调用比较领取／登记次数及账户投影。仅比较输出相同不足以证明成本相同，本轮因此拒绝了未恢复共享状态的前两次准备尝试。

复制、候选转换和共享状态恢复在计时外，逐调用保存开销；不能把这些准备工作当作免费的端到端收益。S1 转换只从调用前历史推导旧缓存，当前帧的必要重算仍在计时内。额外连续验证只在段入口转换一次，候选随后独立持有并推进缓存与历史。上述接口只存在于离线基准副本，生产未增加快照 API。保留的原 Ledger 记录回调会写入诊断的重复调用，诊断录制不能作为新的权威交易回放。消费恢复不回滚后台耐久确认，也不代表已验证有交易账户的通用快照恢复。

基准副本以四个持久 Rayon 池分别设置 1／4／8／16 线程。计时包含完整 `consume` 和统一的池分派包装；与生产入口的额外包装边界明确区分。原生线程与 ORT 线程分别设置，两者不是同一个线程参数。

原生缓存观测量是当前根保存的精确键数，以及其中仍在调用前缓存内的唯一键数；它不是逐次查找次数或逐次命中率。批量建树和距离向量仍占与当前档数成正比的临时空间，没有增加跨帧无限驻留。原生过程峰值包含前史、五种版本及恢复夹具，不能单独归因为某项生产改动的内存占用。S1 新增的结果载荷为每市场 24 个 f32，即 96 字节，不复制历史队列。

状态图沿用原 1,024 个真实抽样帧和原未训练权重，B=1、每帧零 hidden、输入预构造；只计关闭分析器后的 `session.run`。正式矩阵为 24 个 MAIN 架构 × 4 个线程数 × 基线／候选 × 两轮，共 384 组、393,216 次调用。第二轮反转配置遍历及每对版本顺序。正式矩阵的模块入口经包初始化导入 Torch，但计时进程不执行 Torch 模型；S4 沿用该入口。S3 单独改为直接脚本入口，断言 Torch 未导入，旧四份内存诊断作废。筛选用固定 133 帧和 MAIN-1×256／MAIN-30×1024，独立于正式样本统计。每进程预热 16 次，覆盖最大单侧和总档位形状；输入构造、加载及预热墙钟另记。

ORT 使用 CPUExecutionProvider、ALL 图优化、SEQUENTIAL、inter-op=1，关闭 spinning 和 memory pattern。机器为 AMD RYZEN AI MAX+ 395，16 物理核／32 逻辑线程、128 GB，Linux 7.0.0-34-generic；全部 32 逻辑 CPU 保持可用，schedutil、boost 开启。Python 3.13.15、Torch 2.11.0+cpu、ONNX 1.22.0、ORT 1.28.0、NumPy 2.5.3。未调整亲和性、频率或后台服务，全部 CPU 计时串行运行。

分位数使用 `linear` 插值；样本最大值不是最坏情况上界。原生与状态图的样本和边界不同，其分位数不能相加。**这是有限真实片段与真实帧抽测，不是完整五分钟连续模型回放，也不证明在线实时容量。**连续 hidden 与实际动作消费另作正确性回归，不混入性能表。

### S4：最大值伴随复测

选择正式 MAIN-30×1024／16 线程／候选第一轮的最大值帧 86（27.416 ms），及最接近本轮中位数的帧 1004（14.488 ms），各重复 16 次。正式 S4 保留全部 1,024 帧预构造输入驻留，与原矩阵同模块导入路径、同一图／权重／逐帧五输入、完全相同的 16 帧预热列表；`resident_sample_count=1024`、导入标记和预热列表均已核对。读取计数器在推理墙钟计时外，不回填原最大值。

原最大值帧复测为 13.778—15.324 ms、中位数 14.806；普通帧为 13.723—14.772 ms、中位数 14.381。异常没有重现。两类的平均进程 CPU 为 127.114／124.014 ms、主动切换 1,446.13／1,499.06、被动切换 2.13／2.50、次缺页 1.44／1.63、主缺页均为 0。计数器本身也会扰动执行，CPU／切换／缺页差值包含少量计时外读取开销，不当作纯算子 CPU 时间。没有证据将原最大值定位为缺页、某个固定同步点或盘口剧烈波动，更不能补证旧轮 47.288 ms 的原因。原始值见 [同驻留条件 S4 结果](outlier-matched.json)。

[较早的独立诊断](outlier.json) 只预构造 32 次重复输入，驻留集合与正式矩阵不同，因此另存，不作为完成 S4 相同输入条件的依据；其中两类中位数为 14.490／15.608 ms，也未复现异常。两次独立诊断之间的差异不能单独归因为驻留输入数量。

### CPU 与基准准备成本

状态图的 CPU 为阶段累计进程值，推理阶段差值包括计时外有限值检查等循环工作，并非逐次纯算子 CPU 分位数。原生正式 7,992 次调用所在进程没有采集累计 CPU，报告不从其他运行补填。随后在已有连续段准备中，对旧 20 帧另做基线／最终组合、1／4／8／16 线程、两轮反序的 320 次独立资源调用。每次计时外读取进程累计 CPU 纳秒，覆盖所有线程；原始前后值和增量见 [资源样本](native-resource-samples.csv)。

19 个热帧的最终候选平均墙钟／CPU：1 线程约 14.87／14.86 ms，4 线程约 8.84／16.01，8 线程约 9.09／18.90，16 线程约 9.03／23.34。这里只对同一旧片段两轮均值作资源概览，全部两轮、冷帧及分位数见 [资源摘要](native-resource-summary.csv)。额外线程增加 CPU 成本但没有相应缩短此片段常见耗时，不能据峰值收益无限扩大线程数。


状态图最终候选推理循环的平均进程 CPU／调用（ms），包含计时外有限值检查；不是单次纯推理 CPU 分位数：

正式原生准备加测量墙钟为 6,618.814 秒；属性扫描为 879.747 秒；26 图导出为 480.243 秒；384 组状态矩阵墙钟为 3,117.133 秒。原生连续对照与独立资源诊断为 509.590 秒，GNU time 的 user＋system 为 684.020 秒。这些都包含各自前史、加载、验证及输出等成本，不是纯推理总和。正式原生过程峰值 VmHWM 为 256,068 KiB；连续诊断 VmHWM 为 118,968 KiB，与 GNU time 峰值计数分别保存，不作阶段差分。

320 帧正式原生调用前快照平均 0.238 ms、最大 0.475 ms。8 线程候选重建加共享状态恢复的均值：基线 0.190、缓存 0.179、投影 0.190、组合 0.183、增加 S1 的组合 1.669 ms；S1 的基准转换需要从调用前旧队列推导缓存，实际连续候选只在入口转换一次。这些成本在逐调用 CSV 的 `snapshot_ns`／`restore_ns` 中单列，不能忽略它们后把整套快照式基准称为在线端到端提速。

## 正确性与回归

全部所列验证在最终生产改动上通过，数值容差保持 `atol=1e-5, rtol=1e-4`，非有限值失败；动作选择与对象身份沿既有严格验收。完整摘要和日志／二进制身份见 [验证证据](validation.json)。

- 正式原生 7,992 次：完整输出、调用后精确缓存键及 f32 位、历史值／身份／时刻、hidden／reset，以及同等 NOE 领取／规则登记次数和 Ledger 投影均一致。最终候选与正式副本源代码去除格式及独立注释后完全相同，核对摘要保存在 `provenance.json`。
- 连续原生候选只在段入口转换一次，之后独立推进 7,784 组并逐组核对完整输出和下一状态。输出包含额外一次根隐藏重置，共 7,785 组。MAIN-1×256 与 BASELINE-2×256 分别在三端独立递推全部 7,784 行（7,752 个 ContextOnly、32 个 DecisionRequired），各 31,136 次输出比较，最大绝对误差分别为 2.861e-6／4.470e-7。MAIN 段还与 #168 原完整连续原生输出逐字段／f32 位比较通过。真实段覆盖 ResetRootHidden 和 InitializeZero，未出现的生命周期不记作已覆盖；退役和清除由现有有效业务夹具回归覆盖。
- Python 全量 32 项通过，包含深档压紧前后精确输出、输入／参数梯度、空侧、并列最大值的首位置梯度、动态形状和混合深度递推。原生启用 `continuous-validation` 后普通测试 38 项、舍入测试 3 项通过；默认忽略 16 项。扩展既有历史波动测试，验证未变历史、同值新身份追加及满队列淘汰。
- 四个代表模型（BASELINE-1×256、BASELINE-2×256、MAIN-1×256、MAIN-30×1024）各在 1／16 线程执行三运行时 27 类切片、每组合 2,102 次比较，共 16,816 次，通过既有容差，最大绝对误差 3.815e-5。另运行四代表的同进程实际 actor、真实深档业务执行及原实际撤单竞态夹具，全部通过。真实连续段中的固定 Family 评分不算自主交易，实际动作消费由这些专用回归覆盖。
- Rust ORT 构建、检查及其测试目标通过（该目标当前 0 项单元测试，运行时证据来自上述三端与实际消费者）；原生 Clippy 使用 `-D warnings`，仅排除已有基线 `needless_borrow`／`too_many_arguments` 两类告警；Rust ORT Clippy 使用 `-D warnings`。工作区和原生 Rust 格式检查通过。
- 根工作区固定命令通过：68 个顶层测试目标合计 1,190 passed、18 ignored、1 filtered。只累计每个顶层目标的最终汇总，排除测试内部子进程重复输出。具名 UTC 时钟夹具 `four_source_production_path_sustains_two_to_five_thousand_native_messages_per_second` 明确为 **跳过**，没有计作通过。

```bash
cargo test --workspace --lib --bins --tests --examples --locked --offline -- --skip four_source_production_path_sustains_two_to_five_thousand_native_messages_per_second
```

撤单夹具首次在写证据时因输出目录参数误传为文件路径而失败；创建专用目录后原测试通过，没有修改产品或夹具行为。离线 Python 扩展最终使用锁定环境构建 wheel 并以 `--no-deps` 安装，未修改项目依赖。MAIN／BASELINE 两个完整三端连续验证的外层墙钟分别约 632.681／531.839 秒；其内部计时不含前置原生对照和套件序列化，因此不替代外层成本。T6 是正确性回归，不纳入正式时延统计。
