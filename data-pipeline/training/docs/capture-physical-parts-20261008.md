# 公共与隐藏捕获材料的物理分片

本轮修复属于 #185 任务3。真实准备曾在单个 Parquet 文件超过行组序号上限时失败。锁定的 Parquet 59.0.0 允许一个文件保存32768个行组；写第32769个行组会失败。原捕获器按1024行或64MiB内存批次写入并刷新，不是逐条输入多余刷新。改变额度、压缩或批次不能消除有限文件序号上限。

## 写入与物理定位

`SequentialCaptureWriter::create_segment` 用于公共录制和隐藏派生材料的段出口。写满32768个行组后，它关闭当前文件，再用既有 `part_path` 命名创建下一片。原 `create` 和旧门A固定单文件出口保持原行为，不把旧门A产物消费者宣称为多片消费者。

首片仍为 `captured.parquet`，后续片为 `captured-part-00001.parquet` 等。单片材料不新增描述，仍返回原 Parquet 路径。多片材料用既有 `SortedRun.parts` 保存同目录文件名的有序定位：

```json
{"parts":["captured.parquet","captured-part-00001.parquet"]}
```

描述文件名为 `captured.parts.json`。它不保存业务状态、指标或哈希副本。捕获器继续共用原总字节额度，描述字节也计入此额度。换片不发布公共前缀：所有片与描述仍在同一个 `pending-*` 段内，整个段关闭、同步并原子提交后才得到稳定前缀。写入、关闭、换片或额度失败沿原错误传播，不能把部分片提升为成功材料。

隐藏索引改用已有外部排序器的多片出口 `finish(None)`，保存相同的有序相对片定位。例如 `sorted.parts.json` 定位 `sorted.parquet` 与 `sorted-part-00001.parquet`。它继续使用原排序预算。隐藏准备同步完成后，上层才能发布最终准备描述。

## 消费与兼容

公共读取按描述中的物理顺序推进；稳定前缀只在该逻辑段最后一片结束时核对。参考查询保存真实物理文件、行组和组内行位置，不把逻辑稳定段号当作物理文件号。独立重放继续使用同一公共读取链。

隐藏桶、隐藏步骤和隐藏索引三类读取沿既有 `PartCursor` 连续读取有序片。跨片不闭桶、不重置逻辑位置，也不签发结束。最终准备描述仍使用原公共根、隐藏派生路径和隐藏索引路径字段；隐藏路径可以定位旧单片 Parquet 或新物理片描述。没有第二份业务合同。

读取不会通过目录搜索“剩余片”推测完整材料。描述中的缺片在实际打开文件时返回原错误，不当作有限结束。旧单文件材料、逻辑记录、来源时序、观察与组的位置、隐藏撮合事实及账户读取保持原语义。既有布局成本工具按实际片顺序读取并合并各片页脚信息。

## 定向证据与限制

本轮19项不同定向测试通过，2项既有真实十二分钟布局试验保持忽略；标准 Clippy 与格式检查通过，保留既有警告。必要原始日志及准确候选保存在 `issue-185/capture-parts-20261008`。

- 轻载夹具实际写入32769个行组，得到32768与1组的两片，逐行核对顺序、载荷、结束及包括描述的总字节计数。这证明库边界修复，不是业务容量或性能估计。
- 公共重放逐次比较完整结果；真实参考查询跨片核对TWAP页、截止位置、依赖类型、重复与缺失位置。
- 隐藏材料跨片、跨页核对源时间乱序、纯参考桶、关闭与结束。一个明确列出但被删除的片返回文件打开错误。
- 现有账户复用夹具的两次独立读取改用等价公共和隐藏多片材料；旧完整表示继续作为对照。成交、按原公式计算的费用、最终完整报告与新账户初态一致，原材料逐字保持。
- 原捕获额度失败、公共输入/发布失败、绑定写入失败及最终准备描述失败代表保持原不发布行为。
