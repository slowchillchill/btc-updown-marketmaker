# 历史录制的观察计数与按序后台写入

本轮对应 [#185 任务3](https://github.com/slowchillchill/btc-updown-marketmaker/issues/185)。无统计的公共历史准备不再构造随后丢弃的完整市场观察。公共归约、原组、事实和逻辑观察数量保持；既有持久格式没有变化。

`PublicObservationCoreV1::push_recording` 与正常 `push` 共用输入验证、去重、来源归约、依赖选择和封组。它返回明确的 `PublicRecordingAppliedIngressV1`；每组包含原事实、位置和封组当时的真实 `observation_count`。数量取自同一已登记市场集合，包括已闭市市场。它在完整深度观察投影、来源集合复制和逐市场观察构造前返回。该临时录制材料不能当作策略或统计观察流，也不使用研究专用来源进展入口。

`PublicRecordingWriterV1` 沿同一材料写入逻辑，继续保存原 Input、Canonical／深度参考、报告、绑定和 `GroupObservationRange`。观察位置按真实数量推进。既有 reader 直接恢复完整观察索引与组，独立公共重放仍运行正常 Core 并恢复完整市场观察。需要统计的准备和既有完整观察回调继续使用正常 `push`。

历史循环使用一个 Core 和一个录制线程。主线程先把当次材料转为 owned，再经零容量 FIFO 交接；录制线程接收后，主线程可准备和归约下一输入，录制线程同时执行上一条的物化、身份计算、JSON、Parquet 压缩和写入。零容量表示不额外积压待录制输入，并不表示两线程必须串行。每条初始化绑定随所属输入交接，writer 保持原顺序。

入队不代表持久成功。后台错误经线程结束结果返回；正常 End 后按序排空并稳定成功，才交付 Core 和持久前缀进入隐藏准备。主线程提前失败会关闭通道，不发送正常结束指令，writer 不因此发布。统计入口也使用这一个录制线程，统计回调仍在主线程读取完整结果。

验证覆盖：

- 有效盘口、深度快照／增量／失效／恢复轨迹：完整与计数路径逐组比较事实、数量和位置；计数路径没有建立完整深度观察投影缓存，切回正常入口后完整观察逐字段相同。
- 原两个市场、闭市后加入排序居中市场的夹具：旧完整录制、原历史区间录制和新计数录制的逻辑行、稳定前缀、跨页读取与独立重放相同。仍为实际夹具的 5 组、11 个逻辑观察，不能作为真实容量估计。
- 正常结束排空，以及实际后台 writer 单行载荷超限：返回原错误，不发布成功材料。
- 统计与独立重放、初始化绑定、无统计进度计数、已发布材料重复读取和独立账户的成交、费用与最终经济结果。

13 项不同定向测试通过；最终消息表示调整后补验沿用目标，不重复计数。受影响包标准 Clippy 和格式检查通过，既有警告保留。必要原始日志和候选绑定入口为 `issue-185/observation-projection-20261008`。未执行根 workspace 全量、真实前缀、容量试验或三日双跑。

本轮没有函数热点比例或吞吐测量，不承诺提速比例。来源准备与 Core 因果推进仍按序，原始归约及 Canonical 材料物化仍存在。修改没有改变当前冻结作业的二进制、配置或单次授权，也没有启动账户经营。
