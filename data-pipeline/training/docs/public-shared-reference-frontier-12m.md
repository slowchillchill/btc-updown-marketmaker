# 保存依赖与临时候选共用验证前沿：十二分钟有界对照

本报告对应 [#214 当前分配“保存依赖与临时候选共用验证前沿”](https://github.com/slowchillchill/btc-updown-marketmaker/issues/214)，需求来源为 #185 任务3，父交付为 #1。前段 [PR #222](https://github.com/slowchillchill/btc-updown-marketmaker/pull/222) 已交付有限重放的候选位置索引。本段将非空保存依赖接入同一次 `PublicReplayV1` 的原验证前沿，保留首次依赖完整校验至 EOF 的责任。

同一最终优化测试二进制、既有十二分钟材料、串行各一次，旧依赖与共用依赖均成功：进程墙钟 **192.48→179.86秒**，本次少12.62秒；完整33页、4,981条候选和唯一真实保存依赖返回逐字段相等。消除的是旧候选另行验证的2,990,349条记录；首次非空依赖的3,994,880条完整校验仍发生，约19秒没有被消除。结果只支持本段重复工作减少和此次观察到的端到端改善，不是稳定加速比例、小时预算或策略盈利验收。[机器结果](public-shared-reference-frontier-12m.json)保留准确数值、计量口径与公开投影范围。

## 接线、匹配和失败责任

`finite_reference_candidates.rs` 继续拥有原 `PublicRecordingReaderV1`、原序定宽 Reference 位置/类型索引和原文件定位读取。候选页与保存依赖共用一个推进步骤，原解析、`observe`、分片计数、顺序/流身份及 EOF 检查由原 reader 完成。

空依赖直接返回空，不创建验证 reader。首次非空依赖从已有候选前沿继续，或惰性创建前沿，完整推进至选定稳定视图 EOF 后才读取全部匹配正文。早处命中、异流或不存在的引用均不提前成功；晚段坏 JSON 或 EOF 计数错误仍在该请求失败，失败 Input 不先应用于 core。后续同次重放复用已完成的验证责任，没有新文件改动检测或重哈希。独立公开 `read_dependencies`、历史身份修复及在线候选仍沿原入口。

原保存依赖以 `CanonicalInputRecordRefV1.input_stream_id + input_position` 匹配 Canonical 的 `binding.position.input_stream_id + closed_at_input_position`。原 reader 已逐条检查 Canonical 的流身份等于本稳定视图的流身份，索引无需逐项复制流字符串。按原文件顺序遍历索引，以原 `any` 匹配关系返回全部 Reference：重复引用不重复结果，同位置多事件及非TWAP事件保留，缺失引用仍为空。每条匹配正文用原 RunCursor 有界定位，正文不成为历史缓存。

验证到 EOF 不授权未来事实进入当前候选：原 cutoff、当前 Input 自身候选、页满后的 next/finished、非TWAP越界及唯一选择器保持。索引随 replay 释放，不跨运行、账户或目录共享。
