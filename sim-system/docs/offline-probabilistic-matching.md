# 完整历史约束下的局部概率撮合

模型身份为 `LOCAL_PROBABILISTIC_SHARED_FIFO_V2`。本模型用于 #388 的离线工程对照。平台规则文件显式选择模型；日配置的 `offline_scenes` 将运行标识映射到冻结场景文件。场景文件的内容 SHA、构造参数、原清单引用及准备统计进入运行元数据和比较身份。旧 V2 及 PAPER 保留各自规则身份。

## 事实、参考过程与实际执行

准备入口 `prepare_offline_scene` 复用 `DayIngressV1`、`DayProducerV1` 和公共 PM 归约。它提取准确价位、shares、原接收时间、源时间及稳定派生顺序。策略仍沿原日生产者接收原始公共组。隐藏场景不向策略提供未来片段、随机参数或市场摘要。

BUY 坐标将本资产 BID 和互补资产 ASK 映射到同一资源。两条镜像观测冲突时，参考过程采用正式来源顺序中最后一条观测的数量，不相加；这是匿名盘口重建假设。快照重建差值单独归为参考修正，不直接冒充普通取消或成交。场景的段标识只用于模拟记账，不是真实 L3 订单。

准备过程维护参考外部段。运行过程维护同一段中的实际剩余区间。自单承接成交需求后，参考中原本被成交消耗的外部区间可以继续留在实际队列。后续历史 book 不重新裁齐、补足或扣减实际队列。Taker 与 Maker 需求共享这些区间；Taker 的对价量化继续复用公共执行的累计量化函数。新单在实际生效时加入队尾，成功撤单及 GTD 只移除剩余自单。

## 局部关联与数量

关联仅在同市场、同规范 BUY 坐标及同准确价位内发生。候选窗口事前声明为 50、250、1000 毫秒，并设成交接收时间错开 10 秒的对照。窗口是准备阶段的查找范围，不是运行时的等待时间。

`Nearest` 按接收时间距离、稳定派生顺序分配容量。`DistanceWeighted` 使用由事件身份及种子生成的指数竞争顺序，距离越近权重越大。每条减量和每笔公开成交各有一份剩余 shares，重叠窗口共同领取。分配不是逐条减量独立抽签。`association_trade_shift_ms` 只影响对照中的关联位置，不移动需求实际时间。

未解释成交保留原价、原量及一笔完整需求。未被成交解释的普通减量形成取消候选。参考过程在需求时刻缺量时，于该需求前加入明确的隐含补量事件；准备统计报告其数量。运行时不因策略订单或盘口差值临时补量。当前参考队列不足以覆盖的取消量单列 `unavailable_cancellation_quantity`，不转扣未来新增量。

## 内部时间与取消位置

`SourceWhenPresent` 使用记录的源时间，缺失时使用原接收时间；`Received` 使用原接收时间。二者都是明确的内部时间假设。来源 timestamp 不是对真实撮合时刻的独立证明。原始时间字段仍保留，关联范围不把成交搬到某条减量时刻，也不把一笔需求均匀摊平。

初始化上下文在会话起点按既有因果顺序装入。此时尚无自单。准备范围、目标市场范围和执行起点分别记录，不能把前史或尾上下文计作策略经营范围。

取消规则在准备时选出具体外部段区间，并将结果冻结：

| 参数 | 构造方式 |
| --- | --- |
| `Front` | 优先选择参考队首区间 |
| `Back` | 优先选择参考队尾区间 |
| `SegmentProportionalV2` | 按原外部数量段的存活 shares 分配总量，再在段内存活数量排名上抽一次环形连续区间 |
| `Concentrated` | 对区间作事件级随机排序，连续领取完整区间及最后的部分区间 |

`SegmentProportionalV2` 的整数分配使用大整数计算。设原段的存活量为 q_i、总量为 Q、取消量为 C、同事件随机相位为 u，段 i 获得 `floor((sum_{j<=i} q_j*C+u)/Q)-floor((sum_{j<i} q_j*C+u)/Q)`。份额望远镜求和等于 `min(C,Q)`。随后在该原段全部存活量组成的排名坐标上抽一个连续区间，必要时接回段首，再映射回原坐标。已有空洞不被补回，每个原段每次至多新增两处切边。一个事件的随机结果共同影响全部自单。随机数仅依赖场景种子及外部事件身份，不依赖自单数量、订单 ID、拆单或线程排程。取消目标已被吃掉的部分不再扣量，也不转扣其他段。

## 执行与经济链

冻结成交需求按价格优先、同价 FIFO 消费一份预算。更优报价的自单和外部量共同参与，不因准备按准确价位分组就只允许同价自单成交。主动买单消费互补 BUY 坐标中的外部区间，自单不会与自身成交。post-only、FOK 和资金判断先计算候选计划，通过后才消费数量；拒绝请求不改变队列。

场景成交转换为公共 `apply_maker_depletions` 的输入，继续更新正式订单、预留、费用、最终性和账户事实。NOE 及 Ledger 沿原消费链归约。模拟器不在策略或报告中另算可执行余额。

隐藏合流采用 `offline-scene-before-reference-before-pm-v1`：同毫秒场景事件在原隐藏事实之前，场景内部保持冻结顺序，原隐藏事实保持其原相对顺序。合流重新生成完整毫秒桶、索引和下一事件封口，不把更早场景塞进原桶引用。公开接收流保持原路径。

## 策略信息与宿主审计

公共策略接口只交付当时已送达的行情及自有订单、成交和账户业务事实。隐藏预载、隐藏事件桶和平台推进仍参与原 SIM 执行，但它们的处理数量、actor 输入序号和持久位置不属于策略输入。公开行情、自有反馈、策略状态及调用时点相同时，仅隐藏预载变化不能改变策略可读值；隐藏环境已经改变实际送达的自有反馈时，策略可以作出不同决定。

`shared-run` 分开宿主输入与策略输入。`HostStrategyInputV1` 保存宿主计算所需的可信截止；`StrategyInputV1`、当前读取和后续策略回调使用业务视图。`StrategyObservationCutoffV1` 只携带公开组标识、允许的时间和已交付反馈前缀。原 `applied_input_sequence`、`drive_position`、请求输入序号、NOE 原批引用及日志/checkpoint 继续由宿主保存，不重编号，也不改成公开组计数。

策略行情视图继续借用原业务观察并共享规则和统计；订单、成交及账户读取只提供对应已交付业务字段。单条 NOE 视图不持有整批原引用，不能通过 `Debug`、序列化或比较展开尚未交付的同批记录。安全类型不能反向取得宿主对象。决定、借用/冻结计算、健康与资格检查、派发和失效通知使用同一边界；完整审计和恢复材料保留原身份。

合格返佣的隐藏平台资格属于学习标签，不进入策略的 `learning_account()`。策略仍可读取已交付账本和执行反馈形成的确认经济、义务及已确认成交。宿主按原输入冻结时点保留完整学习标签，由独立轨迹观察器在动作形成后写入原学习记录；策略只提供待记录的业务数据，不接收标签或观察器。整组采集完成后才形成学习目标，原返佣计值、负修正和故障保存语义保持。

该边界用真实策略回调的隐藏预载差分、同批不同交付时点的记录反例、冻结计算/回调及必要恢复回归验证。测试必须同时保留宿主内部输入差异，不能删除隐藏执行或审计字段来制造相等。小夹具证明对应信息隔离，不证明完整日容量，也不把旧版本小时结果直接重标为修复后结果。实际通过项、成本和剩余缺口见 #388 的对应验证记录。

## 固定工程比较

按用户在 #388 的继续裁决，主情景设为 250 毫秒、`Nearest`、`SegmentProportionalV2`、`SourceWhenPresent`、种子 7。主要敏感性采用单因素变化：50/1000 毫秒，`Front`/`Back`/`Concentrated`，`Received`，种子 11/19。关联方法及错位对照通过准备统计比较，不以匹配覆盖率最大证明真实性。固定策略使用 `baseline-mm/configs/strategies/continuous_inventory/adopted-v1.toml` 的完整有效参数。

V2 与新模型可分别运行原日入口。重复公共供料成本需要计入总成本。新模型的关联事实索引复用一次，各场景只重做必要容量分配和抽样，不扫描另一份完整行情。不得按策略收益更改撮合参数或种子。

正确性、真实输入结果、成本及报告由 #388 的实际验证材料证明；有限小时对照与完整日验收分别记录，不以已有小时结果宣称完整日通过。未知归因、源时间解释、镜像冲突、隐含补量和恢复规则均保留模型假设身份。

## 旧逐碎片候选的身份

`LOCAL_PROBABILISTIC_SHARED_FIFO_V1` 与 `Cancellation::Proportional` 表示此前逐存活碎片分配份额并分别随机切割的候选。首市场准备中出现了数百万至两千多万个价位区间碎片；等价批量区间差集仍不足以解决其构造成本，样本受控停止。该候选保留失败身份及准确证据，不标成成功场景或旧 V2 模型。

新整段规则改变了联合概率分布，不能称为纯性能优化。例如同一原段只剩 `[0,4)` 和 `[8,12)`，需要取消 4，旧逐碎片规则每边固定分配 2；新整段环形规则可以取消其中一边全部 4。该改变由用户明确批准，发生在固定策略结果产生之前，不根据收益或更有利种子选择。

准备输入必须让范围内所有会被公共 Core 处理的元数据有合法身份上下文，包括起点正好关闭的前一市场。实际故障记录为 10/17 23:55:00.016 的本地关闭转换；修正使用原文件真实 Snapshot 及现有初始化选择器，不跳过该记录或改写原时间。场景准备只读取原清单引用的 PM market 与 metadata 文件；固定策略回放仍使用原全部七个来源并保留 Binance snapshot/update 连续性校验。

## 流式存储与内存生命周期

新物料使用 `.scene` 小清单和同目录的 `.events.zst` 载荷，存储版本为 `OFFLINE_SCENE_JSONL_ZSTD_V2`。清单保存模型、参数、准备统计、市场身份、来源清单、事件数及载荷 SHA-256。载荷逐条保存完整事件及原坐标取消目标。流中的位置就是全局派生顺序，不按 `source_sequence` 再排序。zstd 只做无损压缩；旧 compact JSON 仍可读取。

准备过程直接向 sink 交付事件，不同时保存所有取消目标。各场景共享一次事实扫描及只读关联索引，`scenario_workers` 显式控制独立场景并行。全局事实顺序及外部段标识保持不变。准备参考队列仅在按实际内部时间排序后的该 condition 最后一条事实处理完后释放，不用市场结束时间或原接收序提前释放。正式运行使用独立流游标；只保留下一条场景事件与必须完整封口的当前毫秒桶。实际队列在原正式匹配关闭点释放，订单、最终性、预留及经济义务仍由原执行状态和账本维护。

区间按最多 4096 条一块保存，缓存每块的存活量。块边界只加速排名查找、前缀消费和区间差集。它不合并原区间，也不改变原外部段身份、随机相位或目标顺序。验证包括跨洞差集、块边界、整数精度，以及旧首市场物料的取消目标逐字段对照。

隐含补量的缺口按与 Demand 完全相同的合法价格优先域计算：同 condition、同规范 BUY token、准确价及更优价位的参考外部量共同参加。更优外部量足够时不补量，不足时只补共同预算的差额。此前首市场先行结果使用修正前代码和物料，保留其原身份，不作为最终新模型结果。

## Taker 的同价量化与人工碎片

外部段及其存活区间只标识共享数量，不代表平台 L3 订单。Taker 不按每个存活碎片独立舍入并提前停止。预览先汇总同一准确价位的实际外部活量，再使用公共整数 quote 和订单预算函数决定可成交 base。算术分母补至整 share 的倍数，使比率准确等于记录价格；补齐部分不参加可成交数量。确定 base 后，按原价位、段标识及坐标顺序选择实际目标。通过 FOK、资金及请求检查后，同一价位的目标一次提交。拒绝请求不消费目标。

每订单、每成交价位形成一笔数量和对价，quote 为公共 `floor(base × price)` 结果。其舍入不按区间数量累积。连续订单仍各自遵守原 quote 最小单位：例如两笔成交的 floor 之和可比合并计算少一个 micro-PUSD；这项差异须明确记录，不能当收益来源或改变种子。测试同时核对累计外部量、实际 principal、费用与现金，并比较碎片和相同活量的完整版本。

post-only 直接按可跨越的正外部量判断，不因首片的 quote 暂为零而放行。如果整个准确价位的活量仍不足一个 quote 单位，该量保持原坐标、不成交且不扣款；它不阻断后续可表达的深度。同价后续新增量可共同使其可表达。该边界来自公共金额精度，不增加订单规模、可信度或策略动作门槛。

## 按市场并行构造

`condition_workers` 控制同一情景内独立 condition 的构造。公共事实和关联结果不复制给各 worker。轻量数量预计划先按原全局 `(internal_time, fact_sequence)` 顺序递推各价位总量，固定每个显式或隐含 Add 的原全局段标识。计划中的 Demand 使用完整合法价格优先域，Recovery 使用差值，不能直接把当前参考量设置为新盘口数量。

每个 worker 处理一个 condition 的两个互补 token 和全部价位，写入带全局 fact rank 的临时压缩流。worker 不等待其它市场的有界事件队列。最终以 rank 合流，并保持同一 fact 的派生先后，再执行初始化时间 clamp。最终载荷及清单完整写入、事件数核对后，才删除已消费的准确临时文件；失败时保留现场。构造、合流、临时逻辑字节和最终字节分别计量。串行与并行在 20 组参数组合上逐字段比较事件及准备统计，实际全日提速和空间成本仍须实测。


持久场景额外保存从原公共归约取得的二元资产身份，只供 SIM 内部预载。预载沿原目录校验，仅登记盘口和撮合数量容器，不登记返佣市场和结束时钟，也不产生消费者 `MarketEnrollment`、NOE 投影或账户市场行。原公开组成功消费后才启用经济 owner 并发布一次，且不再次初始化已保存的队列。已经过市场截止的返佣时钟放在仍未闭合的执行毫秒处理；不倒写原行情或终态来源时间。隐藏路径已保存的合格终态在实际公共消费后沿原经济链补接。GTD、成交最终性及返佣日桶仍须有原订单或成交前驱，隐藏外部数量事件不建立这些前驱。该分离通过公开前／后完整 `StrategyInput` 经济和账本枚举、实际成交余量，以及控制日志恢复验证。

场景数量复用原执行 owner 的六位微单位转换。低于一个 micro-share 的尾数沿原转换截断；原始输入文件及字段不改写，派生精度不是原始行情精度的证明。新增持久 DTO 在原 actor 接纳点核对市场／token 归属及桶内时间，拒绝会使区间差集重复数量的倒置切口。零 Add、零需求、空取消目标及零长切口保持合法 no-op，不增加订单规模门槛。

Back 取消按队尾区间先行，部分区间使用 `[end-n,end)`；Front 使用 `[start,start+n)`。两者的冻结坐标在实际 Taker 已消费其中一部分后仍不转扣其它数量。日入口先完成全部候选场景的打开、SHA 和模型核对，再启动消费者，避免后候选错误留下等待供料的先候选线程。原 SHA 循环按 `progress_interval_seconds` 输出文件、已读／总字节和耗时，0 表示关闭，不增加扫描。

报告的订单观察截止来自候选实际范围／退出点，开放未完成订单保留右删失；markout 使用独立的公共事后评价路径，可能覆盖候选退出之后。评价尾之前没有足够公共覆盖时返回 `UnknownCoverageEnd`，不把未知值计作0。
