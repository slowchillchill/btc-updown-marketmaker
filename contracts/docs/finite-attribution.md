# 有限精度经济归属候选

依据 [D-0295](https://github.com/slowchillchill/btc-updown-marketmaker/issues/62#issuecomment-5993533059)，
#181 保留平均成本形成配对后固定的方法，将递归派生归属改为有限精度。本文定义公共数值
候选；生产 Ledger 尚未切换，当前 `account_economics_v2` / `native_inputs_v7` 的历史
验收及持久事实保持原版本。实际 GPU 接线时绑定新的经济和输入语义，不在活动账户中途换政策。
必要正确性核对并入该路径，复用已完成样板证据；不再以独立低配置参考任务或完整旧 CPU 回放作为接线前置。

## 原事实与派生结果

真实现金、成交份额、本金、费用、预留、实际返佣付款及平台舍入保持原精确事实。源值
可能比12位小数更细，不能截断源事实、添金额上限或为整数实现缩小合法域。
`ExactRationalV1` 继续精确编码结果值；结果按新有限分摊规则产生，不再宣称等于旧无限精确比例。
全局 `EconomicRational` 四则和模型 `round_f32`、`signed_log_f32`、`sqrt_log_f32` 不随本候选修改。
末端log/sqrt的标准浮点验证另按[D-0297](https://github.com/slowchillchill/btc-updown-marketmaker/issues/62#issuecomment-5994293485)及
[100ms窗口输入](../../model-train/docs/100ms-window-inputs.md#2-数值单位和缺失)推进，不混同为本有限分摊候选的已验收能力。

## 二分规则

货币分摊量子候选为 `10^-12 pUSD`；份额贡献候选单独使用 `10^-12 shares`。两者是不同单位，
不能拿份额刻度改变真实成交份额。12位候选须在实际 GPU 经济路径中核对，不表示正式精度验收。

对非负有限十进制总额 `T`，分配比例 `0 <= q <= Q`、`Q > 0`：

1. `q = 0` 时分配为零，剩余为原 `T`；`q = Q` 时分配为原 `T`，剩余为零。
2. 其他比例先精确计算本次 `T*q/Q`，按指定单位做最近偶数舍入。
3. 原金额细于量子时，最近格点可能越过零／总额边界；该分配取对应精确边界。
4. 剩余值恒为 `T - 已分配值`，不独立舍入。源值更细的部分因此保留在分配或剩余值中。

这里的区间是总额分配的数学范围，不是新增资金上限、动作拒绝或源金额裁剪。例如
`T=0.0000000000006`、`q/Q=9/10`，无界舍入会得到 `0.000000000001` 并制造负余项；
候选取原总额作为分配、剩余为零。该例检验细源保留，不允许以“源只到6位”掩盖现有接口。

每次把有限结果写回后再处理下一笔。临时除法可产生分数，但不能把新的数量除数带入
持久成本分母；保存值的十进制位数由原有限源精度与候选刻度决定，不随部分配对次数增长。

## 多项分配候选

逐成交剩余贡献沿原稳定身份顺序，对剩余总份额和剩余权重做二分；末项取得精确余量。
某项保留量不能超过它的原贡献。对当前项原容量 `w`、后续容量和 `F`、剩余待分总量 `T`，
可行区间为 `[max(0,T-F), min(w,T)]`。舍入候选落在该区间内，保证每项非负且分项之和
等于实际剩余份额。无材料仍保持原未知状态，不补造贡献身份。

市场返佣先沿原condition身份汇总贡献，再对原应付与锁定总额分配。账户原门槛、付款
截断与 `locked_remainder_pusd` 业务含义保持；数值尾差不能冒充既有锁定返佣。
已付/未付的互补关系在生产接线前核对原付款与更正合同；本样板不修改源付款或默认增加裁剪。

### B 日归属接线公式

按 D-0295 的市场汇总要求，在首次接纳原 `DayFinalized` 时，先按原 condition
身份汇总该日已接纳的贡献，得到精确权重 `w_i`。condition 序沿原身份序，不能用
物理slot或收到时刻替代。原 SIM 日结果的 `accrued_pusd`、`payable_pusd` 和
`locked_remainder_pusd` 均保持精确源值；本公式只形成市场归属。

分别令待分总额 `T` 为原 payable 和原 locked，总权重 `W = sum(w_i)`。
对每项先计算 `RNE12(T*w_i/W)`，按上述当前/后续容量区间保护；将该项结果
写回，随后以 `T -= 已分值`、`W -= w_i` 继续。最后正权重项取得该分类的精确
余量。两分类各自守恒，不把 payable 的数值尾差加进 locked，不根据两分类的
派生合计重新裁剪或改写源贡献。除端点和细源边界外，每次舍入误差最多半量子；
末项承接该分类累计尾差。两分类的单市场合计因此不承诺等于旧无限比例值。

这一次归属在首次日结果中固定，后续观察复用。当前 B 原 SIM 的付款路径对正
payable 只产生一次全额 Payment：市场已付从已冻结 payable 归属取得，市场未付
取该归属减已付；全额时未付为零。不二次比例分摊，不累加相同付款事实，不通过
Evidence 再增现金或应收；真实变化仍消费独立经济delta。低于原门槛的日结果
继续原 below-threshold 分类。原 `ledger/src/economics.rs` 的 Contribution、
DayFinalized、Payment 和 `RebateDay::amounts` 是原事实/分类依据；原
`sim-system/src/rebate.rs` 保留日门槛、平台截断和单次付款规则。

上述公式不批准分期、负付款、超额付款或日更正，不把有限工程场景参数变成正式
训练场景默认。遇到该类实际来源时保留原事实并回到适用合同，不静默clip。

## 验证与覆盖

- 实际 GPU 公共函数与适用公共计算对同一输入执行相同候选规则，核对分配、剩余及守恒；
  必要 CPU 对照也在训练服务器进行，采用可并行批量并复用结果，不建立另一套长参考运行。
- 覆盖最近偶数的两个方向、零／全额、细源、多个小贡献，以及旧3654轮增长构造的新归约。
- 旧精确有理数仅用于必要的独立正确性核对，保持原成交顺序，不能作为 GPU 热循环逐步 CPU 回调。
- 同一成本池从精确初态开始、原输入在量子网格、每步一次最近舍入、比例系数在[0,1]时，
  `N`次分摊的保守误差界为 `N*delta/2`；若初态已有误差，加上其绝对值。
  该界不是整个账户、策略、返佣归属或训练误差保证；额外舍入须单独计入。
- 最终接线需检验补腿报价、利润预算等实际消费者的临界行为。新旧动作与学习轨迹不承诺一致。
- 固定宽度由实际字段和中间乘除范围决定。当前GPU诊断的256/512位不成为生产金额上限。
  计时必须区分编译、预热和稳态，不能把本样板称为完整一帧或完整训练环境。
