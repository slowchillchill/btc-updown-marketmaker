# 同步借用输入与撤单历史成本（2026-10-13）

本轮对应 #185、D-0342。代码基线为 `8adc4cb8586638a9810019a4bb433add4768fb29`。
本轮只实施同步输入表示和重复读取简化，没有重跑经营研究。

## 实现与业务边界

`shared-run::pending_cancellation_count` 只读取在途撤单数量，沿用原市场关联和
Known/Unavailable。完整 `cancellation_requests` 复用该数量逻辑，仍提供原最新响应和计数。
`ActionPopulation.cancellations` 仍是全部撤单历史，未增加第二个索引或缓存。

`ComplementaryPairV1` 显式选择同步借用路径。`backtest::run` 先领取反馈、准备原截止和观察，
再借用 Registry 和原公开观察，同步执行策略，最后释放借用。策略决定与资格复核共用原策略实现。
借用装配只有 `strategy_borrowed_observation_input`：账户和各市场帧使用同一最新观察截止。
宿主只在启用 source health 且策略显式选择时调用；其他计算保留原拥有式组/观察入口。
借用路径不调用 `action_snapshot`，因此不为未消费的历史撤单响应逐对象预计算。
默认 `StrategyInputV1`、`ActionBeforeReadV2` 和其他策略仍取得完整拥有式冻结。
旧拥有式输入不会被后续反馈改写；Pending 只保留原拥有式计算结果和时序。

动作读取只生成一次 Ledger 经济读取，复用其 `base()`。每次仍从本次观察重估孤腿。
没有跨调用缓存；没有削减健康期限、资格复核、A1、同毫秒失效或 15ms 模拟计算窗口。
SIM 自动结算、精确经济、Maker 模型、累计请求统计和真实 checkpoint 恢复均未改变。
借用只缩短同步调用的表示成本，不改变实际收到哪些事实或允许发送哪些请求。

## 有限同版本路径对照

用例 `completed_cancel_history_owned_and_borrowed_strategy_inputs` 复用原合法材料：
866 个观察市场、301 个成熟来源点，另有原 Maintain 所需的新鲜前缀。
通过正常 SIM 请求形成 1、128、512 个已完成零目标撤单；原策略另有一次旧市场撤单，
故实际总完成量分别为 2、129、513。当前市场只有两笔真实已接受的 50 份策略挂单。
账户还保留原旧市场成交，不能称为全账户空仓。

每格两条路径各预热一次、测 32 次，共 96 对样本，全部为真实 Maintain NoTrade。
每格先验证真实 Actions 的请求身份、内容、记忆、截止和经济读取一致，并正常分派建立挂单。
计时输出不分派；准备、策略恢复、序列化和逐值比较均在计时外。
本表来自收窄观察入口后的候选，同一二进制先测 owning 再测 borrowed；
owning 也已享受投影复用，不能视作原 main 的实测。收窄前的样本与 helper 身份独立保留。
原 sealed 规则及 PAPER/CleanRun 工程夹具身份不变；它不是保守 Maker 历史经营验收。

单位为毫秒；每项写“中位数 / p95”。p95 使用 32 个样本的 nearest-rank 第 31 项。

本构造显示：绕过未用历史预计算后，该规模下借用装配不再随已完成撤单历史明显增长。
残余计数仍可遍历撤单历史，但只在实际取消准备需要时读取；本次证据不支持另建持久索引。
这不是在线端到端延迟、CPU 占比、整场研究提速或容量保证，也没有固定性能门槛。
装配与连续边界是不同计时范围，不能相减当作精确函数分解。

## 验证与失败历史

收窄后有限计时命令实际墙钟 40.632 秒，其中 Cargo 编译 7.85 秒、业务用例 32.72 秒。
首个辅助编译因引用不存在的测试 helper 失败，已保留原错误和当时差异；改为本文件已有的正式
`RequestContextV2` 构造后，输入和期望不变，取得以上成功结果。

实际受影响 shared-run、baseline-mm、backtest、backtest-cli 四包回归：167 通过、0 失败、
7 个原/显式诊断忽略，墙钟 45.882 秒。真实 baseline 的 Trace 委托借用选择和回调，
覆盖健康复核、同毫秒失效、pending/day 恢复；旧完整冻结、迟到 query、部分撤单、零目标完成、
Known/Unavailable 关联、自动结算和精确费用原断言保持。
这不是根全工作区或 B 独立工作区验收。

新增报价代表用例验证同 Ledger 前缀在 36/37/38/40/42 秒的孤腿标记变化，包含 fresh 空 bid 已知零，
owning/borrowed 截止、经济与明细一致，旧拥有式 NAV 不被后续报价改写。
其首轮五个报价点断言均通过，随后误领取无 terminal 材料的 EOF 而失败。
在线核对准确基线原材料与 `stop_and_drain` 后，只在第五个报价点停止；一次复验 1 通过，墙钟 1.419 秒。
不添终态、行情或未来尾部，不改变金额期望。缺报价 NAV 的原既有用例在四包回归中通过。

提交前审查发现新增的非观察借用分支可能混用新账户截止与旧组帧截止。
该分支没有生产消费者，已删除选择布尔及整条分支；不为它新增状态、校验或专属路径。
报价用例改用两种观察表示，五点金额/同 Ledger/旧冻结保持，另核各市场帧截止等于账户截止。
收窄后此用例 1 通过（2.200 秒），实际 source_health 宿主目标 12 通过/2 个原忽略（11.062 秒），
含同毫秒失效及 pending/day 恢复。原四包结果复用于其余未变路径，不重复计为新全量通过。

受影响 all-targets check/clippy、根 workspace 实际消费者静态编译、格式和 diff 检查通过。
根静态编译不覆盖独立 native 工作区；保留既有 warnings，不顺手清理旧代码。
本轮没有运行经营、CPU 采样或训练服务器任务。
