## 3. 错误分类与训练经验分类

### 3.1 错误分类

默认使用以下错误分类，不随意发明新分类：

```text
plan_authority_and_cursor
version_lineage_confusion
dataset_provenance_and_integrity
training_boundary_and_split_leakage
feature_contract_dimension_order
label_visibility_and_temporal_causality
model_bundle_and_artifact_contract
reward_action_semantics
replay_and_leaderboard_truth_surface
paper_trade_runtime_semantics
paper_trade_accounting_reporting
artifact_audit_schema_and_persistence
operational_remote_gpu_sync
performance_resource_misdiagnosis
review_and_process_failure
docs_sync_and_archive_boundary
```

分类说明：

- `version_lineage_confusion`：模型 alias、run root、bundle、dataset boundary、paper runtime profile 混用。
- `dataset_provenance_and_integrity`：canonical root、tarball corruption、manifest/labels/tick_stream completeness、data error exclusions。
- `training_boundary_and_split_leakage`：train/test/holdout 时间边界、new_unassigned_pool、random split、per-file split、cold start handling。
- `feature_contract_dimension_order`：65/76/160 维、FeatureSpecV2、feature order、normalization、account_state shape/order。
- `label_visibility_and_temporal_causality`：`t_decision -> t_exchange_arrival -> t_local_ack`、`y_ev` 可见性、Chainlink label/feature split。
- `model_bundle_and_artifact_contract`：ModelBundleV2、AlphaV2 bundle、ONNX input names、model id/kind、sha/path provenance。
- `reward_action_semantics`：MakerRewardV2、MakerActionV2、SizeHead、Flip、inventory_cap、order frequency reward。
- `replay_and_leaderboard_truth_surface`：Phase 6.5/6.6 replay、leaderboard、diagnostic-only gate、Decision Surface Audit Gate。
- `paper_trade_runtime_semantics`：paper runtime market switch、order lifecycle、oversell reserve、TTL/cancel/fill realism、risk control。
- `paper_trade_accounting_reporting`：PnL/NAV/accounting columns、dashboard/report freshness、formula reconciliation。
- `operational_remote_gpu_sync`：5090 Python 解释器、git push/pull、bundle/rsync fallback、network_turbo、远端源码编辑边界。
- `performance_resource_misdiagnosis`：page cache 与 anon memory 混淆、profiler-first、GPU/CPU 利用率、长任务静默。

### 3.2 训练经验分类

训练经验不是错误台账的附属物。V2 涉及多个模型训练框架、训练批次和 replay/paper 验证面；模型效果不及预期、leaderboard 诊断较弱、候选未入选、某个训练 recipe 被淘汰，这些不一定是错误。只有当源证据明确记录了错误假设、数据泄漏、契约破坏、实现 bug、流程遗漏或证据过度外推时，才进入 `错误实例台账.jsonl`。

训练经验默认使用以下分类：

```text
experiment_result_below_expectation
candidate_selection_signal
hyperparameter_tradeoff
dataset_scope_tradeoff
feature_or_label_signal_learning
reward_action_design_learning
replay_generalization_learning
paper_trade_transfer_learning
resource_efficiency_learning
negative_result_retained
```

分类说明：

- `experiment_result_below_expectation`：训练或 replay 指标不如预期，但没有明确工程错误证据。
- `candidate_selection_signal`：候选模型入选、淘汰、排序变化、稳健性差异形成的经验。
- `hyperparameter_tradeoff`：`seq_len`、batch size、epoch、lambda、模型层数、seed、buffer 设置带来的取舍。
- `dataset_scope_tradeoff`：训练窗口、holdout、new_unassigned_pool、canonical scope 对结果的影响。
- `feature_or_label_signal_learning`：特征、label、target、Chainlink 可见性或 signal gate 对学习信号的影响。
- `reward_action_design_learning`：MakerRewardV2、MakerActionV2、SizeHead、Flip、inventory/risk 设计经验。
- `replay_generalization_learning`：训练内 leaderboard 与独立 replay、全量 replay、paper 迁移之间的差异。
- `paper_trade_transfer_learning`：离线模型迁移到 paper-runtime 后的行为经验。
- `resource_efficiency_learning`：5090 训练/replay 的吞吐、I/O、显存/内存、并行度经验。
- `negative_result_retained`：明确保留的负结果，用于避免未来重复尝试同一方向。

训练经验判定规则：

- 不因“不赚钱”“leaderboard 低”“未入选 top3”“paper 表现弱”直接标记为错误。
- 如果源文档写明这是设计探索、候选筛选、负结果或诊断结论，进入训练经验台账。
- 如果同一段同时记录“结果不佳”和“错误假设/实现修复”，拆成两条：训练经验一条，错误实例一条。
- 训练经验也必须有源路径、行号范围、版本族、训练批次或 run id，不能写成泛泛总结。
