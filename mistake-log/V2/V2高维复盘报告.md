## 版本生命周期复盘
- `v1_m3_m5_archive` 提供早期 dataset、label、feature、offline RL 的历史经验，不能直接覆盖当前 V2 全局契约。
- `alpha_v2` 的主要价值是 gate 体系、边界冻结和 signal calibration；错误多来自边界越权、review 证据误用、远端同步和资源判断。
- `canonical_dataset_20260610` 解决 source-of-truth，但不自动扩大训练边界；corrupt archive 与 exclusion manifest 仍是硬边界。
- `maker_policy_v2` 的关键风险是 bundle lineage、reward/action 语义、decoded action collapse 和 replay 过度解释。
- `paper_trade_v1_runtime` 与 `paper_trade_reporting` 要把 order lifecycle、economic accounting、dashboard freshness 和 multi-profile report 分成不同真相面。

## 根因层次
- 计划权威层：archive/current、diagnostic/promotable、training/paper/live 的边界混用。
- 数据层：canonical root、new_unassigned_pool、time-forward split、label visibility、Chainlink 因果需要一起核对。
- 模型层：alias 不是 bundle，bundle 不是 replay gate，replay gate 不是 paper/live 授权。
- runtime 层：order lifecycle 闭合、sequence buffer 隔离、market switch、settlement 和 accounting 公式需要分层验证。
- 运维层：远端 Python、sync 方式、page cache、cgroup pressure、exit code 和吞吐需要证据化，不能凭单一症状归因。

## 错误与训练经验的分界
- 错误：源证据给出错误假设、修复、contract mismatch、artifact/schema 缺口、路径错误、gate failure 或 root-cause。
- 训练经验：源证据只说明表现弱、泛化不足、候选不可 promotion 或负结果仍有 recipe 价值。
- 混合案例：Phase 6.5/6.7 中 decoded action collapse 是错误/根因，leaderboard 小差异和候选筛选保留为训练经验。

## paper-trade 复盘要点
- order lifecycle 100% 闭合只说明事件生命周期改善，不能替代 NAV、realized PnL、adjusted PnL 与 settlement 差额核对。
- dashboard freshness 只证明展示层 freshness；日报和报告必须从 raw artifacts、manifest 和 profile-local updated_ts 推导。
- MPV2 market switch 后 sequence buffer 隔离是模型输入语义，不能沿用 V1 before_market 习惯。
