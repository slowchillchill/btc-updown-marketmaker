# V2 后续训练技术路径判断

## 状态

- 生成日期：2026-06-28
- 当前状态：已按第一轮独立复审修订，并通过 A/B/C 针对性复审
- 输入依据：`V2训练经验汇总.md`、`V2高维复盘报告.md`、`错误实例台账.jsonl`、`训练经验台账.jsonl`、本地记忆中的 MPV2 lineage/replay/paper 事实，以及外部论文、官方文档和框架文档。
- 边界：本文是训练技术路径建议，不授权训练、replay、paper trade、live trade、部署或数据边界扩大。

## 复审修订摘要

- 本地证据复审结论：大方向成立，Phase 6.5/6.6/6.7 支持 action-surface gate 先于 leaderboard。
- ML/offline RL 复审修订：新增监督式 action ranking、calibration、uncertainty / conformal gate；将 AWAC/AWR/MARWIL 从 CQL/IQL 的保守 offline RL 中拆出。
- 量化交易/market making 复审修订：新增路径 0 `Execution Reality Gate`，把 fill、queue、slippage、fee、rebate、settlement、order lifecycle 与 paper artifact 对账放到所有模型训练和 leaderboard 前。
- 治理修订：模型锦标赛必须有预注册候选、试验预算、失败 run 记录、冻结外层 holdout、nested walk-forward / CPCV、PBO/DSR 或等价多重试验披露。

## 核心结论

后续不应继续沿用“扩大同一套 BC / weighted imitation 训练，然后按 replay leaderboard 排名”的思路。

本地证据显示：Phase 6.5/6.6 中多个 MPV2 候选在 common rows 上 decoded action 完全相同，leaderboard 只产生很小 PnL 差异。这说明当前瓶颈不是模型容量不足，而是 execution reality、action surface、reward/action contract、runtime consumption、offline objective 与验证门槛没有形成可交易行为分化。

后续训练目标应从“训练一个更强模型”改成“训练一组可证伪的交易行为生成器”。每条路径必须先证明执行真实性、动作分化、风险边界、经济账本闭合和 paper runtime 可迁移，再谈 replay 排名或 paper/live 授权。

## 后续训练总原则

1. 训练结果低于预期不等于错误；但 action collapse、执行模型失真、契约不一致、数据泄漏、reward/action 语义错误必须作为阻断项。
2. replay/leaderboard 只作为诊断面；paper/live 授权必须另有 execution gate、runtime gate、accounting gate 和 artifact-backed report。
3. canonical dataset ready 不等于 training boundary 已扩大；`new_unassigned_pool`、exclusion manifest 和 train/test time split 必须先锁定。
4. Alpha 预测、action ranking、maker policy、runtime rendering、inventory、fee/rebate、settlement/accounting 应分层验证，不应把一个端到端分数当作全链路正确。
5. 每个候选必须保留 recipe、dataset scope、model bundle、action-surface audit、execution-reality audit、replay report、paper report 与失败原因。
6. paper runtime 不得参与反复调参；paper 是迁移验证，不是无限搜索的训练集。

## 推荐技术路径

### 路径 0：Execution Reality Gate

优先级：最高，位于所有模型训练、replay leaderboard 和 paper/live 授权之前。

目标是先证明执行环境和经济账本可被模型训练正确消费。没有这个 gate，selected EV、replay PnL、paper adjusted PnL 都可能只是模拟或记账误差。

建议：

- 建立 fill probability、queue position、partial fill、cancel/replace、latency、post-only reject、tick size、marketable/taker delay、adverse fill、calibrated slippage 的校准层。
- 用 paper artifacts 对账：raw trades、orders、risk events、settlement、cash、position、NAV、realized PnL、adjusted PnL 必须能逐层反推。
- fee/rebate 必须使用当前 market info 和真实成交参数；不能用固定常数或旧文档口径替代。
- 订单生命周期必须覆盖 submitted、matched/mined/confirmed、retrying、failed、cancelled、filled、partial filled、TTL、market close、settlement finality。
- simulator 若存在，必须先对 historical replay 与 paper artifacts 做账本闭合校验，再允许进入 RL 或 online fine-tune。

适用原因：

- market making 的收益高度依赖成交到达率、排队位置、库存、报价距离、延迟、取消和费用。
- 本地 paper-trade 经验已经证明 order lifecycle 闭合不等于经济账本闭合，dashboard freshness 也不能替代 raw artifact 报告。

主要风险：

- 真实 queue position 和 fill probability 很难完整观察，只能做保守校准和敏感性分析。
- 过度复杂的 simulator 可能反而制造新的误差源；因此必须先做最小可对账版本。

### 路径 1：Action Surface Audit + BC / AWBC 修复

优先级：高。

目标不是先提高 replay PnL，而是先消除 action collapse，并确认 runtime 真正消费模型输出。

建议：

- 在训练和验证前加入 raw-output 分布、decoded action entropy、threshold sweep、alpha sensitivity、control separation。
- common rows 上若 decoded action 仍完全一致，直接淘汰候选，不进入 replay leaderboard 解释。
- 使用 BC / weighted BC 时，必须证明 reward weight 或 sample weight 会改变 action 分布，而不是只改变 loss 数字。
- replay 排名前先执行 Decision Surface Audit Gate。
- 路径 1 不能绕过路径 0，也不能绕过数据、label、feature、ModelBundleV2 和 reward/action contract 硬门槛。

适用原因：

- 这是最贴近当前 MPV2 failure-root 的路径。
- 成本相对低，可最快验证当前 MPV2 objective 是否还有修复价值。

主要风险：

- 如果行为数据本身缺少高质量多样动作，BC/AWBC 仍可能复制旧行为。
- 如果 runtime 只消费 enabled slots，模型额外输出头不会产生真实交易边。

### 路径 2：Alpha 预测与 maker policy 解耦

优先级：高。

目标是先训练可解释 alpha / EV / side / risk 模型，再由 maker policy 或规则优化器决定 quote/no-quote、offset、size、TTL。

建议：

- Alpha 模型只负责预测概率、EV、方向、波动、risk state，不直接下单。
- maker 层使用独立 policy 或优化器消费 alpha，生成有限 action。
- PatchTST、TSMixer、TFT 等时间序列模型可作为 alpha 表征候选，但不要直接当可交易 policy。
- Alpha gate 必须继续看 selected EV、baseline margin、side-match、no-test-rerank，而不是只看 AUC。
- selected EV 必须在路径 0 的 fee、rebate、slippage、fill probability 和 settlement 约束下重新计算。

适用原因：

- 本地 AlphaV2 经验显示 AUC 不等于 selected-side EV。
- 解耦后可以定位失败来自 alpha 预测、maker action、执行模型，还是 runtime/accounting。

主要风险：

- 如果 alpha 信号弱，maker 层再强也难盈利。
- 如果 label visibility 或 Chainlink causality 被混淆，会重新引入泄漏。

### 路径 2.5：监督式 action ranking + calibration + uncertainty gate

优先级：高，放在 offline RL 之前。

目标是在不直接做 RL 的情况下，对同一 market/time 的候选 quote/no-quote、side、offset、size 做分组排序、概率校准和风险过滤。

建议：

- 对同一 market/time 的候选 action 构造 query/group，训练 supervised ranking 或 learning-to-rank 模型。
- 输出 calibrated probability、calibrated EV、risk interval，不直接下单。
- no-quote、size、TTL 由 calibrated EV、下行分位数、conformal interval、inventory state、fee/rebate 和 fill probability 共同裁决。
- 用 temperature scaling、isotonic calibration、conformalized quantile regression 或等价方法处理概率/区间失真。
- 先和 rule maker、BC/AWBC 做 walk-forward 对照，再进入 offline RL。

适用原因：

- 当前问题包含 selected EV 与 AUC 不一致、action collapse、leaderboard 过度解释；监督式排序和校准比直接 offline RL 更稳。
- 同一时刻/市场的一组候选 action 天然适合 grouped ranking。

主要风险：

- ranking label 若来自失真的 simulator 或不闭合账本，会把 execution bias 学进去。
- calibration 只解决概率和区间口径，不保证交易行为自动可执行。

### 路径 3：规则 maker + 学习型参数头

优先级：高。

目标是用可控 maker baseline 管住执行真实性、库存和生命周期，模型只学习少数参数。

建议：

- 固定规则层处理双边报价、inventory skew、market switch、sequence buffer、quote TTL、stale quote cancel、min order size、settlement、no-quote、kill switch。
- 硬 gate 必须覆盖 inventory、latency、order lifecycle、settlement finality、fee-aware EV、rebate accounting、post-only reject 和 cancel guard。
- 模型只输出 quote/no-quote、side bias、offset bucket、size bucket、risk bucket。
- 每个 action head 都必须证明被 runtime 消费。
- 将 fill、cancel、settlement、realized PnL、adjusted PnL 与 NAV 分层记录。

适用原因：

- market making 经典框架本来就是库存风险、报价距离、时间和成交强度驱动的低维优化问题。
- 规则 maker + 参数头优先于 offline RL，是在当前 transition/reward/runtime accounting 未完全闭合时的工程优先级，不是一般性理论结论。

主要风险：

- 规则层过强会掩盖模型贡献。
- 参数头太粗会限制收益，太细又可能回到 offline RL 数据支持不足的问题。
- 在真实 LOB simulator、高质量状态、完整 reward 和执行闭环存在时，深度 RL market making 可能超过规则基准；当前排序是基于本项目现阶段风险控制。

### 路径 4A：保守 offline RL，优先 CQL / IQL

优先级：中。

目标是在完整 transition dataset 和 reward/action contract 上做保守离线策略改进。

建议：

- CQL/IQL 作为保守 offline RL baseline；重点处理数据分布外动作和 OOD Q-value 过估计。
- 必须先通过 maker_transition、done row、support class、reward interval、guard cancel、settlement backfill、execution reality gate。
- 用 d3rlpy 或最小自研实现做 baseline，对比 BC/AWBC、rule maker、supervised ranking。
- 每个 run 必须输出 OOD action ratio、support coverage、Q distribution、policy action entropy、action support heatmap。

适用原因：

- 外部 offline RL 研究明确指出离线数据分布外动作价值高估是核心风险。
- CQL/IQL 的设计目标与当前“不能盲目选择数据外动作”的问题相关。

主要风险：

- 数据里若缺少优质 maker 行为，保守 offline RL 可能只学会不下单。
- 稀疏长 horizon reward 会让 Q 学习继续不稳定。

### 路径 4B：AWAC / AWR / MARWIL 与 offline-to-online 候选

优先级：中低，不能和 CQL/IQL 混称为保守 offline RL。

目标是用 advantage-weighted imitation 或 offline-to-online 方法，作为 BC/AWBC 与在线微调之间的候选路径。

建议：

- AWAC/AWR/MARWIL 单独记录为 advantage-weighted imitation / offline-to-online family。
- 不把它们当作 CQL 式保守 Q 约束。
- 必须输出 advantage 分布、权重截断、effective sample size、action entropy 和 support coverage。
- 若进入 online fine-tune，必须先通过路径 0、rule maker guard、paper no-submit rehearsal 和 capital cap。

适用原因：

- AWAC 原始定位更接近用 offline data 加速后续 online fine-tuning，而不是纯保守 offline RL。
- 本项目可用它作为 BC/AWBC 修复后的桥接实验。

主要风险：

- advantage 权重若被噪声 reward 或失真执行模型驱动，会放大错误行为。
- online fine-tune 成本和风险高，不能绕过 paper gate。

### 路径 5：Decision Transformer / trajectory model

优先级：中。

目标是把交易过程作为轨迹序列建模，条件化学习不同 return/risk 行为。

建议：

- 输入轨迹必须包含 market_id 边界、inventory、quote state、fills、cancel、settlement、reward、fee/rebate 和 latency。
- 先做短 horizon 和 single-market trajectory，不要一开始跨 market 混合。
- 需要和 BC、CQL/IQL、rule maker、supervised ranking 做同一 walk-forward 对照。
- 如果存在 sparse reward、低质量数据、长 horizon 或 human-demonstration 风格数据，DT 可能比单纯 BC/CQL 更值得提前试验；但仍必须先过 execution reality 和 action-surface gate。

适用原因：

- DT 类方法适合把 RL 转成 return-conditioned sequence modeling，可能更适合长 horizon 行为。

主要风险：

- 若训练数据主要是 collapse 行为，DT 会复制 collapse。
- 如果 return conditioning 不稳定，模型会学到不可执行的伪目标。

### 路径 6：可对账 simulator + paper-online 小步 fine-tune

优先级：分两层处理。simulator/fill/queue/fee 校准属于路径 0，高优先级；online fine-tune 属于后期路径。

目标是构造可对账的 maker simulator，再小步做在线或半在线训练。

建议：

- simulator 必须复现 order lifecycle、fee、rebate、settlement、market switch、sequence buffer、inventory、latency 和 partial fill。
- 先用 historical replay 与 paper artifacts 对账，证明 simulator 账本闭合。
- 再用 PPO/SAC/DRQN 或 RLlib/SB3 做小规模对照。
- 在线 fine-tune 前必须有 kill switch、capital cap、no-submit rehearsal、rollback plan 和 paper-only shadow validation。

适用原因：

- 真实 maker 行为依赖交互反馈，纯离线数据难覆盖。

主要风险：

- simulator 不准会让 RL 学到模拟器漏洞。
- 线上探索成本高，不能绕过 paper gate。

### 路径 7：模型锦标赛 / 元选择器

优先级：贯穿全程，但只能作为治理框架。

目标是不押单一模型，而是用统一证据链淘汰、晋级和保留候选，同时控制多重试验偏差。

建议：

- 候选包括 rule maker、AlphaV2、MPV2 修复版、supervised ranking、CQL/IQL、AWAC/AWR/MARWIL、DT、不同 alpha model。
- 预注册候选、参数范围、试验预算、晋级门槛、失败记录格式。
- 记录所有失败 run，不只记录 winner。
- 冻结外层 holdout，使用 nested walk-forward / CPCV；paper runtime 不得参与反复调参。
- 报告 PBO/DSR，或至少报告试验次数、未选结果、选择过程和外层 holdout 表现。
- paper 多 profile 必须从 raw JSONL、manifest、profile-local updated_ts 生成报告。
- 结论必须分层：training bundle、execution reality gate、replay gate、paper runtime gate、accounting gate、deployment gate。

适用原因：

- 项目已经有多模型训练、replay、paper runtime 的经验积累，适合形成训练工厂式筛选流程。

主要风险：

- 多模型、多参数、多 profile 按表现筛选会天然产生 backtest overfitting 和 selection bias。
- 如果指标体系不分层，锦标赛会把 dashboard freshness、NAV、replay PnL 混成单一结论。

## 推荐执行顺序

0. Execution Reality Gate：fill、queue、slippage、fee、rebate、settlement、order lifecycle 与 paper artifacts 对账。
1. Action Surface Audit + BC/AWBC 修复：确认 decoded action 真的分化且 runtime 消费。
2. Alpha 预测与 maker policy 解耦：只在执行模型校准后比较 selected EV。
3. 监督式 action ranking + calibration + uncertainty gate：先排序、校准和过滤，再谈 RL。
4. 规则 maker + 学习型参数头：含 inventory skew、quote TTL、latency/cancel guards、fee-aware EV。
5. Conservative offline RL：CQL/IQL 必须通过 support、OOD action、execution simulator、nested validation。
6. AWAC/AWR/MARWIL 与 DT：作为中期候选，不能替代 execution reality 和 action gate。
7. 可对账 simulator 后的 paper-online 小步 fine-tune：只在 simulator 对账和 paper gate 之后。
8. 模型锦标赛 / 元选择器：贯穿所有路径，但必须有多重试验控制和冻结 holdout。

短期最该做的是路径 0、1、2、2.5、3。中期再做路径 4A、4B、5。路径 6 的 simulator 校准部分前置到路径 0，online fine-tune 部分后置。路径 7 是治理框架，不是单独模型。

## walk-forward / purged / embargo 规则

- walk-forward 是调参和滚动适应流程，不是最终无偏验收。
- 外层 holdout 必须冻结，不能因为 paper 或 replay 结果反复改参。
- embargo 长度必须由 label horizon、market lifetime、order TTL、settlement lag、reward finalization lag 和 feature lookback 共同决定。
- 如果 reward 或 settlement 跨 market / 跨时间窗口延迟，purge 范围要覆盖完整依赖链。
- 每次调参频率本身也是超参数，必须记录并纳入过拟合风险评估。

## 继续训练前硬门槛

- canonical 数据根、exclusion manifest、new_unassigned_pool 与 training boundary 已明确。
- strict time-forward split、purge、embargo 和 no-test-rerank 已通过。
- `v2_maker_160`、FeatureFrameV2、ModelBundleV2、target contract、label visibility 已锁定。
- MakerRewardV2、MakerActionV2、SizeHead、Flip、inventory/risk/settlement 语义已验证。
- Execution Reality Gate 先于 action-surface audit，action-surface audit 先于 leaderboard。
- paper runtime 的 sequence buffer、market switch、order lifecycle、settlement、adjusted PnL、NAV 报告可从 raw artifacts 反推。
- fee/rebate/settlement/accounting 使用当前 market info、raw trades、rebate 入账、pUSD/settlement、failed/retrying trade 和 NAV/realized/adjusted PnL reconciliation。
- 5090 训练同步使用 git push/pull 优先，资源判断基于 cgroup pressure、throughput、exit code、stdout/stderr。
