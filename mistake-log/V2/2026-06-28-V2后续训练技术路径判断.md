# V2 后续训练技术路径判断

## 状态

- 生成日期：2026-06-28
- 当前状态：已按第一轮独立复审修订，并通过 A/B/C 针对性复审
- 输入依据：`V2训练经验汇总.md`、`V2高维复盘报告.md`、`错误实例台账.jsonl`、`训练经验台账.jsonl`、本地记忆中的 MPV2 谱系/回放/模拟盘事实，以及外部论文、官方文档和框架文档。
- 边界：本文是训练技术路径建议，不授权训练、回放、模拟盘交易、实盘交易、部署或扩大数据边界。

## 复审修订摘要

- 本地证据复审结论：大方向成立，第 6.5/6.6/6.7 阶段支持动作面门禁先于排行榜。
- 机器学习/离线 RL 复审修订：新增监督式动作排序、校准、不确定性/共形门禁；将 AWAC/AWR/MARWIL 从 CQL/IQL 的保守离线 RL 中拆出。
- 量化交易/做市复审修订：新增路径 0“执行真实性门”，把成交、队列、滑点、手续费、返佣、结算、订单生命周期与模拟盘产物对账放到所有模型训练和排行榜之前。
- 治理修订：模型锦标赛必须有预注册候选、试验预算、失败运行记录、冻结的外层留出集、嵌套步进验证/CPCV、PBO/DSR 或等价的多重试验披露。

## 核心结论

后续不应继续沿用“扩大同一套 BC/加权模仿训练，然后按回放排行榜排名”的思路。

本地证据显示：第 6.5/6.6 阶段中多个 MPV2 候选在共同策略样本行上的解码动作完全相同，排行榜只产生很小的 PnL 差异。这说明当前瓶颈不是模型容量不足，而是执行真实性、动作面、奖励/动作合同、运行时消费、离线目标与验证门槛没有形成可交易行为分化。

后续训练目标应从“训练一个更强模型”改成“训练一组可证伪的交易行为生成器”。每条路径必须先证明执行真实性、动作分化、风险边界、经济账本闭合和模拟盘运行时可迁移，再谈回放排名或模拟盘/实盘授权。

## 后续训练总原则

1. 训练结果低于预期不等于错误；但动作坍缩、执行模型失真、合同不一致、数据泄漏、奖励/动作语义错误必须作为阻断项。
2. 回放/排行榜只作为诊断面；模拟盘/实盘授权必须另有执行门、运行时门、核算门和产物支持的报告。
3. 规范数据集就绪不等于训练边界已经扩大；`new_unassigned_pool`、排除项清单和训练/测试时间切分必须先锁定。
4. Alpha 预测、动作排序、做市策略、运行时渲染、库存、手续费/返佣、结算/核算应分层验证，不应把一个端到端分数当作全链路正确。
5. 每个候选必须保留训练方案、数据集范围、模型包、动作面审计、执行真实性审计、回放报告、模拟盘报告与失败原因。
6. 模拟盘运行时不得参与反复调参；模拟盘是迁移验证，不是无限搜索的训练集。

## 推荐技术路径

### 路径 0：执行真实性门

优先级：最高，位于所有模型训练、回放排行榜和模拟盘/实盘授权之前。

目标是先证明执行环境和经济账本可被模型训练正确消费。没有这个门禁，模型所选方向 EV（`selected-side EV`）、回放 PnL、模拟盘调整后 PnL 都可能只是模拟或记账误差。

建议：

- 建立成交概率、队列位置、部分成交、撤单/替换、时延、仅挂单拒绝、最小价格变动单位、可立即成交订单/taker 延迟、不利成交和校准后滑点的校准层。
- 用模拟盘产物对账：原始成交、订单、风险事件、结算、现金、持仓、NAV、已实现 PnL 和调整后 PnL 必须能逐层反推。
- 手续费/返佣必须使用当前市场信息和真实成交参数；不能用固定常数或旧文档口径替代。
- 订单生命周期必须覆盖 `submitted`（已提交）、`matched`/`mined`/`confirmed`（已撮合/已上链/已确认）、`retrying`（重试中）、`failed`（失败）、`cancelled`（已取消）、`filled`（全部成交）、`partial filled`（部分成交）、TTL、市场关闭和结算最终性。
- 若存在模拟器，必须先用历史回放与模拟盘产物校验账本闭合，再允许进入 RL 或在线微调。

适用原因：

- 做市收益高度依赖成交到达率、排队位置、库存、报价距离、延迟、取消和费用。
- 本地 `paper-trade` 经验已经证明订单生命周期闭合不等于经济账本闭合，仪表板新鲜度也不能替代原始产物报告。

主要风险：

- 真实队列位置和成交概率很难完整观察，只能做保守校准和敏感性分析。
- 过度复杂的模拟器可能反而制造新的误差源；因此必须先做最小可对账版本。

### 路径 1：动作面审计 + BC/AWBC 修复

优先级：高。

目标不是先提高回放 PnL，而是先消除动作坍缩，并确认运行时真正消费模型输出。

建议：

- 在训练和验证前加入原始输出分布、解码动作熵、阈值扫描、Alpha 敏感性和对照组分离检查。
- 若共同策略样本行上的解码动作仍完全一致，直接淘汰候选，不进入回放排行榜解释。
- 使用 BC/加权 BC 时，必须证明奖励权重或样本权重会改变动作分布，而不只是改变损失数值。
- 回放排名前先执行决策面审计门。
- 路径 1 不能绕过路径 0，也不能绕过数据、标签、特征、`ModelBundleV2` 和奖励/动作合同硬门槛。

适用原因：

- 这是最贴近当前 MPV2 失败根因的路径。
- 成本相对低，可最快验证当前 MPV2 目标函数是否还有修复价值。

主要风险：

- 如果行为数据本身缺少高质量多样动作，BC/AWBC 仍可能复制旧行为。
- 如果运行时只消费已启用槽位，模型额外输出头不会产生真实交易优势。

### 路径 2：Alpha 预测与做市策略解耦

优先级：高。

目标是先训练可解释的 Alpha/EV/方向/风险模型，再由做市策略或规则优化器决定报价/不报价、偏移、规模和 TTL。

建议：

- Alpha 模型只负责预测概率、EV、方向、波动和风险状态，不直接下单。
- 做市层使用独立策略或优化器消费 Alpha，生成有限动作。
- PatchTST、TSMixer、TFT 等时间序列模型可作为 Alpha 表征候选，但不要直接当作可交易策略。
- Alpha 门禁必须继续看模型所选方向的头部分位 EV（`selected_side_top_decile_ev`）、基线差额（`baseline_margin_ev`）、方向匹配和禁止测试集重排（`no-test-rerank`），而不是只看 AUC。
- 模型所选方向的头部分位 EV 必须在路径 0 的手续费、返佣、滑点、成交概率和结算约束下重新计算。

适用原因：

- 本地 AlphaV2 经验显示 AUC 不等于选中方向 EV。
- 解耦后可以定位失败来自 Alpha 预测、做市动作、执行模型，还是运行时/核算。

主要风险：

- 如果 Alpha 信号弱，做市层再强也难盈利。
- 如果标签可见性或 Chainlink 因果关系被混淆，会重新引入泄漏。

### 路径 2.5：监督式动作排序 + 校准 + 不确定性门禁

优先级：高，放在离线 RL 之前。

目标是在不直接做 RL 的情况下，对同一市场/时刻的候选报价/不报价、方向、偏移和规模做分组排序、概率校准和风险过滤。

建议：

- 对同一市场/时刻的候选动作构造查询组，训练监督式排序或排序学习模型。
- 输出校准后概率、校准后 EV 和风险区间，不直接下单。
- 不报价、规模和 TTL 由校准后 EV、下行分位数、共形区间、库存状态、手续费/返佣和成交概率共同裁决。
- 用温度缩放、保序回归校准、共形分位数回归或等价方法处理概率/区间失真。
- 先和规则做市、BC/AWBC 做步进验证对照，再进入离线 RL。

适用原因：

- 当前问题包含模型所选方向 EV 与 AUC 不一致、动作坍缩、排行榜过度解释；监督式排序和校准比直接采用离线 RL 更稳。
- 同一时刻/市场的一组候选动作天然适合分组排序。

主要风险：

- 如果排序标签来自失真的模拟器或未闭合账本，模型会学入执行偏差。
- 校准只解决概率和区间口径，不保证交易行为自动可执行。

### 路径 3：规则做市 + 学习型参数头

优先级：高。

目标是用可控的做市基线管住执行真实性、库存和生命周期，模型只学习少数参数。

建议：

- 固定规则层处理双边报价、库存偏斜、市场切换、序列缓冲区、报价 TTL、过时报价撤单、最小订单规模、结算、不报价和紧急停止开关。
- 硬门禁必须覆盖库存、时延、订单生命周期、结算最终性、考虑手续费的 EV、返佣核算、仅挂单拒绝和撤单保护。
- 模型只输出报价/不报价、方向偏置、偏移档位、规模档位和风险档位。
- 每个动作头都必须证明被运行时消费。
- 将成交、撤单、结算、已实现 PnL、调整后 PnL 与 NAV 分层记录。

适用原因：

- 经典做市框架本来就是由库存风险、报价距离、时间和成交强度驱动的低维优化问题。
- 规则做市 + 参数头优先于离线 RL，是在当前状态转换/奖励/运行时核算未完全闭合时的工程优先级，不是一般性理论结论。

主要风险：

- 规则层过强会掩盖模型贡献。
- 参数头太粗会限制收益，太细又可能回到离线 RL 数据支持不足的问题。
- 在真实 LOB 模拟器、高质量状态、完整奖励和执行闭环存在时，深度 RL 做市可能超过规则基准；当前排序基于本项目现阶段的风险控制。

### 路径 4A：保守离线 RL，优先 CQL/IQL

优先级：中。

目标是在完整状态转换数据集和奖励/动作合同上做保守离线策略改进。

建议：

- CQL/IQL 作为保守离线 RL 基线；重点处理数据分布外动作和 OOD Q 值过估计。
- 必须先通过 `maker_transition`、终止行、支持类别、奖励区间、保护性撤单、结算回填和执行真实性门。
- 用 d3rlpy 或最小自研实现建立基线，对比 BC/AWBC、规则做市和监督式排序。
- 每次运行必须输出 OOD 动作比例、支持覆盖率、Q 值分布、策略动作熵和动作支持热力图。

适用原因：

- 外部离线 RL 研究明确指出，离线数据分布外动作价值高估是核心风险。
- CQL/IQL 的设计目标与当前“不能盲目选择数据外动作”的问题相关。

主要风险：

- 数据里若缺少优质做市行为，保守离线 RL 可能只学会不下单。
- 稀疏的长时域奖励会让 Q 学习继续不稳定。

### 路径 4B：AWAC/AWR/MARWIL 与离线到在线候选

优先级：中低，不能和 CQL/IQL 混称为保守离线 RL。

目标是用优势加权模仿或离线到在线方法，作为 BC/AWBC 与在线微调之间的候选路径。

建议：

- AWAC/AWR/MARWIL 单独记录为优势加权模仿/离线到在线方法族。
- 不把它们当作 CQL 式保守 Q 约束。
- 必须输出优势分布、权重截断、有效样本量、动作熵和支持覆盖率。
- 若进入在线微调，必须先通过路径 0、规则做市保护、模拟盘禁止提交演练和资金上限。

适用原因：

- AWAC 的原始定位更接近用离线数据加速后续在线微调，而不是纯保守离线 RL。
- 本项目可用它作为 BC/AWBC 修复后的桥接实验。

主要风险：

- 如果优势权重受噪声奖励或失真执行模型驱动，会放大错误行为。
- 在线微调的成本和风险高，不能绕过模拟盘门禁。

### 路径 5：Decision Transformer/轨迹模型

优先级：中。

目标是把交易过程作为轨迹序列建模，条件化学习不同收益/风险行为。

建议：

- 输入轨迹必须包含 `market_id` 边界、库存、报价状态、成交、撤单、结算、奖励、手续费/返佣和时延。
- 先做短时域、单市场轨迹，不要一开始就跨市场混合。
- 需要和 BC、CQL/IQL、规则做市、监督式排序做同一步进验证对照。
- 如果存在稀疏奖励、低质量数据、长时域或人工示范风格数据，DT 可能比单纯 BC/CQL 更值得提前试验；但仍必须先通过执行真实性门和动作面门禁。

适用原因：

- DT 类方法适合把 RL 转成以收益为条件的序列建模（`return-conditioned sequence modeling`），可能更适合长时域行为。

主要风险：

- 若训练数据主要是坍缩行为，DT 会复制这种坍缩。
- 如果收益条件化不稳定，模型会学到不可执行的伪目标。

### 路径 6：可对账模拟器 + 模拟盘在线小步微调

优先级：分两层处理。模拟器/成交/队列/手续费校准属于路径 0，优先级高；在线微调属于后期路径。

目标是构造可对账的做市模拟器，再小步进行在线或半在线训练。

建议：

- 模拟器必须复现订单生命周期、手续费、返佣、结算、市场切换、序列缓冲区、库存、时延和部分成交。
- 先用历史回放与模拟盘产物对账，证明模拟器账本闭合。
- 再用 PPO/SAC/DRQN 或 RLlib/SB3 做小规模对照。
- 在线微调前必须有紧急停止开关、资金上限、禁止提交演练、回滚计划和仅模拟盘影子验证。

适用原因：

- 真实做市行为依赖交互反馈，纯离线数据难以覆盖。

主要风险：

- 模拟器不准确会让 RL 学到模拟器漏洞。
- 线上探索成本高，不能绕过模拟盘门禁。

### 路径 7：模型锦标赛 / 元选择器

优先级：贯穿全程，但只能作为治理框架。

目标是不押单一模型，而是用统一证据链淘汰、晋级和保留候选，同时控制多重试验偏差。

建议：

- 候选包括规则做市、AlphaV2、MPV2 修复版、监督式排序、CQL/IQL、AWAC/AWR/MARWIL、DT 及不同 Alpha 模型。
- 预注册候选、参数范围、试验预算、晋级门槛、失败记录格式。
- 记录所有失败运行，不只记录胜出者。
- 冻结外层留出集，使用嵌套步进验证/CPCV；模拟盘运行时不得参与反复调参。
- 报告 PBO/DSR，或至少报告试验次数、未选结果、选择过程和外层留出集表现。
- 模拟盘多配置报告必须从原始 JSONL、清单和各配置自身的 `updated_ts` 生成。
- 结论必须分层：训练模型包、执行真实性门、回放门、模拟盘运行时门、核算门和部署门。

适用原因：

- 项目已经积累多模型训练、回放和模拟盘运行时经验，适合形成训练工厂式筛选流程。

主要风险：

- 多模型、多参数、多配置按表现筛选会天然产生回测过拟合和选择偏差。
- 如果指标体系不分层，锦标赛会把仪表板新鲜度、NAV 和回放 PnL 混成单一结论。

## 推荐执行顺序

0. 执行真实性门：成交、队列、滑点、手续费、返佣、结算、订单生命周期与模拟盘产物对账。
1. 动作面审计 + BC/AWBC 修复：确认解码动作确实分化且被运行时消费。
2. Alpha 预测与做市策略解耦：只在执行模型校准后比较模型所选方向 EV。
3. 监督式动作排序 + 校准 + 不确定性门禁：先排序、校准和过滤，再谈 RL。
4. 规则做市 + 学习型参数头：包括库存偏斜、报价 TTL、时延/撤单保护和考虑手续费的 EV。
5. 保守离线 RL：CQL/IQL 必须通过支持范围、OOD 动作、执行模拟器和嵌套验证检查。
6. AWAC/AWR/MARWIL 与 DT：作为中期候选，不能替代执行真实性门和动作门。
7. 可对账模拟器后的模拟盘在线小步微调：只在模拟器对账和模拟盘门禁之后进行。
8. 模型锦标赛/元选择器：贯穿所有路径，但必须有多重试验控制和冻结的留出集。

短期最该做的是路径 0、1、2、2.5、3。中期再做路径 4A、4B、5。路径 6 的模拟器校准部分前置到路径 0，在线微调部分后置。路径 7 是治理框架，不是单独模型。

## 步进验证/清洗期（`purge`）/隔离期（`embargo`）规则

- 步进验证是调参和滚动适应流程，不是最终无偏验收。
- 外层留出集必须冻结，不能因为模拟盘或回放结果反复改参。
- 隔离期（`embargo`）长度必须由标签时域、市场生命周期、订单 TTL、结算延迟、奖励最终确定延迟和特征回看窗口共同决定。
- 如果奖励或结算跨市场/跨时间窗口延迟，清洗期（`purge`）范围要覆盖完整依赖链。
- 每次调参频率本身也是超参数，必须记录并纳入过拟合风险评估。
