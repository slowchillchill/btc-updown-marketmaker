## 结论

当前 `poly-tx` 不能作为新系统的数据层基础直接复用。它可以作为历史采集雏形，但必须先重构为“市场发现 gate + T-30s 预加载 + 多源统一时间轴 + V2 typed raw parquet + artifact/run manifest”的数据服务。

最关键的判断：

1. `poly-tx` 只提前 3 秒建连，不满足 T-30s 预加载。
2. 默认首次目标是下一个窗口，不采当前活跃市场。
3. Binance/RTDS 辅助源等首个 Polymarket market 成功后才启动，预加载窗口会缺源。
4. Polymarket 采集写 NDJSON，且丢弃 `new_market`，不满足后续市场发现/预取证据要求。
5. V2 已能消费 typed raw parquet，但要求 `raw_json`、source kind metadata、manifest/labels/validation/tick_stream_v2 合同，不能只把文件后缀改成 `.parquet`。
6. mistake-log 里与数据直接相关的旧错集中在：market discovery、prefetch/active 边界、market switch buffer、artifact atomicity、archive integrity、manifest/labels 边界、resource watermark、execution feedback labels。

## P0 问题

### P0-1：T-30s 预加载缺失

`poly-tx` 的预热常量是 `PRE_SUBSCRIBE_LEAD_SECONDS = 3`，调度条件是 `now + 3 >= target_ts`。分段辅助源也复用这个 3 秒 warmup。新系统要求“活跃市场开始前 30 秒预加载数据源输入给模型”，当前设计不满足。

影响：

- 训练/回放如果要覆盖 `T-30s -> T+300s`，采集源天然少了 `T-30s -> T-3s`。
- live runtime 不能验证“模型从预加载开始就持续看数据”的合同。
- 市场切换前 30 秒准备 next context 无法落地。

### P0-2：默认启动跳过当前活跃市场

`next_spawn_target_ts()` 首次返回 `current_window_ts(now) + step`。除非手动传 `--start-market-ts`，否则进程启动时不会采当前 active market，而是等下一个 market。

影响：

- 采集中断后重启会漏当前 market。
- 数据缺口会被后续 V2 validation/gap 检查暴露，但已经无法补齐完整 market。
- 若新系统自检/热身后立即进入 active market，数据层没有当前 market 的完整上下文。

### P0-3：辅助源启动被 Polymarket 首个 worker 绑住

Binance orderbook 和 RTDS Chainlink 只在第一个 Polymarket worker 成功启动后拉起。若 Gamma slug/token 查询延迟、失败或重试，辅助源也同步变晚。

影响：

- 多源输入的覆盖起点不一致。
- `validation.parquet` 可能出现 source gap/drop。
- 模型看到的 Polymarket、Binance、Chainlink 可见时间不一致，容易制造伪信号。

### P0-4：市场发现只靠 slug，且丢弃 `new_market`

当前 `fetch_asset_ids_by_slug()` 通过 Gamma slug 找 `clobTokenIds`，没有保存 active/closed/acceptingOrders/conditionId/tick/min_size/fee/reward 等 market context。采集端还过滤 `event_type == "new_market"`。

影响：

- 与 online-feedback OF-18/OF-30 冲突：slug 只能生成候选，不能作为交易授权。
- 预加载 next market 时无法证明 candidate/prefetched/active/retired 四态边界。
- 平台创建延迟、clock drift、slug 变体会造成漏市场或错市场。

### P0-5：市场切换状态污染未被独立建模

mistake-log 已把 market switch buffer 泄漏列为高风险旧错：prefetched context 不能污染 active submit path，旧 feature buffer、sequence buffer、orderbook state、open order state 不能泄漏到新 market_id。

最低要求：

- 切换前执行 cancel/audit。
- 每个 market 独立保存 feature/orderbook/order/account state。
- 切换时 reset per-market buffer，并记录 reset receipt。
- 新市场 snapshot + seq_len warmup 完成前 no-submit/no-quote。
- prefetched context 只能准备数据，switch gate 成功后 submit path 才能使用新 token。

### P0-6：账户/订单/持仓输入没有进入统一数据层

`poly-tx` 的 `user_channel` 是独立 CLI，只查当前挂单并监听事件，主要写日志。positions 在 redeem 路径用于可赎回仓位查询。本轮证据没有看到这些账户源进入 `ws-series` 的统一时间轴，也没有看到它们落盘为模型可消费的数据源；price-to-beat、active resting count、local ledger、open orders、current position 也没有出现在当前采集合同中。

影响：

- 新流程第 4 点“模型持续看到 price to beat、当前持仓、open order”当前没有数据合同。
- 不能从采集层直接构造 execution feedback labels。
- 订单生命周期与账务权威源仍会分散，复发旧的 ledger/platform snapshot 混淆。

### P0-7：NDJSON -> Parquet 不是简单后缀替换

V2 支持 typed raw parquet，但依赖严格合同：

- schema metadata：`parquet_raw_layout_version=v1`
- schema metadata：`parquet_raw_source_kind`
- Polymarket/orderbook/Chainlink 必须保留可解析 `raw_json`
- aggTrades 必须满足 typed columns
- 下游必须联合消费 `manifest.parquet + labels.parquet`

因此 `poly-tx` 直接写 parquet 的正确目标是“V2 typed raw parquet mirror”，不是任意 parquet。

### P0-8：直接 Parquet 会放大 partial artifact 风险

Parquet 文件通常要 close 后才稳定可读。如果新采集器直接写最终 `.parquet`，V2 discovery 可能读到 partial file。旧 mistake-log 已把 artifact writer/schema/run manifest/sha256 列为 P0。

最低要求：

- 写 `*.tmp` 或 `*-running.parquet`
- close 后 atomic rename
- run manifest 记录 required files、row count、sha256、schema version、source coverage
- discovery 只读 finalized parquet

### P0-9：archive/data integrity 旧错必须前移到采集 gate

`poly-arb-2` 历史归档出现过 `.rsync-partial` 混入 raw tree 导致 migration/coverage 失败；V2 canonical 也记录过 corrupt archive 与 exclusion manifest。数据完整性问题不能等到训练阶段才发现。

采集重构 gate 必须包含：

- finalized file count
- row count
- source coverage/gap
- sha256/content-chain
- `.rsync-partial`、running/temp 文件排除
- disk watermark
- archive upload/listing retry

### P0-10：resource watermark 必须是采集运行门

T-30s preload、active + next 双市场、JSONL/parquet/journal 并发写入会直接影响数据是否完整。如果 disk/cgroup/PSI/journal 水位异常，继续采集可能造成 silent data loss、partial parquet、fail-open 或无法复盘。

最低要求：

- run manifest 记录 cgroup memory.current/stat/events、PSI、anon/file/slab。
- 记录 disk free、artifact_dir_bytes、journal 限额状态。
- 低于磁盘/内存硬阈值时进入 no-submit/cancel-only 或停止新市场采集。
- 先保护已采数据的 atomic publish 和 sha256 manifest，再尝试恢复。

### P0-11：manifest/labels/training boundary 不能混用

V2 明确把 market discovery/source path 放在 `manifest.parquet`，把 p2b/resolution/label 放在 `labels.parquet`，把 source gap/drop 放在 `validation.parquet`。训练消费端还要求 canonical split / strict time-forward split。

影响：

- 采集成功不等于训练边界批准。
- canonical root 完整不等于可以扩大训练范围。
- 只读 manifest 或只看 parquet 存在，会复发 archive manifest label boundary 错误。

### P0-12：live/paper 的 source of truth 不能被单一路径 Parquet 替代

历史 paper 经验明确：paper/live 运行应保留 JSONL source of truth，parquet 更适合后处理/压缩/训练镜像。对 offline historical collector 可以直接写 typed raw parquet；对 live/paper runtime，应保留 append/flushed event log 或等价不可丢事件日志，再 compact parquet。

## P1 问题

### P1-1：asset_ids 查询失败会卡住后续目标

`collect.rs` 只有成功 spawn 后才推进 `spawned_target_ts`。如果某个 slug 在创建延迟/接口抖动时一直找不到 token，调度会持续重试同一个 target，而不是过期跳到当前应采窗口。

建议：记录 miss 后在过期阈值跳过或重新按当前时间计算 target，同时写入 `discovery_miss_rate`。

### P1-2：`market_resolved` 关闭条件可能提前结束

当前关闭条件检查 event asset ids 是否都属于 subscribed set，而不是 subscribed set 是否都已 resolved。若单腿 resolved event 出现，可能提前关闭该 market worker。

建议：改为 subscribed subset/equality 语义，并写单测覆盖两腿 token。

### P1-3：Binance aggTrades 实时/离线边界未被统一

V2 daily archive 当前第 2 步仍是 backfill Binance aggTrades；本轮在 `poly-tx` 采集源码和文档中未发现实时 aggTrades collector。若新模型需要 event-level 连续输入，aggTrades 不应只靠日后补齐。

建议：新采集器至少明确：

- orderbook depth 是实时源
- aggTrades 是实时源还是离线 backfill
- 若仍 backfill，训练和 live 可见性不得假装一致

### P1-4：schema mismatch 已经在 paper 路径出现过

`2-paper-trade` changelog 记录 converter 写 aggtrade parquet 只写 4 列，但 data-pipeline 严格读 M0 真实 10 列，最终 `KeyError: 'symbol'`。这证明“写 parquet”本身不够，必须写对 V2 schema。

### P1-5：资源误诊仍需保留诊断 telemetry

mistake-log 已记录 page cache/resource pressure 误诊。P0 gate 负责保全和 no-submit/fail-closed 动作；P1 telemetry 负责避免把正常 page cache、dashboard memory 或 loadavg 误判成 pipeline/训练失败。run manifest 仍应记录 cgroup/PSI/disk/journal/artifact bytes/stage latency。

## 可优化的 V2 步骤

当前 archive/data pipeline 典型链路：

1. download collect-orderbook
2. backfill Binance aggTrades CSV
3. migrate raw -> typed parquet
4. verify parquet/raw coverage
5. pigz raw
6. pigz parquet
7. upload

`poly-tx` 直接写 V2 typed raw parquet 后，可以减少：

- 第 3 步 raw -> typed parquet migration
- 第 4 步 raw/parquet 一致性比对的一部分
- 部分重复 raw archive 成本；但 typed raw parquet 仍必须保留 `raw_json`、source metadata、manifest/hash/archive 证据

不能减少：

- `manifest.parquet`
- `labels.parquet`
- `validation.parquet`
- Chainlink/pseudo label 处理
- asset-map readiness
- tick_stream_v2 导出
- feature metadata 检查
- strict split / canonical boundary 审批
- artifact/resource 完整性验证

## 新数据采集重构的最低验收合同

### 采集合同

- 每个 5m market 有 `candidate -> prefetched -> active -> retired` 状态。
- `T-30s` 开始采集 next market 的 Polymarket market WS。
- Binance orderbook、Binance aggTrades、Chainlink 与 market worker 解耦启动。
- 当前 active market 和 prefetched next market 不能共享 ledger/order token/submit path。
- market switch 必须 cancel/audit/reset/warmup；per-market feature/orderbook/order/account buffers 必须清空或隔离。
- Polymarket `new_market`、market metadata、CLOB token ids、condition_id、tick/min size、fee/reward 都要落盘。

### 文件合同

- 直接输出 V2 typed raw parquet。
- 每个 source parquet 带 `raw_json` 和 `parquet_raw_source_kind`。
- 文件只以 atomic rename 发布。
- run manifest 记录 row count、sha256、source coverage、schema version、start/end time。
- temp/running/rsync partial 文件不进入 discovery。

### 消费合同

- 离线开发消费 `manifest + labels + validation + tables`。
- 训练消费 `tick_stream_v2 + labels + canonical split`。
- live/paper 消费权威 runtime event log + compact parquet mirror。
- execution feedback labels 记录 decision/action/book/account/order lifecycle 的因果上下文。

## 下一步建议

先不要直接改大系统。最小可靠实施顺序：

1. 冻结 market discovery / preload / source coverage 合同：slug candidate + active scan 双路径、T-30s、candidate/prefetched/active/retired。
2. 定义 market switch gate：cancel/audit/reset/warmup、per-market buffer 隔离、warmup 前 no-submit/no-quote。
3. 定义 V2 typed raw parquet writer 和 atomic publish 合同。
4. 把 `PRE_SUBSCRIBE_LEAD_SECONDS` 从硬编码 3 秒改成 30 秒需求合同，并补测试。
5. 拆出独立 source collectors：Polymarket current/prefetch、Binance orderbook、Binance aggTrades、Chainlink。
6. 新增 run manifest + coverage validator，先在 1-2 个 market 上验证 V2 data-pipeline 可消费。
7. 最后再接 live/paper 的 user-channel、open orders、position、price-to-beat 到统一时间轴。
