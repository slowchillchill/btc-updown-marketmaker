## 1. 目标

提供一个 SDK 优先、因果可审计、可恢复且有界的外部市场数据采集模块，为训练写入
类型化原始数据，并为后续模拟盘和实盘在线接入提供隔离的二进制程序与版本化交接
基础；不得侵入训练加工、交易执行或账本职责。

## 2. 模块范围

1. 训练二进制程序采集 Polymarket 市场、元数据、RTDS 和 Binance
   深度快照、深度更新、`aggTrade` 六类数据。
2. 模拟盘、实盘二进制程序与训练程序分进程、分输出根、分部署角色；当前只提供启动
   回执与 Unix 套接字心跳、状态。
3. `data-collect` 不负责标签、特征、训练切分、模型输入、订单、撤单、钱包、
   NOE、账本、PnL 或策略。
4. 当前只有训练程序连接真实外部源。模拟盘和实盘的真实适配器不属于
   `model-train`，继续保持延期。必须先完成 `model-train`（模型训练模块，不是
   `data-collect-training-collector`）；之后仍只有在用户决定返回 `data-collect` 时，
   才另立需求、计划和变更记录开发；该延期不阻断当前模块完成。
5. 当前跨模块主线为
   `data-collect(training) -> sim-system -> data-pipeline(training) -> model-train`；
   该顺序不重开已完成的 `data-collect`，也不提前授权模拟盘和实盘的真实适配器。

## 3. SDK 与数据合同

1. Polymarket 必须使用官方 Rust SDK `0.7.0` 和仓库唯一 `0.7.0-p1` 补丁；SDK
   缺口必须先报告并取得用户决定，禁止未经批准的原始 REST、手动签名或
   影子 SDK。补丁涉及的四个生产文件及其解析、诊断、连接和代际边界由
   `current/contracts.md` 与补丁、运行时契约测试拥有，不得只凭版本名删除、
   缩小或扩大。
2. 当前新写入 schema 固定为订单簿 v3、元数据 v5、RTDS v4、Binance 深度快照 v3、
   深度更新 v4、`aggTrade` v7。
3. 旧 schema 只能用于代码明确保留的精确旧版读取和恢复，不得成为新写入依据。
4. UTC 日和小时必须按采集器接收时间分区；`*.running` 不得被当作最终化产物。
5. 每个 UTC 日只有一个每日清单 v3 和一个归属方，并直接包含单一采集日覆盖信息 v1。

## 4. 运行时合同

1. 采集器拥有的承载数据、准入、延后处理以及写入器队列或批次必须有内存硬上限；
   已接纳数据在可靠停止、UTC 日切换或运行期容量退出时必须排空并最终化。供应商版
   SDK 的出站请求与 `heartbeat PING` 传输控制通道使用无界通道类型；当前封装器对
   最新期望状态的合并、固定且较小的期望状态集合，以及单个待处理心跳只构成逻辑调用约束，
   不等同于通道具有容量硬上限。
2. 配置的容量上限必须为正整数；CLI 默认值和当前生产单元为
   `50_000_000_000` 字节，测试或另行批准的配置可以覆盖。启动容量扫描已达到
   配置上限时，必须在数据源、类型化原始数据、清单和运行时产物启动前直接退出 `75`；
   运行期间每 `60s` 扫描达到配置上限时，必须停止准入、排空并最终化、更新适用清单后
   退出 `75`。采集器不自动删除最终化原始数据。
3. 普通数据源静默或暂时无数据不得退出整体进程；传输故障由对应归属方
   恢复。
4. 训练 RTDS 保留唯一业务静默窄例外：首次收到有效新鲜消息前禁用看门狗，随后
   稳态 `300s` 或首次有效消息 `60s` 超时会触发完整运行时替换；外层退避从 `1s` 起每级
   `×2`、应用 `±20%` 确定性抖动、单次休眠上限为 `300s`，收到有效新鲜消息后重置；
   替换过程没有独立尝试次数或累计耗时耗尽门，并严格先断开再连接。
5. 市场固定身份信息必须在当前、下一、重启和市场判定流程中保持不可变；多重权威、
   不可变信息不匹配或 schema 矛盾时必须失败即关闭。
6. 市场判定后续查询固定为 E+3 至 E+8 六个时间点；合格终态只能关闭一次，查询耗尽不得
   伪造胜方。不匹配当前、下一、待判定角色，或超过市场判定预算时限的迟到
   `market_resolved` 事件会被忽略；第二个 Gamma 终态声明、固定身份信息或 schema
   矛盾，以及与已有终态胜方冲突时必须失败即关闭。
7. UTC 日切换必须先完成旧日生产者围栏、写入器最终化、清单会合和持久关闭，再启用新日。

## 5. 构建与权限边界

1. 发布二进制文件必须在本地从干净且已推送的提交隔离构建，记录提交与
   SHA-256；远端不编译 Rust，不通过服务器 `git pull` 部署。
2. 当前训练二进制文件、数据集根目录与唯一 systemd 单元路径由
   `data-collect/docs/current/operations.md` 固定。
3. 当前文档只描述合同，不授权上传、部署、启停服务、替换二进制文件、删除数据或
   改变远端状态；这些动作需要独立批准的活动三件套。
4. 发布包、二进制文件别名、保留策略管理器、归档上传器和自动删除原始数据不是当前部署路径。

2. 2026-07-28 事故已最终验收；真实 UTC 日切换与完整健康 UTC 日证据不声明为

## 7. 验收标准

1. 三个二进制程序的职责、CLI 和角色派生输出根与当前 Cargo、代码一致，只有训练程序
   连接真实数据源；热路径运行标识尚无安全文件名组件校验的限制必须显式保留，不得冒充
   回执路径限制已经失败即关闭。
2. 六个当前 schema、SDK 与补丁、每小时 Parquet、每日清单、容量退出、RTDS、身份信息、
   市场判定、重启和 UTC 日切换合同均有测试证据。
3. 模拟盘和实盘的当前、后续能力不被夸大，延期不变成隐形执行计划。
4. `data-collect/docs/CURRENT.md` 是唯一当前入口，六个主题归属文档无影子规范。
5. 45 份历史长文可由归档标签、路径和 blob 恢复，但不在活动树，也不产生当前执行权威。
6. 文档权威守卫能拒绝重复入口、错误三件套引用、错误归档 blob、恢复历史路径或
   仅作证据的首屏标记缺失。
7. 当前验收命令和实际结果记录在
   `data-collect/docs/current/acceptance.md`。
8. `CURRENT`、主需求、计划、变更记录和活动的当前主题归属文档对跨模块主线与模拟盘、
   实盘适配器延期门的表述一致，不再把 `model-train` 误称为当前下一模块。
