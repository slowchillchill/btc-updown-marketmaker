## 1. 成功标准、三层验收和停止条件

### 1.1 总成功标准

1. 组件符合性门先以官方 HTTPS 合同测试替身验证私有 `PlatformRuleHttpLoader`，再在网络禁用、无钱包、无凭据、
   无模型框架环境下，以合同有效的固定规则快照、黄金 `ExecutionMarketEvent` 和合成请求，
   证明模拟器的八方法面、动态影子 CLOB、撮合、
   队列、订单/成交/结算、返佣、查询、恢复、确定性、隔离和有界资源语义。
2. 真实管道纵向门只在 DPT Gate A 已机械签发 `REAL_EXECUTION_TAPE_READY` 后，消费由
   `data-pipeline(training)-A` 产生的真实 `ExecutionMarketEvent`，完成至少一个代表性市场
   窗口和真实性能重新定标。`REAL_EXECUTION_TAPE_PARTIAL` 不满足该入口。
3. 训练闭环门位于模拟器之后，由外部归一化层和 training Ledger 消费模拟器原始证据，
   再由 `data-pipeline(training)-B` 形成完整 Observation 与训练产物。该门不是模拟器核心
   开发前置，但未通过时不得进入正式 `model-train`；RewardContract 的实际计算仍属于
   `model-train` 首门。
4. 三层验收不得相互冒充：黄金替身不能替代真实纵向，真实纵向不能替代归一化/Ledger
   闭环，训练闭环也不得反向要求 `sim-system` 实现外部模块。
5. 所有通过结论必须绑定真实测试命令、输入身份、代码版本、配置和产物 SHA-256。未运行、
   被过滤、失败或仍受外部前置阻断的测试不得写成通过。

### 1.2 并行关系和硬顺序

在 `ExecutionMarketEvent` 及桥接器模拟领域合同冻结后，组件实现和黄金组件测试可以与
DPT Gate A 的准入器、规范化核心和真实事件带建设并行。以下顺序不可交换：

```text
DPT 需求/计划批准并冻结共享合同
    -> sim-system 组件实现与黄金符合性测试       [可与 DPT Gate A 实现并行]
    -> DPT REAL_EXECUTION_TAPE_READY
    -> DPT/sim-system 联合真实管道纵向验收
    -> 外部归一化层 + training Ledger + DPT Gate B 训练闭环
    -> model-train
```

完整归一化层、Ledger、RewardContract、模型框架和 `sim-calibration` 写入器都不是组件开发
或黄金符合性门前置。模拟器不得为等待这些模块而建设临时替代实现。
