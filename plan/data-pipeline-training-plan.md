### 2.1 模块职责、数据流与实施单元

1. `data-pipeline(training)` 是合格类型化原始证据到唯一规范事件带的唯一语义归属方；门 A
   与门 B 复用同一个版本化核心，不得分别建立临时和正式的排序、去重、状态重建或源解释。
2. 唯一允许的主数据流是：最终化 `typed_raw` 与每日清单进入 DPT；DPT 生成规范事件带、
   `ExecutionMarketEventV1` 和市场侧 `MarketObservationCausalShellV1` 供 `sim-system`
   使用；门 B 再只读合并同一训练实例的 Ledger 投影，生成完整 Observation、成熟标签和
   训练数据集供 `model-train` 使用。
3. `model-train` 进程可为血缘、审计和质量诊断直接读取 `manifest`、`source_coverage`、
   `source_health`、`source_gap`、`reconnect_trace`、`backpressure_state`；这些元数据不得
   参与准入、切分、样本选择、决策触发、Observation、特征、标签、训练样本或模型输入。
   进程可读不等于模型可达，模型输入只能来自版本化 DPT 输出。
4. DPT 不写 `data-collect` 写入器或运行时，不写模拟器订单簿、账户或随机状态，不写 NOE 或
   Ledger，不拥有 `RewardContract`、奖励、模型训练、筛选或晋级；下游也不得绕开 DPT
   重建原始排序、去重或源解释。
5. 当前只实施 `contracts`、`data-pipeline/core`、`data-pipeline/training` 三个单元，并保持
   1.3 节依赖边界。所有共享输出均为框架中立、版本化、可哈希的领域或列式合同。
6. 本事项只覆盖离线训练角色。未来复用核心的 offline-evaluation、paper 或 live 运行必须
   另行批准，并隔离运行实例、输入权限、状态、检查点、产物根和 Ledger 投影。

### 2.3 因果时间、全序、身份与数值

1. 分离源业务时间、采集器接收时间、采集器接纳时间/序号、`available_at`、
   `group_available_at` 和决策截止点。有接纳坐标时，以接纳时间/序号作为离线因果可用性的
   主要证据，不得按更早源时间或接收时间回排；RTDS v4 只使用真实
   `timestamp_received` 与稳定证据键，并明确降低排序和因果证据质量。
2. 因果组仅在唯一状态转换实际最终确定时可见，`group_available_at` 不得早于组成证据的
   最大 `available_at` 或实际最终确定时间。同毫秒决胜依次优先源 epoch、接纳序号和源原生
   唯一身份；证据不足时使用稳定、可解释的规范证据键并降低质量。
3. `total_order_key` 和规范事件 ID 必须版本化且独立于目录、文件、分片、行组、读取批次、
   线程和机器。事件 ID 由版本化语义身份、规范载荷和稳定来源证据确定；物理重分片不改变
   ID，业务证据变化必须改变 ID 或产生显式冲突。
4. 每个输出可追溯到日清单、文件 SHA、源行或接纳坐标、规范规则版本及合并/去重证据。
   规范事件保存语义身份所需前像，独立报告保存操作证据，运行清单绑定报告 SHA；不重复
   增加没有独立前像的派生摘要。
5. 价格、数量、费率和金额在规范层保持精确十进制。单位、方向、资产侧、状态和枚举显式
   映射；未知值只进入版本化 `unknown/unmodeled` 路径或隔离，不得默认为零、空字符串或
   最相似枚举。模型浮点转换只发生在后续冻结的编码边界。

### 2.4 状态归约、质量与公开事件合同

1. 去重由事件类型特定身份和状态规则驱动，禁止用全局内容哈希删除看似相同但实际独立的
   事件。每次合并、覆盖、删除或确认进入版本化独立报告，记录源事件、原因、规则版本、
   数量守恒和结果事件或明确的 `NO_OUTPUT`/`SUPPRESSED`。
2. 初始完整 `book` 只装载基准；绝对 `price_change` 只应用一次；后续完整 `book` 状态相同
   时只确认，只有剩余唯一净差额才重校准并形成 `LevelExecutionTransitionV1`。该转换至少
   保存前后数量、净增、净缩、队头只应用一次的数量、组成事件、因果组、
   `group_available_at`、`source_attribution_quality` 和 `queue_result_quality`。
3. `best_bid_ask` 只更新或验证价格，不能推进数量队列。公开成交与盘口变化没有共同权威
   因果 ID 时不得因邻接而双算或标为真实逐订单 `EXACT`；无法归因为 `UNATTRIBUTED`，合同
   允许的 L2 净缩推断为 `DETERMINISTIC_INFERRED`。公开 L2 不能证明真实 FIFO、账户成交、
   市场冲击或模拟订单对历史市场的反事实影响。
4. Binance 深度归约共同尊重 epoch、接纳坐标、`stitch`、`stale`、`confirmed-hole` 和
   `not-applied`，只有合法 `applied` 更新推进锚点。更新先到而快照后返回时，不得以后见
   连续性回填过去；待处理项使用实际形成连续性的可用时间。合法 aggTrade 保留原生 ID
   范围、方向、数量和时间，无效记录作为无效证据保留。
5. 模型可见质量保持 `fresh`、`stale`、`missing`、`unknown_not_observed`、
   `confirmed_gap`、`invalid` 六种状态。只有当时已可用、结构化且可定位的证据可生成
   `confirmed_gap`；自由文本或事后日志不得反推精确缺口。缺口、epoch、陈旧、重同步和身份
   冲突只影响可定位市场或范围，不得跨市场传播。
6. 当前共享入口直接绑定 `ExecutionMarketEventV1`、`MarketObservationCausalShellV1` 和
   `GateAReceiptV1` 的公开 V1 类型；审核中 `SIM-S-004` 只能用于兼容性复核，不能覆盖已批准
   的生产语义。`ExecutionMarketEventV1` 必须表达市场/条件/代币、窗口和生命周期，彼此
   独立的 `active/closed/accepting_orders`，首次完整 L2、价位转换、最优价、tick 变化、来源
   可辨成交、全部时间坐标、全序键、质量状态和终态水位线。
7. tick 的唯一权威链为 `data-collect -> data-pipeline -> ExecutionMarketEventV1 ->
   sim-system`。初始逐资产 tick 来自当时已保存的源证据，动态变化由 `tick_size_change`
   推进；旧 tick 可未知，首次快照不携带用途分支。模拟器冷启动规则快照不得查询、保存或
   交叉校验 tick。`min_order_size`、`feeSchedule`、`itode`、`oas` 和秒级延迟规则不得进入
   事件或 Observation。
8. metadata 与 WebSocket 终态只能合并成一个规范终态或产生显式冲突。派生兑付向量必须
   保存源事件、获胜身份和版本化映射规则，并明确其派生属性；冲突不得重复结算。

### 2.5 Observation、标签、切分与归一化

1. 同一截止点的 Observation 与 `ExecutionMarketEventV1` 使用同一最终确定状态，不得一侧

   年龄、缺失掩码、覆盖质量和规范哈希，不冻结训练框架张量。
2. 门 B 只读同一实例的 Ledger 投影，并绑定 `ledger_projection_sequence`、
   `ledger_projection_digest` 和因果可用时间。完整 Observation 分别拥有市场状态、账户
   状态、活动订单/预留、两侧持仓、现金、返佣应收和可用现金，冻结单位、缺失语义和唯一
   消费方，避免重复经济事实。
3. 未来判定、标签成熟度、模拟反馈、奖励、原始 JSON、解析器诊断、采集器重连信息和
   offline-evaluation 留出归属均对过去 Observation 不可达。标签构建侧与因果 Observation
   在物理路径和权限上隔离，标签不得回写规范事件带。
4. 执行反馈标签等待 `sim-system -> 外部归一化层 -> Ledger` 事实成熟，并绑定模拟原始
   证据摘要、归一化事件、权威来源、因果截止点、成熟时刻、删失原因和规则版本；未成熟、
   未知、主动截尾或隔离不得填零。`RewardContract` 和奖励值归 `model-train`；手续费、返佣、
   结算和赎回只作为平台或 Ledger 经济事实，DPT 不生成第二笔奖励。
5. 切分先按市场和因果时间前推，再按最大依赖推导 purge/embargo；禁止逐文件随机切分、逐
   Parquet 切分后拼接、跨市场身份混合、同一因果组或依赖窗口跨集合。完整 UTC 日、固定
   288 个市场和物理文件边界不是强制轨迹边界。
6. T-30 不得越过日期下限；需要更早字节时排除该市场或返回 `EVIDENCE_INSUFFICIENT`。

   没有合格未见区间时只能证据不足或隔离，不得回退到更早数据。
7. 归一化只拟合训练许可范围，并版本化记录拟合范围、算法、精度、缺失处理、截断规则和
